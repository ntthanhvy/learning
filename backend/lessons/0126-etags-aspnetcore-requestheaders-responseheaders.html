ETags, now in C# too

Lesson 51 covered ETags and conditional requests as HTTP-native mechanisms: a fingerprint header plus two companion headers, If-None-Match for cheap reads and If-Match for safe writes. Nothing about that mechanism is Go-specific — it lives in the HTTP spec, not in net/http. What ASP.NET Core adds isn't a new concept, just strongly-typed C# access to the same three headers, instead of reading and comparing raw strings by hand.

1 · The same headers, parsed instead of string-compared

Lesson 51's Go handlers read ETag/If-None-Match/If-Match as plain strings via r.Header.Get(...) and compared them with ==. ASP.NET Core offers a typed alternative: GetTypedHeaders(), which parses the raw header text into real objects:

var requestHeaders = HttpContext.Request.GetTypedHeaders();
IList<EntityTagHeaderValue> ifNoneMatch = requestHeaders.IfNoneMatch;
IList<EntityTagHeaderValue> ifMatch = requestHeaders.IfMatch;

var responseHeaders = HttpContext.Response.GetTypedHeaders();
responseHeaders.ETag = new EntityTagHeaderValue("\"a1b2c3d4\"");

RequestHeaders's IfMatch and IfNoneMatch are each an IList<EntityTagHeaderValue>, not a single value — the spec allows a client to send several candidate ETags separated by commas, asking "does the current one match any of these?" On the response side, ResponseHeaders's ETag property is a single value, since a response only ever has one current fingerprint.

2 · EntityTagHeaderValue: a real type instead of a quoted string

Lesson 51's Go etag() function returned a plain string with the quotes baked in by hand (fmt.Sprintf(`"%x"`, sum)) — easy to get wrong (forgetting a quote, double-quoting, not handling a weak-validator prefix). ASP.NET Core's EntityTagHeaderValue class owns that formatting instead:

var tag = new EntityTagHeaderValue("\"a1b2c3d4\""); // quotes are part of the tag text
tag.IsWeak;   // false -- no "W/" prefix
tag.Tag;      // the quoted text itself

// Compare(other, useStrongComparison) implements RFC 7232's two matching
// modes -- strong demands an exact match with neither side weak; weak
// comparison ignores the W/ prefix, only the tag text must agree.
bool matches = tag.Compare(otherTag, useStrongComparison: true);

Lesson 51 didn't need the strong-vs-weak distinction because the Go example never generated weak ETags. It is worth naming once here since Compare is the method that actually enforces it: a weak ETag (one prefixed W/) signals "semantically equivalent, not necessarily byte-identical" — a strong comparison must reject two weak ETags outright regardless of their tag text, which is exactly what Compare's useStrongComparison flag exists to enforce.

3 · The same two handler shapes, now with typed headers

Lesson 51's two handlers port directly — same logic, same status codes, same "check before touching the DB" order, just reading parsed objects instead of raw header strings:

app.MapGet("/orders/{id:int}", (int id, HttpContext ctx) =>
{
    var order = LoadOrder(id);
    var tag = new EntityTagHeaderValue($"\"{ComputeEtag(order)}\"");
    ctx.Response.GetTypedHeaders().ETag = tag;

    var ifNoneMatch = ctx.Request.GetTypedHeaders().IfNoneMatch;
    if (ifNoneMatch.Any(candidate => candidate.Compare(tag, useStrongComparison: true)))
        return Results.StatusCode(StatusCodes.Status304NotModified); // 304, no body

    return Results.Ok(order);
});

app.MapPatch("/orders/{id:int}", (int id, UpdateOrder body, HttpContext ctx) =>
{
    var current = LoadOrder(id);
    var currentTag = new EntityTagHeaderValue($"\"{ComputeEtag(current)}\"");

    var ifMatch = ctx.Request.GetTypedHeaders().IfMatch;
    if (ifMatch.Count > 0 && !ifMatch.Any(candidate => candidate.Compare(currentTag, useStrongComparison: true)))
        return Results.StatusCode(StatusCodes.Status412PreconditionFailed); // 412, reject before writing

    // ... persist the change, same shape as Lesson 51's patchOrderHandler
    return Results.Ok(current);
});

Nothing about the decision logic changed from Lesson 51 — still 304 for a matching read, still 412 for a stale write, still checked before any database call runs. The only difference is that ifNoneMatch/ifMatch arrive pre-parsed as a list of EntityTagHeaderValue, so the comparison is .Compare(...) against a real object instead of a raw string ==.

Scope line

This lesson covers GetTypedHeaders(), RequestHeaders.IfMatch/IfNoneMatch, ResponseHeaders.ETag, and EntityTagHeaderValue as the C# mechanism for Lesson 51's conditional-request headers. It does not cover ASP.NET Core's separate static-file conditional-request handling (the built-in StaticFileMiddleware and MVC's output-caching features already compute and check ETags automatically for served files) or ActionResult helpers some controller-based APIs build on top of these same typed headers — both real, both out of scope for a first pass at the raw mechanism.
