str.extract(): pulling structured pieces out of text

Lesson 41's teaser named this gap directly: Lesson 10's .str accessor covered contains/upper/lower/startswith/split, but never regex-based extraction — pulling a sub-piece out of a text column into its own real column. Today closes that gap with the tool interviewers reach for whenever a "clean" column turns out to be several fields jammed into one string.

1 · The problem: one column, several facts glued together

Order codes like "NA-0231" pack two facts into one string: a region code and a sequence number. .str.contains() from Lesson 10 can only tell you a pattern exists somewhere in the string — it can't hand you the matched piece back as usable data:

orders = pd.DataFrame({
    "order_id": [1, 2, 3, 4, 5, 6],
    "customer": ["An", "Binh", "An", "Chi", "Binh", "An"],
    "order_code": ["NA-0231", "EU-0089", "NA-0245", "AP-0012", "EU-0104", "bad-code"],
})
orders["order_code"].str.contains(r"[A-Z]{2}-")
-- 0     True
-- 1     True
-- 2     True
-- 3     True
-- 4     True
-- 5    False
-- dtype: bool   <- confirms a match exists, but never hands back "NA" or "0231"

str.extract() is the tool that solves exactly this: give it a regex with parenthesized capture groups, and it returns the captured pieces as real columns.

2 · One group, two groups, and the DataFrame-vs-Series shape rule

# one capture group, expand=False -> a Series
orders["order_code"].str.extract(r"([A-Z]{2})-\d+", expand=False)
-- 0     NA
-- 1     EU
-- 2     NA
-- 3     AP
-- 4     EU
-- 5    NaN
-- Name: order_code, dtype: str

# two capture groups -> always a DataFrame, one column per group
orders["order_code"].str.extract(r"([A-Z]{2})-(\d+)")
--     0     1
-- 0  NA  0231
-- 1  EU  0089
-- 2  NA  0245
-- 3  AP  0012
-- 4  EU  0104
-- 5 NaN   NaN

The shape rule: one capture group with expand=False returns a Series; any other case — two or more groups, or the default expand=True even with one group — returns a DataFrame, one column per group. The columns are unnamed (0, 1, …) unless the regex names them.

Named groups fix the unnamed-column problem directly — (?P<name>...) instead of a bare (...) makes the extracted column's name useful right away, no rename() needed:

orders["order_code"].str.extract(r"(?P<region>[A-Z]{2})-(?P<seq>\d+)")
--   region   seq
-- 0     NA  0231
-- 1     EU  0089
-- 2     NA  0245
-- 3     AP  0012
-- 4     EU  0104
-- 5    NaN   NaN
Gotcha: row 5's "bad-code" doesn't match the pattern at all — str.extract() puts NaN in every captured column for that row instead of raising. This is the opposite failure behavior from Lesson 41's astype(), which raises the instant one value can't convert. str.extract() behaves like errors="coerce" always — a non-match is just a missing value, and the rest of the column still comes back. There is no "strict" mode; if a row silently not matching would be a real bug, check for it explicitly: extracted["region"].isna().sum().

3 · Using the extracted column: it's a real column now

Once extracted, the piece can be assigned back and used exactly like any other column — including inside groupby() (Lesson 4), which quietly drops the NaN group the same way it always drops missing group keys:

orders["region"] = orders["order_code"].str.extract(r"([A-Z]{2})-\d+", expand=False)
orders.groupby("region")["order_id"].count()
-- region
-- AP    1
-- EU    2
-- NA    2
-- Name: order_id, dtype: int64   <- row 5's NaN region silently excluded, same rule as any groupby key

4 · The SQL bridge: no single equivalent, that's the point

Postgres has the pieces but not one clean built-in call: substring(col from '[A-Z]{2}') for a single capture, or regexp_match(col, '...') returning an array you then have to index into. str.extract() is the one-call, multi-column version of stitching those together — extract every group at once, get real columns back, no follow-up array indexing:

-- SELECT substring(order_code from '[A-Z]{2}') AS region FROM orders;
-- (a second substring() call needed for the sequence number)
orders["order_code"].str.extract(r"(?P<region>[A-Z]{2})-(?P<seq>\d+)")
-- both pieces, one call

Q: "You've got a column like order_code with a region prefix and a sequence number jammed together. How do you split it?" A strong answer, out loud: "str.extract() with a regex that has one capture group per piece I want — parentheses around each part I care about, named groups with (?P<name>...) so the resulting columns come back already labeled instead of 0, 1, 2. One capture group with expand=False gives me back a Series; more than one group always gives a DataFrame, one column per group. The part I'd flag unprompted: a row that doesn't match the pattern at all doesn't raise, it just becomes NaN in every captured column — same coercing behavior as to_numeric with errors='coerce', not astype's raise-on-failure. So right after extracting I'd check isna().sum() on the result to see how many rows silently didn't match, because that's easy to miss if you're not looking for it." The signal: naming the shape rule (Series vs. DataFrame), named groups, and the silent-NaN-on-no-match behavior without being prompted for any of the three.
