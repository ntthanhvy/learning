weakref: references that don't keep things alive

Every reference held so far — a variable, a list element, a dict value — is a strong reference: it keeps the object it points to alive. Today's module, weakref, builds the one kind of reference that doesn't — useful for a cache that should never be the reason an object outlives its real owner.

1 · A normal reference keeps the object alive — that's the whole problem

Day 1 taught that assigning a name, or storing something in a list or dict, creates a reference — and every one of those references is strong: as long as at least one exists, the object cannot be garbage-collected, no matter how it got there.

class Node:
    def __init__(self, name):
        self.name = name

cache = {}
obj = Node("strong")
cache["k"] = obj   # a second strong reference, now owned by the dict
del obj             # only the *name* obj is gone -- the dict's reference remains

print(cache["k"].name)
# strong -- confirmed live: the object is still fully alive

That's correct and desired for almost everything. But it becomes a bug in one specific shape: a cache, registry, or "who's listening" list that exists purely to look up objects owned elsewhere. If that structure holds strong references, every object it ever saw stays alive forever — a memory leak with a very innocent-looking cause.

2 · weakref.ref(): a reference that doesn't count

weakref.ref(obj) returns a callable weak reference object: call it, and you get the real object back — or None, once nothing else is keeping it alive:

import weakref

obj = Node("cache-entry")
r = weakref.ref(obj)
print(r())          # Node object -- confirmed live, obj is still referenced by the name "obj"

del obj           # the only strong reference is gone
print(r())          # None -- confirmed live, collected as soon as nothing strong pointed to it

Holding r itself never kept obj alive — that's the entire point. Not every object can be weakly referenced, either: plain int, str, and tuple don't support it at all (weakref.ref(5) raises TypeError: cannot create weak reference to 'int' object, confirmed live) — weak references exist for ordinary instances of your own classes, not for the language's own immutable built-ins.

3 · WeakValueDictionary: a cache that cleans up after itself

Calling weakref.ref() by hand and checking for None everywhere is tedious. weakref.WeakValueDictionary is a dict whose values are held weakly — an entry quietly disappears on its own the moment nothing else holds its value alive, with no manual cleanup code anywhere:

cache = weakref.WeakValueDictionary()
obj = Node("weak-value")
cache["k"] = obj
print(len(cache), dict(cache))
# 1 {'k': Node(...)} -- confirmed live, obj is still alive elsewhere

del obj
print(len(cache))
# 0 -- confirmed live, the entry vanished with no code deleting cache["k"] directly
cache["k"]
# KeyError: 'k' -- confirmed live

weakref.WeakKeyDictionary is the mirror image — the keys are held weakly instead, useful for attaching extra metadata to objects you don't own without keeping them alive just by having annotated them (confirmed live the same way: the entry vanishes once the key object itself is gone).

4 · weakref.finalize(): run cleanup exactly once, on collection

weakref.finalize(obj, func, *args) schedules func(*args) to run when obj is garbage-collected — without creating any reference that would keep obj alive itself:

def on_gone(name):
    print(f"cleaned up {name}")

obj = Node("finalized")
f = weakref.finalize(obj, on_gone, "finalized")
print(f.alive)   # True -- confirmed live

del obj
# cleaned up finalized  -- confirmed live, printed automatically on collection
print(f.alive)   # False -- confirmed live

A finalizer can also be fired early, by calling f() directly — that runs func immediately and returns its return value. Calling f() a second time (or letting collection happen after an early manual call) is a safe no-op that just returns None — confirmed live: f() first returned 'cleaned up manual' while printing the message once, and the very next call returned None with no second print. Either path — collection or a manual call — only ever runs func once.

Where pandas/NumPy go from here: neither library has an equivalent — weakref is pure CPython object-lifetime mechanics, with nothing resembling it in tabular data handling; this callout exists only to confirm the absence, per MISSION.md's no-pandas rule.
