Glossary

Every jargon term used in the lessons, in one place, grouped by the lesson that introduced it. The Tiếng Việt column is dev-style: how Vietnamese data engineers actually say it, not a textbook translation.

Day 1 — The pipeline map & the repo

TermTiếng Việt (dev-style)In software
pipelinegiữ nguyên "pipeline" — chuỗi bước tự động di chuyển/biến đổi dữ liệuA scheduled, repeatable sequence of steps that moves and transforms data from a source to somewhere it can be used — the umbrella term for the whole thing this course builds.
ETLgiữ nguyên "ETL" — biến đổi TRƯỚC khi load vào đíchExtract, Transform, Load — data is transformed in a separate processing engine before it ever reaches the destination, so the destination only ever sees clean, final-shaped data.
ELTgiữ nguyên "ELT" — load THÔ trước, biến đổi SAU ngay trong warehouseExtract, Load, Transform — raw data is loaded into the destination first, untransformed, and transformation happens afterward inside that same destination using its own compute. This course's approach; dbt is the T.
raw layergiữ nguyên "raw layer" — dữ liệu thô, y nguyên lúc mới vào, chưa xử lý gìThe schema holding data exactly as it arrived from its source, before any cleaning or reshaping — the permanent, replayable starting point every transformation can be re-run from.
dbtgiữ nguyên "dbt" — công cụ biến đổi dữ liệu bằng SQL, chạy ngay trong warehouseA SQL-based transformation tool: you write SELECT statements, it compiles and runs them inside the warehouse, tracks which model depends on which via ref(), and can test the results — the T in this course's ELT.
Kafkagiữ nguyên "Kafka" — hệ thống log phân tán, nhận sự kiện liên tục theo thời gian thựcA distributed append-only log system: producers write events to topics, consumers read them in order, and it's built for continuously arriving data rather than periodic batches.
Airflowgiữ nguyên "Airflow" — công cụ lập lịch và điều phối, tự nó không xử lý dữ liệuA scheduler and orchestrator: it runs a defined sequence of tasks (a DAG) on a schedule, retries failures, and tracks whether each run succeeded — it does not transform or move data itself, it triggers the tools that do.
idempotentgiữ nguyên "idempotent" — làm 1 lần hay N lần, kết quả như nhauAn operation that produces the same end state whether performed once or many times — safe to retry blindly, which matters wherever a step might run twice. Same idea as backend/'s idempotency keys, applied to a pipeline.
