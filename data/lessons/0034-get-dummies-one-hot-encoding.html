pd.get_dummies(): turning one category column into many 0/1 columns

Lesson 33's teaser named no single dangling candidate ("a fresh curriculum/glossary scan for the next genuinely-uncovered pattern"), so this round did exactly that: grepped lessons/*.html and reference/glossary.html for a batch of common pandas/NumPy terms not yet confirmed taught (clip(), between(), combine_first(), merge_asof(), .at[]/.iat[], get_dummies()). pd.get_dummies() came back genuinely uncovered and is the natural next step after Lesson 25's category dtype — a different, equally common answer to "this column is a category" that a table-shaped model (or a correlation matrix) needs numbers, not text, to work with.

1 · The problem: models and math don't read text

Lesson 25 taught the category dtype — a memory-efficient way to STORE a text column with few distinct values. That's still text under the hood, though. Plenty of downstream tools (a regression, a correlation matrix, a similarity calculation) can't consume a column of the literal strings "North"/"South"/"West" at all — they need numbers. one-hot encoding is the standard fix: replace one categorical column with several 0/1 columns, one per distinct value, each answering "is this row THAT value?"

On this course's cleaned 4-row slice (An 120.0/01-05, An 42.0/01-10, Binh 35.5/01-06, Binh 180.0/01-09) merged with customers.csv for region (Lesson 5's join):

merged
#   order_id customer  amount  order_date region
# 0        1       An   120.0  2026-01-05  North
# 1        6       An    42.0  2026-01-10  North
# 2        2     Binh    35.5  2026-01-06  South
# 3        5     Binh   180.0  2026-01-09  South

2 · pd.get_dummies(): one call, one column becomes several

pd.get_dummies() does the whole conversion in one call, naming which column(s) to expand via columns=:

pd.get_dummies(merged, columns=["customer"])
#   order_id  amount  order_date region  customer_An  customer_Binh
# 0        1   120.0  2026-01-05  North         True        False
# 1        6    42.0  2026-01-10  North         True        False
# 2        2    35.5  2026-01-06  South        False         True
# 3        5   180.0  2026-01-09  South        False         True

The original customer column is gone, replaced by customer_An and customer_Binh — one new column per distinct value, named <original column>_<value> by default. Every other column (order_id, amount, order_date, region) passes through untouched. Each row has exactly one True across the new columns — the row sums to 1 across them, confirmed here as [1, 1, 1, 1].

3 · This is what a full-string comparison would give you anyway

This isn't new information — it's Lesson 24's np.where()/Lesson 29's isin() family, generated automatically instead of written by hand. customer_An is exactly merged["customer"] == "An", computed for every distinct value at once instead of one comparison at a time. In SQL terms, it's the classic pivot-by-hand idiom: SELECT *, (customer = 'An') AS customer_An, (customer = 'Binh') AS customer_Binh FROM merged — a manual CASE WHEN per value, which is exactly what get_dummies() saves you from writing out by hand for every distinct value in the column.

4 · prefix= and drop_first=

prefix= replaces the default <column>_ naming with something else, useful when the source column name is long or unclear:

pd.get_dummies(merged["customer"], prefix="cust")
#   cust_An  cust_Binh
# 0    True   False
# 1    True   False
# 2   False    True
# 3   False    True

drop_first=True drops the first category's column entirely:

pd.get_dummies(merged["customer"], drop_first=True)
#    Binh
# 0  False
# 1  False
# 2   True
# 3   True

With only Binh left, False means "this row is An" by elimination — the two columns carried the exact same information as one, since row-sum-to-1 makes the last column fully predictable from the rest. This is the standard fix for multicollinearity in downstream modeling: dropping the redundant column keeps every row's information intact while removing the duplication. This course won't go deeper into modeling itself (out of scope per MISSION.md) — just naming why drop_first= exists is enough for an interview answer.

5 · The gotcha: a missing value silently gets its own all-False row, or vanishes

Continuing this course's "no crash, quietly wrong" family since Lesson 19: a NaN in the source column does not raise and does not get its own dummy column by default — that row just gets False across every dummy column, indistinguishable from a genuinely rare category by looking at the dummy columns alone:

s = pd.Series(["a", "b", None, "a"])
pd.get_dummies(s)
#        a      b
# 0   True  False
# 1  False   True
# 2  False  False   # the None row: both False, nothing marks it as missing
# 3   True  False

dummy_na=True is the fix — it adds an explicit NaN dummy column instead of leaving the missing row silently blended in with "none of the known categories":

pd.get_dummies(s, dummy_na=True)
#        a      b    NaN
# 0   True  False  False
# 1  False   True  False
# 2  False  False   True   # now visible
# 3   True  False  False

Same reflex as Lesson 3's missing-data lessons: know whether "missing" needs to stay visible in the output before choosing the default.

Q: "How would you turn a categorical column into something a model can use, and what's a common pitfall?" A strong answer, out loud: "pd.get_dummies() one-hot encodes it — one new True/False column per distinct value, replacing the original text column. It's the vectorized version of writing a CASE WHEN comparison for every value by hand. Two things I'd watch for: first, the columns are fully redundant with each other — if I know every dummy column except one, I already know that last one, so for linear models I'd usually drop_first=True to avoid multicollinearity. Second, a NaN in the source column doesn't raise or get flagged — it just becomes False across every dummy column by default, silently indistinguishable from a real category unless I pass dummy_na=True." The signal: naming both the multicollinearity reason for drop_first and the silent-NaN gotcha unprompted, not just describing the mechanical column-splitting.
