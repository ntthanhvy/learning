difflib: finding exactly what changed between two texts

== on two strings or two lists only answers yes/no — it says nothing about where they differ, which is what a code reviewer, a log comparer, or a "did the config change?" check actually needs. The difflib module is the standard-library tool for exactly that: given two sequences, it finds the added, removed, and shared parts and can render them as a human-readable diff.

1 · The problem: == only says yes or no

Comparing two versions of a config file, or two log captures, with plain equality gives no detail to act on:

old = ["host = localhost", "port = 8000", "debug = true"]
new = ["host = localhost", "port = 9000", "debug = true"]

print(old == new)   # False -- but which line changed? == can't say.

Finding the actual change by eye works for three lines; it stops working for a 500-line file. This is the gap difflib closes.

2 · unified_diff(): the familiar git diff shape

difflib.unified_diff() takes two lists of lines and returns a generator of lines in the same ---/+++/@@ format git diff and code-review tools already use — each changed line prefixed - (removed) or + (added), unchanged lines shown for context:

import difflib

diff = difflib.unified_diff(
    old, new, fromfile="old.conf", tofile="new.conf", lineterm=""
)
for line in diff:
    print(line)
# --- old.conf
# +++ new.conf
# @@ -1,3 +1,3 @@
#  host = localhost
# -port = 8000
# +port = 9000
#  debug = true

unified_diff() is a generator — nothing runs until iterated, same as Day 5's generators. The ---/+++ header lines and the @@ hunk marker always get their own newline added by unified_diff() itself; lineterm="" stops that addition, which only matters when the input lines (like old/new above) don't already carry a trailing \n of their own, as real lines read from an open file would.

3 · SequenceMatcher: a similarity ratio, no diff formatting

Sometimes the question isn't "show me the diff" but "how similar are these two strings?" — useful for fuzzy-matching a typo'd input against a list of known values. difflib.SequenceMatcher gives a single number between 0.0 (nothing alike) and 1.0 (identical):

import difflib

matcher = difflib.SequenceMatcher(None, "color", "colour")
print(matcher.ratio())   # 0.909... -- close but not identical

The first argument is reserved for an optional "junk" filter (characters to ignore when comparing, rarely needed) — pass None when there is nothing to ignore. difflib.get_close_matches(word, possibilities) builds directly on the same ratio to return the best-matching candidates from a list, which is the shape a "did you mean…?" suggestion needs:

import difflib

known_fields = ["username", "password", "email"]
print(difflib.get_close_matches("usrname", known_fields))   # ['username']
Where pandas goes from here: nothing pandas-specific today — difflib compares plain Python sequences (lines of text, or any list of hashable items); a DataFrame-vs-DataFrame diff is a different, library-specific question this course doesn't teach, per MISSION.md.
