1 · dumps/loads: JSON as a string, not a file

Day 6's json.load(f)/json.dump(obj, f) always take an already-open file object. Often the JSON text itself is what's needed — to send over a network, to store in one column of a database row, to print for debugging — with no file involved at all. dumps() ("dump string") and loads() ("load string") are the string-based twins of the exact same conversion:

import json

record = {"city": "Hanoi", "amount": 120, "tags": ["retail", "q3"]}

text = json.dumps(record)
print(text)        # '{"city": "Hanoi", "amount": 120, "tags": ["retail", "q3"]}'
print(type(text))  # <class 'str'>

back = json.loads(text)
print(back == record)  # True -- round-trips to an equal dict

The naming pattern holds across the whole module: dump/load work with an open file, dumps/loads work with a plain str already in memory. Reach for dumps/loads whenever the JSON text itself is the thing being passed around — an HTTP request body, a log line, a single text column — and dump/load only when writing straight to or reading straight from a file on disk.

2 · indent= and sort_keys=: JSON for a human to read

json.dumps()'s default output above is compact — correct, but hard to scan by eye. indent= reformats it as readable, multi-line text:

import json

record = {"city": "Hanoi", "amount": 120, "tags": ["retail", "q3"]}

print(json.dumps(record, indent=2))
# {
#   "city": "Hanoi",
#   "amount": 120,
#   "tags": [
#     "retail",
#     "q3"
#   ]
# }

indent=2 tells dumps() to insert that many spaces per nesting level and a newline after every item — the same shape a formatted config file or a pretty-printed API response uses. sort_keys=True additionally sorts every dict's keys alphabetically before writing, which makes two JSON dumps of the same data byte-for-byte comparable regardless of the order the dict happened to build its keys in — useful for diffing a saved snapshot against a freshly generated one. Both keywords work identically on json.dump() when writing to a file.

3 · default=: the one escape hatch for types json doesn't know

Day 72 named the core limit: json only knows the fixed set of types its text format defines — strings, numbers, booleans, None, lists, and dicts of those. A dataclass instance, a datetime, or any other custom object raises TypeError the moment dumps() reaches it:

from dataclasses import asdict, dataclass, is_dataclass
import datetime
import json

@dataclass
class Order:
    city: str
    placed_at: datetime.datetime

o = Order("Hanoi", datetime.datetime(2026, 10, 13, 9, 0))
json.dumps(o)   # raises TypeError: Object of type Order is not JSON serializable

default= is the hook json.dumps() calls on exactly the values it doesn't already know how to handle, letting the caller supply a conversion instead of giving up:

def fallback(value):
    if isinstance(value, datetime.datetime):
        return value.isoformat()
    if is_dataclass(value):
        return asdict(value)
    raise TypeError(f"not JSON serializable: {type(value)}")

json.dumps(o, default=fallback)
# '{"city": "Hanoi", "placed_at": "2026-10-13T09:00:00"}'

dumps() tries its built-in types first; only when a value is none of those does it call default(value) and use whatever that function returns in its place — which itself must be one of json's native types, or default runs again on that return value. fallback above handles both cases Day 72 called out by name: datetime turned into its standard string form with .isoformat(), and a dataclass turned into a plain dict with dataclasses.asdict() — both now just strings, numbers, and dicts that json already knows.

So when does default= lose to pickle? default= only helps when every custom type in the data has an obvious, lossless text-or-number stand-in — a datetime as an ISO string, a dataclass as a dict of its own JSON-safe fields. The moment an object's exact Python identity matters — it needs to come back as that class, with methods, not just a dict shaped like it — default= can convert it to JSON but nothing converts it back automatically; pickle round-trips the real object with no hand-written conversion function on either side, at the cost of Day 72's untrusted-source risk. Prefer default= for data crossing a network or a database column; reach for pickle only for same-process, trusted scratch storage of a real Python object.
