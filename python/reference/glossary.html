Python Intensive · Reference

Glossary

Every jargon term used in the lessons, in one place. Tiếng Việt column is dev-style — how Vietnamese devs actually say it, not textbook translation.

Day 1 — Names, objects & mutability

TermTiếng Việt (dev-style)In software
objectgiữ nguyên "object" — vùng dữ liệu thật nằm trong bộ nhớThe actual piece of data living in memory, with a type and a value. In Python everything is one — numbers, strings, lists, functions, even classes. Names are attached to objects; the object is the thing that exists.
name (variable)"biến" / "name" — cái nhãn dán lên object, không phải cái hộp chứaA label bound to an object. Python names are not boxes holding values — they are tags stuck onto objects. x = 5 makes the name x point at the object 5; it does not put 5 inside a container called x.
binding / rebinding"gán" — dán nhãn lên object; gán lại là chuyển nhãn sang object khácAssignment attaches a name to an object (binding). Assigning again moves that name to a different object (rebinding) — it never changes the object the name used to point at.
referencegiữ nguyên "reference" — đường trỏ từ tên tới objectThe link from a name to an object. Two names can hold references to the same object, which is why changing it through one name is visible through the other.
alias / aliasinggiữ nguyên "alias" — hai tên cùng trỏ một objectTwo or more names bound to the same object. b = a aliases; it does not copy. The classic Python surprise: mutating through b changes what a shows.
mutable"mutable" — sửa được tại chỗ (list, dict, set)An object whose contents can be changed in place without creating a new object: list, dict, set. Mutation is visible through every name referencing it.
immutable"immutable" — không sửa được, muốn đổi phải tạo object mớiAn object that cannot be changed after creation: int, float, str, tuple, bool. "Changing" one always builds a new object and rebinds the name.
mutate / mutated (in place)"sửa in-place" — đổi ruột object, không tạo cái mớiTo change an object's contents directly — lst.append(x), d["k"] = v. Contrast with rebinding, which swaps which object a name points to and leaves the original untouched.
identity (is)is — hỏi "có phải CÙNG MỘT object không", khác ==Whether two names refer to the very same object, tested with is and shown by id(). Distinct from ==, which asks whether two objects have equal values. Two equal lists can be separate objects.
shallow copy"shallow copy" — copy lớp ngoài, ruột bên trong vẫn dùng chungA new outer object whose elements are still references to the same inner objects. list(a) or a[:] gives one — safe against appends to the outer list, not against mutating a nested list inside it.
deep copy"deep copy" — copy toàn bộ, không dùng chung gì cảA recursive copy of an object and everything nested inside it, via copy.deepcopy(). Nothing is shared with the original — correct but slower, and rarely what you need.
mutable default argument"bẫy default mutable" — đừng để =[] hay ={} làm giá trị mặc địnhPython evaluates a function's default values once, when the function is defined — so a default [] or {} is one object shared by every call, accumulating across calls. The fix is None as the default plus a fresh object inside the body.
garbage collectiongiữ nguyên "GC" — object hết tên trỏ tới thì bị thu hồiAutomatic reclamation of objects nothing refers to any more. Rebinding the last name pointing at an object makes it unreachable, and Python frees it — which is why you never free memory by hand.

Day 2 — Comprehensions & slicing

TermTiếng Việt (dev-style)In software
list comprehensiongiữ nguyên "comprehension" — viết loop thành 1 dòng, tạo list/dict/set mớiA single expression that builds a new list directly from an iterable — [expr for item in iterable if cond] — replacing a for loop whose only job is appending one transformed item per iteration. The SQL parallel: expression is SELECT, the for-clause is FROM, the optional if-clause is WHERE.
dict comprehensiongiữ nguyên "dict comprehension" — comprehension tạo dict, dùng {} và dấu :A comprehension that builds a dict: {key_expr: value_expr for item in iterable}. Curly braces like a set, but with a colon separating key from value.
set comprehensiongiữ nguyên "set comprehension" — comprehension tạo set, dùng {} nhưng không có dấu :A comprehension that builds a set: {expr for item in iterable}. Curly braces like a dict but with no colon — one expression per element, and duplicates collapse since a set holds no repeats.
slicinggiữ nguyên "slicing" — cắt một đoạn của list/string cùng lúc bằng seq[start:stop:step]The seq[start:stop:step] syntax for extracting part of a sequence at once. stop is always exclusive; any of the three parts can be omitted (seq[:n], seq[n:], seq[:]), and a negative step like -1 reverses.
sequencegiữ nguyên "sequence" — dữ liệu có thứ tự, đánh index được (list, tuple, str)An ordered collection indexable by position — list, tuple, and str are the three used constantly. Slicing and positional indexing both rely on this ordering, and both work identically across all three types.

Day 3 — dict & set: grouping without pandas

TermTiếng Việt (dev-style)In software
dictgiữ nguyên "dict" — mapping key → value, tra cứu theo keyA mutable mapping from keys to values, written {key: value, ...}. Keys must be hashable (immutable); lookup by key is direct, not a scan of every entry.
setgiữ nguyên "set" — tập hợp phần tử duy nhất, không trùng, không thứ tựAn unordered collection of unique, immutable elements, written {a, b, c} — no duplicates, no positional index. Membership testing with in is direct, the same way dict key lookup is.
keygiữ nguyên "key" — giá trị dùng để tra cứu, phải là immutableThe value used to look something up in a dict, or an element of a set. Must be immutable — str, int, tuple, bool, frozenset qualify; list and dict do not, and raise TypeError if used as one.
setdefaultgiữ nguyên "setdefault" — lấy value nếu key có sẵn, chưa có thì tạo với default rồi trả vềdict.setdefault(key, default) returns the value at key if present, otherwise inserts key with that default and returns it. The one-line version of the "if not in, create it first" guard — the first line of a hand-written grouping loop.
defaultdictgiữ nguyên "defaultdict" — dict tự tạo value mặc định khi key chưa có, thay vì báo lỗicollections.defaultdict(factory) is a dict subclass that calls factory() to auto-create a value the first time a missing key is accessed, instead of raising KeyError. defaultdict(list) is the common grouping choice — no setdefault call needed.

Day 4 — Functions that pull their weight

TermTiếng Việt (dev-style)In software
functiongiữ nguyên "function" — khối code tái sử dụng, nhận đối số, có thể trả về giá trịA named, reusable block of code defined with def, taking zero or more arguments and optionally returning a value with return. A function name is bound to a function object exactly the way any other name is bound to any other object — it can be passed around like any value.
positional argumentgiữ nguyên "positional argument" — đối số khớp theo vị trí, không nêu tênAn argument matched to a function's parameter purely by its position in the call — discount(100, 0.2) matches 100 to the first parameter and 0.2 to the second.
keyword argumentgiữ nguyên "keyword argument" — đối số truyền dạng name=value, khớp theo tênAn argument passed as name=value in a call, matched to the parameter by name rather than position — discount(rate=0.2, price=100) works regardless of the order written.
default argumentgiữ nguyên "default argument" — giá trị mặc định khai báo sẵn, dùng khi caller không truyềnA parameter value supplied in the def line, e.g. def discount(price, rate=0.1), used automatically whenever the caller omits that argument. Evaluated once, when def runs — the reason a mutable default like [] is a trap.
lambdagiữ nguyên "lambda" — hàm ẩn danh viết trên 1 dòng, chỉ có 1 biểu thức, tự động returnlambda params: expr — an anonymous inline function limited to a single expression, whose value is returned automatically with no return keyword. Used where a small function is needed as a value, most often as the key= argument to sorted(), min(), or max().
key= (sorting)giữ nguyên "key=" — đối số nhận 1 hàm, tính giá trị dùng để so sánh thay vì so sánh trực tiếp itemA keyword argument accepted by sorted(), min(), max(), and list.sort() — a function called once per item to compute the value actually compared, instead of comparing the items directly. sorted(rows, key=lambda r: r["amount"]) sorts by each row's amount.

Day 5 — Iterators & generators: lazy pipelines

TermTiếng Việt (dev-style)In software
iterablegiữ nguyên "iterable" — cái gì for được, gọi iter() đượcAn object you can loop over with for — anything supporting iter(), including list, dict, set, str, range, and a generator. Being iterable says nothing about whether the whole sequence already exists in memory at once.
iteratorgiữ nguyên "iterator" — object nhớ vị trí, next() để lấy item kế tiếpThe object a for loop actually drives, produced by calling iter() on an iterable. Repeated calls to next() return successive items and remember position between calls, until StopIteration ends the loop.
generator functiongiữ nguyên "generator function" — function có yield, gọi nó tạo ra generator chạy lườiA function containing at least one yield statement. Calling it doesn't run the body — it returns a generator object that runs the body lazily, one step at a time up to each yield, on each next() call.
generatorgiữ nguyên "generator" — object trả về khi gọi generator function, tự nó là iteratorThe object returned by calling a generator function. Itself an iterator, so for and next() both work on it directly; running its body is deferred until the next value is actually asked for.
generator expressiongiữ nguyên "generator expression" — comprehension viết bằng ngoặc tròn, sinh giá trị lười(expr for item in iterable if cond) — syntactically a comprehension in parentheses instead of brackets, producing values lazily one at a time instead of building the whole list immediately.
lazy evaluationgiữ nguyên "lazy" — chỉ tính khi thật sự cần, không tính trướcComputing a value only when it's actually requested, rather than up front. Generators and generator expressions are lazy; a list or a list comprehension is eager — built completely before anything can use it.

Day 6 — Files, formats & context managers

TermTiếng Việt (dev-style)In software
with statementgiữ nguyên "with" — mở resource, tự động dọn dẹp dù có lỗi hay khôngThe with expr as name: statement runs the context manager's __enter__ before its block and guarantees __exit__ runs after the block ends, even if an exception was raised inside it. For files this means .close() always happens, unlike a manual open()/.close() pair where an exception in between skips the close entirely.
context managergiữ nguyên "context manager" — object có __enter__/__exit__, dùng được sau fromAny object implementing __enter__ and __exit__, making it usable after with. __enter__ runs at the start of the block and its return value is bound by as name; __exit__ runs at the end unconditionally — normal exit or exception — which is what makes with safe for cleanup.
file object as iteratorgiữ nguyên "file object" — chính nó là iterator, for line in f dùng đúng protocol Day 5An open file object is itself an iterator in the exact Day 5 sense: next() on it returns the next line, and StopIteration ends it once the file is exhausted. for line in f is not special file syntax — it's the same iter()/next() protocol driving any other iterable, applied to a file.
csv.DictReadergiữ nguyên "csv.DictReader" — đọc CSV, mỗi row trả về dạng dict theo tên cột thay vì list theo vị tríA wrapper around csv.reader that consumes the file's first row as field names, then hands back every subsequent row as a dict keyed by column name instead of a plain list indexed by position. Every value is still a str — CSV has no number type, so numeric fields need explicit conversion (int(...), float(...)) after reading.
JSONgiữ nguyên "JSON" — định dạng dữ liệu dạng text, object/array của nó map thẳng sang dict/list của PythonA text format for structured, nestable data whose {...} object and [...] array syntax map directly onto Python's own dict and list literals. json.load(f) reads a file straight into real Python objects, preserving types (int, list, ...); json.dump(obj, f) writes them back out as JSON text.

Day 7 — Dataclasses, typing & an ETL capstone

TermTiếng Việt (dev-style)In software
dataclassgiữ nguyên "dataclass" — class khai báo field có kiểu, tự có __init__/__repr__/__eq__, đỡ phải viết tayA class decorated with @dataclass from the standard library dataclasses module. Declaring typed fields as class-level annotations auto-generates __init__, a readable __repr__, and a field-by-field __eq__, removing the boilerplate a plain class needs for the same guarantees.
default (dataclass field)giữ nguyên "default" — giá trị mặc định khai trong field, dùng khi constructor không truyềnA value written directly in a dataclass field declaration, e.g. currency: str = "VND", used automatically whenever a caller omits that field in the constructor call — same idea as Day 4's default argument, applied to a class field instead of a function parameter. Distinct from Day 4's default argument, which is a function-parameter default, not a class-field one.
type hintgiữ nguyên "type hint" — chú thích kiểu dữ liệu, Python không tự kiểm tra lúc chạyAn optional annotation on a variable, function parameter, or return value stating the type it's expected to hold, written name: Type. Python does not enforce these at runtime — they're documentation plus input for external tools like editors and mypy.
Optional[X]giữ nguyên "Optional" — kiểu X hoặc None, dùng khi field có thể chưa có giá trịtyping.Optional[X], equivalent to X | None, means a value is either type X or the literal None — used to hint a parameter or field that may legitimately be missing.
ETLgiữ nguyên "ETL" — Extract (đọc), Transform (biến đổi), Load (ghi ra) — hình dạng chuẩn của pipeline dữ liệuExtract reads raw data from its source format, Transform reshapes/cleans/aggregates it into the shape actually needed, and Load writes the result to its destination — the standard three-stage shape of nearly every real data pipeline, including the capstone script this lesson builds.

Day 8 — Exceptions: catching failure on purpose

TermTiếng Việt (dev-style)In software
exceptiongiữ nguyên "exception" — object Python raise ra khi có lỗi, mang theo type và message, dừng chạy bình thường ngay lập tứcAn object Python raises the instant something goes wrong, carrying a type (e.g. ValueError, KeyError) and a message. Raising one immediately stops normal execution and hands control to the nearest matching except block, or all the way out of the program if none exists.
tracebackgiữ nguyên "traceback" — báo cáo Python in ra khi exception không ai bắt, cho thấy chuỗi hàm gọi nhau lúc lỗi xảy raThe report Python prints when an exception reaches the top of the program uncaught: the exception's type, its message, and the chain of function calls active when it was raised. An uncaught exception is the default outcome, not a special failure mode.
try / exceptgiữ nguyên "try/except" — chạy code có thể lỗi trong try, bắt đúng loại lỗi mong đợi trong excepttry: runs code that might raise; each except ExceptionType: after it catches only that exact type, letting anything else propagate. Always name the exact type — a bare except: catches everything, including real bugs, and silently hides them.
else / finally (try statement)giữ nguyên "else/finally" — else chạy khi try không lỗi, finally luôn chạy dù có lỗi hay khôngIn a try statement, else runs only if the try block raised nothing at all; finally runs unconditionally — success, caught failure, or even an uncaught failure still propagating afterward — the same "always runs" guarantee as Day 6's context-manager __exit__.
raisegiữ nguyên "raise" — chủ động tạo ra exception khi hàm gặp input không xử lý đượcThe statement that creates and triggers an exception on purpose, e.g. raise ValueError("message"), used inside a function when a caller has done something the function can't handle. Immediately stops that function and propagates like any other exception.
custom exceptiongiữ nguyên "custom exception" — exception type tự định nghĩa bằng cách subclass Exception, đặt tên riêng cho lỗi cụ thể của mìnhA new exception type defined by subclassing Exception (or a more specific built-in type), giving a domain-specific failure its own name so callers can except it narrowly instead of guessing which built-in type a function happens to raise.

Day 9 — Modules, packages & imports

TermTiếng Việt (dev-style)In software
modulegiữ nguyên "module" — một file .py, import được bằng tên (bỏ .py) từ file khác cùng thư mục hoặc nằm trên import pathA single .py file, importable by name (without the .py extension) from another file in the same directory or on Python's import path. Its top-level code runs once, on first import anywhere in the program; a second import elsewhere reuses the cached result instead of re-running the file.
__name__giữ nguyên "__name__" — biến string tự có trong mọi module, giá trị "__main__" khi chạy trực tiếp, tên module khi bị importA built-in string variable every Python module has automatically. It holds "__main__" when the file is run directly (uv run python3 file.py), and the module's own name when the file is imported by another file instead — the mechanism behind the if __name__ == "__main__": guard.
importgiữ nguyên "import" — lấy code từ module/package khác vào file hiện tại, bằng tên đầy đủ hoặc tên rút gọnThe statement that pulls a module or package's code into the current file, either kept behind a prefix (import csv, used as csv.reader(...)) or pulled in directly by name (from csv import DictReader). Python searches already-imported modules first, then the importing file's own directory, then installed packages, then the standard library.
packagegiữ nguyên "package" — thư mục chứa __init__.py, biến thư mục thành namespace import được, module bên trong gọi bằng tên có dấu chấmA directory containing an __init__.py file (possibly empty), making the directory itself importable as a namespace whose modules are reached with dotted names, e.g. mypkg.parsing.

Day 10 — Environments & pyproject.toml

TermTiếng Việt (dev-style)In software
virtual environmentgiữ nguyên "virtual environment" hoặc "venv" — thư mục riêng chứa interpreter và package cho 1 project, tách biệt project khácAn isolated, self-contained directory holding one project's own Python interpreter and installed packages, kept separate from every other project's so their dependencies never collide. uv run finds or creates one automatically as .venv/.
package managergiữ nguyên "package manager" — công cụ cài package vào thư mục riêng cho từng project thay vì cài toàn máyA tool, like uv, that installs packages into an isolated per-project environment instead of system-wide, so different projects can hold different, non-conflicting versions of the same package at once.
pyproject.tomlgiữ nguyên "pyproject.toml" — file khai báo tên project, version, và list dependency chuẩn của PythonThe standard Python project metadata file: declares the project's name, version, required Python version, and the exact list of packages it depends on (split into runtime dependencies and a dev group), so any tool — including uv — can reproduce the same environment elsewhere.
uv.lockgiữ nguyên "uv.lock" — file chốt version chính xác đã cài, tự sinh ra, không sửa tayA generated file recording the exact resolved version of every dependency (and their own dependencies) actually installed, as opposed to pyproject.toml's loose, human-edited constraints. Running uv sync against the same lock file reproduces an identical set of versions on another machine.
uv add / uv run --withgiữ nguyên "uv add" / "uv run --with" — add ghi vào pyproject.toml lâu dài, --with chỉ cài tạm cho 1 lần chạyuv add pkg permanently adds a dependency to pyproject.toml and updates uv.lock; uv run --with pkg script.py installs it into a temporary environment for that single run only, leaving both project files untouched.

Day 11 — Testing with pytest

TermTiếng Việt (dev-style)In software
pytestgiữ nguyên "pytest" — thư viện test bên thứ 3, ngoại lệ duy nhất của luật "chỉ dùng standard library" trong khoá nàyA third-party testing framework — the one deliberate exception to this course's standard-library-only rule. Finds any function named test_* in any file named test_*, runs it, and reports pass/fail based on whether an assert inside it fails. Installed ad hoc with uv run --with pytest pytest ..., or project-wide with uv add --dev pytest.
assert (in a test)giữ nguyên "assert" — pytest chỉ cần assert thường, không cần self.assertEqual kiểu unittestA plain assert expr statement is all a pytest test needs to check a value — no self.assertEqual(...) or test-class boilerplate, which belongs to the standard library's older unittest style and is not taught in this course. On failure, pytest shows the actual values on both sides of the comparison automatically.
fixturegiữ nguyên "fixture" — hàm chuẩn bị dữ liệu/tài nguyên cho test, test nào cần thì khai tên fixture làm tham sốA function decorated @pytest.fixture that prepares something a test needs (data, a temp file, a connection) and hands it to any test naming that fixture as a parameter. Code before yield is setup, run once per using test; code after yield is teardown, guaranteed to run once that test finishes — the same "always runs" guarantee as a context manager's __exit__ (Day 6) or a finally block (Day 8).
parametrizegiữ nguyên "parametrize" — chạy 1 test body nhiều lần với nhiều bộ input/output khác nhau, mỗi lần báo cáo riêng@pytest.mark.parametrize("names", [(...), (...)]) runs one test body once per listed tuple of arguments, reporting each case as its own separate pass/fail instead of one test looping silently over several cases — the pytest-native replacement for a hand-rolled list of check calls.

Day 12 — Decorators

TermTiếng Việt (dev-style)In software
decoratorgiữ nguyên "decorator" — hàm nhận 1 hàm khác, bọc thêm hành vi, rồi trả về hàm bọc đóA function that takes another function, wraps it with extra behavior in a new inner function (usually called wrapper), and returns that wrapper. @decorator above a def is shorthand for calling the decorator on the function just defined and rebinding the original name to its result — no new runtime concept beyond Day 1's binding/rebinding and Day 4's "a function is a value."
wrappergiữ nguyên "wrapper" — hàm nằm bên trong decorator, gọi lại hàm gốc và có thể thêm hành vi quanh nóThe inner function a decorator defines and returns — it calls the original function (usually via *args, **kwargs so it accepts whatever arguments the original takes) and may add behavior before, after, or around that call.
decorator with argumentsgiữ nguyên "decorator có tham số" — hàm nhận tham số riêng, trả về 1 decorator thật, decorator đó mới bọc hàm đíchA decorator spelled with its own call, e.g. @repeat(3): an extra outer function that takes an argument (times) and returns a real decorator (one function argument), which is then applied to the target function — one more layer of nesting than a plain @shout.
functools.wrapsgiữ nguyên "functools.wraps" — decorator chuẩn thư viện, copy __name__/docstring của hàm gốc sang wrapperA standard-library decorator, @functools.wraps(func), applied to a wrapper function so it inherits func's __name__, docstring, and a few other attributes — without it, a decorated function's identity (as reported by __name__) silently becomes the generic "wrapper" instead of its own name.

Day 13 — pathlib

TermTiếng Việt (dev-style)In software
pathlibgiữ nguyên "pathlib" — module chuẩn thư viện, biểu diễn đường dẫn file như 1 object có method thay vì string tự ghépThe standard-library module for representing a filesystem path as a Path object with methods and properties on it, instead of a plain string built and re-parsed by hand. Fixes the structural bugs manual concatenation risks — the wrong separator on Windows, an accidental double slash — by deciding the correct separator itself.
Pathgiữ nguyên "Path" — object đại diện 1 đường dẫn, hỗ trợ / để nối, và các method như exists()/read_text()The core class from pathlib, e.g. Path("data") / "sales.csv". Building one never touches the filesystem by itself — it just describes a location; methods like .exists(), .read_text(), and .glob() are the explicit, separate steps that actually touch disk.
/ operator (path joining)giữ nguyên "/ operator" — Path định nghĩa lại dấu / để nối đường dẫn, không phải phép chiaPath overloads / to mean "join this path with the next component," returning a new Path — the same way + means concatenation for two strings and addition for two numbers, dispatched by the type on the left of the operator, not a new kind of division.
glob (pattern matching)giữ nguyên "glob" — tìm file theo mẫu ký tự đại diện như *.csv, glob() chỉ tìm 1 cấp, rglob() tìm cả thư mục conPath.glob(pattern) lazily yields every path in a directory matching a shell-style wildcard ("*.csv"), staying within that one directory; Path.rglob(pattern) does the same but recurses into every subdirectory too.

Day 14 — datetime & timezones

TermTiếng Việt (dev-style)In software
datetimegiữ nguyên "datetime" — class biểu diễn 1 thời điểm cụ thể: năm, tháng, ngày, giờ, phút, giâyThe class from Python's standard-library datetime module representing a specific point in calendar time — year, month, day, hour, minute, second, microsecond.
naive datetimegiữ nguyên "naive datetime" — datetime không gắn timezone, mơ hồ khi so sánh giữa các múi giờ khác nhauA datetime object with no tzinfo attached — a time with no attached timezone, exactly SQL's plain TIMESTAMP. Ambiguous the moment it needs comparing against a time from a different zone.
aware datetimegiữ nguyên "aware datetime" — datetime có gắn timezone, so sánh/convert được rõ ràng, giống TIMESTAMPTZA datetime object with a real tzinfo attached, anchoring it to a specific timezone or UTC offset — exactly SQL's TIMESTAMPTZ. Safe to compare or subtract against other aware datetimes.
timedeltagiữ nguyên "timedelta" — class biểu diễn khoảng thời gian (duration), cộng/trừ trực tiếp được với datetimeThe class from datetime representing a duration or difference between two points in time — days, seconds, microseconds — usable directly in arithmetic with datetime objects (dt + timedelta(days=7)).

dunder methodgiữ nguyên "dunder method" — method tên có __ hai đầu, Python tự gọi khi dùng cú pháp built-in như print(), ==, <A method whose name starts and ends with double underscores (e.g. __init__, __repr__, __eq__). Python calls these automatically for built-in syntax like print(), ==, <, or len(), instead of them being called by name directly.
operator overloadinggiữ nguyên "operator overloading" — định nghĩa dunder method để toán tử built-in (+, ==, <...) hoạt động trên object tự viếtDefining a dunder method like __add__ or __eq__ on your own class so a built-in operator (+, ==, <, etc.) works on instances of it — reusing an existing operator's syntax for a new type, rather than inventing a new method name.
@propertygiữ nguyên "@property" — decorator biến method thành đọc như attribute thường, không cần dấu ()A built-in decorator that turns a method into something accessed with no parentheses, like a plain attribute. The method's return value is computed fresh on each access, unlike a stored attribute value — useful when a value is fully derived from other already-stored attributes and should never drift out of sync with them.

Day 34 — match/case: structural pattern matching

TermTiếng Việt (dev-style)In software
structural pattern matchinggiữ nguyên "structural pattern matching" — so 1 subject value với nhiều case pattern theo thứ tự, chạy pattern đầu tiên khớp, có thể gán tên cho từng phần bên trong luônA match statement compares a subject value against a series of case patterns in order, running the first one that fits and optionally binding names to the pieces it matched inside — checking shape/type and destructuring contents in one statement, rather than a separate check followed by separate unpacking. Added in Python 3.10 (PEP 634).
wildcard pattern (_)giữ nguyên "wildcard pattern" — case _ khớp với bất kỳ giá trị nào, không gán tên gì, đặt cuối cùng làm nhánh mặc định giống elseThe underscore case pattern that matches any subject and binds nothing, conventionally placed last as the catch-all — the pattern-matching equivalent of an else clause in an if/elif chain.
guard clausegiữ nguyên "guard clause" — điều kiện if thêm vào case, chỉ check sau khi pattern đã khớp shape, để loại bớt trường hợp khớp shape nhưng không đạt điều kiện khácAn extra condition attached to a case pattern with if, checked only after the pattern itself already matched structurally — a match with a false guard is rejected and Python moves on to try the next case. A guarded capture pattern (case cmd if ...:) is not irrefutable, so — unlike an unguarded one — it's allowed before other case lines.

Day 35 — __slots__: trading dynamic attributes for memory and safety

TermTiếng Việt (dev-style)In software
__slots__giữ nguyên "__slots__" — khai tên các attribute cố định cho class, bỏ dict riêng mỗi instance để tiết kiệm bộ nhớ, đổi lại không gán được attribute ngoài danh sáchA class attribute, written as a tuple of attribute-name strings, that tells Python exactly which attributes instances of this class are allowed to have — removing the per-instance dict every plain object carries by default, in exchange for losing the ability to add a new attribute name that wasn't declared. Every class in an inheritance chain needs its own __slots__, or a subclass without one silently regains a __dict__.
instance __dict__giữ nguyên "instance __dict__" — dict riêng mỗi instance có sẵn, chứa tên và giá trị attribute, x.attr = value ghi vào đâyThe dict every plain instance carries by default, mapping each instance attribute's name to its value — where x.attr = value actually stores the label, and the reason a typo'd attribute name silently succeeds instead of raising an error. __slots__ removes it.

Day 36 — functools: memoizing, freezing arguments, and folding

TermTiếng Việt (dev-style)In software
lru_cachegiữ nguyên "lru_cache" — decorator cache kết quả hàm theo tham số, gọi lại với tham số cũ trả kết quả lưu sẵn, không tính lạiA decorator, @functools.lru_cache, that wraps a function with a cache keyed on its arguments — a repeat call with arguments already seen returns the stored result immediately instead of recomputing it. Only safe on a pure function with hashable arguments; cache_info()/cache_clear() inspect and reset the cache.
partialgiữ nguyên "partial" — cố định sẵn 1 số tham số của hàm, trả về hàm mới chỉ cần truyền phần tham số còn lạiA function, functools.partial, that takes a function plus some of its arguments and returns a new callable with those arguments already filled in — calling the new callable only needs whatever arguments are left. Useful anywhere a plain few-argument callable is expected but the real work needs more.
reducegiữ nguyên "reduce" — gộp toàn bộ iterable thành 1 giá trị duy nhất, áp hàm 2 tham số lần lượt từ trái sang phảiA function, functools.reduce(function, iterable, initial), that applies a two-argument function cumulatively across an iterable, left to right, collapsing it to one value — the general mechanism sum()/any()/max() are each one narrow, named case of. An empty iterable with no initial raises TypeError.

Day 37 — Descriptors: how @property and @classmethod actually work

TermTiếng Việt (dev-style)In software
descriptor protocolgiữ nguyên "descriptor protocol" — tập method (__get__, __set__, __set_name__) cho phép 1 object đặt trong class tự can thiệp vào việc đọc/ghi attributeThe set of methods (__get__, __set__, __set_name__) that, when defined on an object stored in a class's own __dict__, let that object intercept and customize attribute access on every instance of the class, instead of a plain value just sitting there. property, classmethod, and staticmethod are all built on it.
descriptorgiữ nguyên "descriptor" — object gắn ở class, định nghĩa __get__/__set__, Python tự gọi khi đọc/ghi obj.attr thay vì trả giá trị lưu sẵnAny object whose class defines one or more of the descriptor protocol's methods, and which is itself stored as a class attribute. Python calls its __get__/__set__ automatically on attribute access instead of just returning a plain stored value.
non-data descriptorgiữ nguyên "non-data descriptor" — descriptor chỉ có __get__, không có __set__, nên instance __dict__ cùng tên sẽ được ưu tiên đọc trước, __get__ không chạyA descriptor whose class defines only __get__, with no __set__ or __delete__ — it customizes reads but has no say over writes, so a same-named entry in an instance's own __dict__ is found first and the descriptor's __get__ never runs. classmethod, staticmethod, and plain functions are all non-data descriptors; property is not (it defines __set__, making it a data descriptor, checked ahead of the instance __dict__).
