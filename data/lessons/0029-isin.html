isin(): filtering against a list of values

Lesson 28's teaser named no single dangling candidate, so this round did a fresh curriculum/glossary scan — the clearest genuinely-uncovered gap found: isin(), the direct pandas spelling of SQL's WHERE col IN (...), has been used unglossed inside earlier lessons' fixture descriptions but never actually taught. A small, high-frequency win to close out today.

1 · The SQL you already know

You already write this constantly: WHERE customer IN ('An', 'Chi'). The naive pandas translation — chaining == comparisons with | (Lesson 24's boolean-mask OR) — works but doesn't scale past two or three values:

# works, but ugly for more than 2-3 values
clean[(clean["customer"] == "An") | (clean["customer"] == "Chi")]

isin() replaces the whole OR chain with one call, for any number of candidates:

clean[clean["customer"].isin(["An", "Chi"])]
#   order_id customer  amount  order_date
#0         1       An   120.0  2026-01-05
#1         6       An    42.0  2026-01-10

Hand-verified: the isin() mask and the equivalent chained ==/| mask are element-for-element identical on this course's fixture — isin() is purely a readability/scaling win, not a different filter.

2 · NOT IN: negate with ~

SQL's NOT IN is pandas' ~ (Lesson 24's boolean-NOT) in front of isin():

clean[~clean["customer"].isin(["An"])]
#   order_id customer  amount  order_date
#0         2     Binh    35.5  2026-01-06
#1         5     Binh   180.0  2026-01-09

Same rule as every other boolean mask in this course: ~ flips every True/False in the mask before it's used to filter — nothing isin()-specific about the negation.

3 · Filtering against another column — a lightweight anti-join

isin()'s argument doesn't have to be a hand-typed list — it can be any list-like, including another DataFrame's column. That gives Lesson 5's anti-join pattern without a full merge(indicator=True) call, when all you need is "which rows match/don't match by key," not the other side's columns:

customers = pd.read_csv("practice/data/customers.csv")
# customer region
# An       North
# Binh     South
# Danh     West

never_ordered = customers[~customers["customer"].isin(clean["customer"])]
# customer region
# Danh     West       <- Danh has no matching order, confirmed against Lesson 5's fixture

This is narrower than Lesson 5's merge-based anti-join: it only tells you which rows matched, with no ability to pull columns across from the other table in the same step. Reach for merge(indicator=True) when you need the other side's data too; reach for isin() when a key-only membership check is all the step needs.

4 · Two gotchas, both hand-verified on this pandas version (3.0.5)

Gotcha 1 — a bare string instead of a list. Older pandas folklore warns that isin("An") silently iterates over the string's characters (checking membership in {'A', 'n'}) instead of matching the whole word — a classic "no crash, quietly wrong" trap. That folklore is now outdated: verified directly that current pandas (3.0.5) actually raises TypeError: only list-like objects are allowed to be passed to isin() for a bare string. pandas added a real guard here, same shape of correction this course made for Lesson 26's SettingWithCopy behavior — always wrap the candidates in [...], a tuple, or a set regardless, since relying on today's guard existing forever isn't a safe habit.

clean["customer"].isin("An")
# TypeError: only list-like objects are allowed to be passed to isin(), you passed a `str`

Gotcha 2 — Python's bare in keyword is not isin(). Python's own in operator on a Series checks the Index labels, never the values — a real and easy mix-up since both spellings look almost identical:

"An" in clean["customer"]     # False -- "An" is a VALUE, not an index label
0 in clean["customer"]        # True -- 0 IS a real index label on this DataFrame

isin() is always the method call; bare in is a different question entirely (row-label membership) that happens to share the same English word.

5 · Inside query() and inside a method chain

isin() combines directly with Lesson 22's query() via the same @variable syntax, and reads close to the SQL original:

allowed = ["An"]
clean.query("customer in @allowed")   # same @variable rule as Lesson 22, "in" spelled like SQL

Because it's one call returning a mask, isin() also drops straight into Lesson 8's method chains without breaking the chain to name an intermediate boolean variable first.

Q: "How would you filter a DataFrame to rows where a column matches any of several values?" A strong answer, out loud: "isin() — it's the direct pandas spelling of SQL's WHERE col IN (...). I pass it a list, and it returns a boolean mask I can index the DataFrame with, or wrap in ~ for NOT IN. It scales better than chaining == comparisons with | past two or three values, and it works against any list-like — a hand-typed list, or another DataFrame's column, which gives me a lightweight anti-join when I only need to check membership and don't need to pull columns across." The signal: naming the SQL equivalence directly and knowing when NOT to reach for it (when you need the other table's columns too, that's a real merge).
