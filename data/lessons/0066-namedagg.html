pd.NamedAgg: naming multi-column aggregations without the MultiIndex dance

Lesson 65 closed out with no fresh teaser, so today started from another from-scratch scan of every lesson and the glossary against MISSION.md's goals. A clean gap surfaced: pd.NamedAgg — zero hits anywhere in 65 lessons or the glossary, despite two lessons standing right next to it. Lesson 4 taught named aggregation on one pre-selected column (df.groupby("customer")["amount"].agg(total="sum", orders="count")) — every named result pulls from the SAME source column. Lesson 61 taught multi-column .agg({col: [funcs]}) on the whole groupby, but its output is an ugly MultiIndex that has to be flattened by hand ("_".join(c) for c in result.columns). pd.NamedAgg is the missing piece that names output columns directly while each one pulls from a different source column — no manual flattening required.

1 · The gap between Lesson 4 and Lesson 61

Lesson 4's named aggregation only works because the groupby is already narrowed to one column first:

df.groupby("customer")["amount"].agg(total="sum", orders="count")
-- both "total" and "orders" read the SAME "amount" column

The moment two output columns need to read different source columns — total spend from amount, but order count from order_id — that single-column form has nowhere to say which column each name comes from. Calling .agg() on the whole groupby with a plain dict falls back to Lesson 61's shape: readable input, ugly MultiIndex output.

2 · pd.NamedAgg(column=, aggfunc=): the explicit form

pd.NamedAgg is a small named-tuple-like object built exactly for this: each keyword argument to .agg() becomes one output column name, and its value names both the source column and the function to run on it:

clean.groupby("customer").agg(
    total=pd.NamedAgg(column="amount", aggfunc="sum"),
    orders=pd.NamedAgg(column="order_id", aggfunc="count"),
    first_order=pd.NamedAgg(column="order_date", aggfunc="min"),
)
--           total  orders first_order
-- customer
-- An        162.0       2  2026-01-05
-- Binh      215.5       2  2026-01-06

Confirmed directly (pandas 3.0.5) on the real orders_raw.csv clean 4-row slice: result.columns.tolist() is a plain flat ["total", "orders", "first_order"] — no MultiIndex, no "_".join() step needed. Three different source columns, three different functions, one call, one pass over the data.

Gotcha, confirmed directly: the keyword is aggfunc=, not func=. Many older tutorials and even casual pandas snippets write pd.NamedAgg(column="amount", func="sum") — that raises outright on this version: TypeError: NamedAgg.__init__() missing 1 required positional argument: 'aggfunc'. There is no silent fallback or deprecation warning; it simply refuses to construct. Worth typing aggfunc= from memory rather than guessing under interview pressure.

3 · The plain-tuple shorthand is identical, not a different feature

pd.NamedAgg(column="amount", aggfunc="sum") and the bare tuple ("amount", "sum") are the same thing under the hood — confirmed directly, both forms below produce byte-identical results (.equals() is True):

clean.groupby("customer").agg(total=("amount", "sum"), orders=("order_id", "count"))
-- identical output to the pd.NamedAgg version above (minus first_order)

The tuple is shorter to type; pd.NamedAgg is worth naming out loud in an interview because it makes the column/function pairing self-documenting in code review, and because it also accepts a custom callable as aggfunc= (a lambda or named function), not just a built-in function name string — confirmed directly, pd.NamedAgg(column="amount", aggfunc=lambda s: s.max() - s.min()) runs Lesson 61's "range" calculation in the .agg() form directly, no groupby().apply() needed for this simpler single-column case.

Gotcha, confirmed directly: pd.NamedAgg only works on the WHOLE groupby, not an already column-selected one. Lesson 4's pattern — df.groupby("customer")["amount"].agg(...) — has already narrowed to one column, so passing a NamedAgg there raises TypeError: func is expected but received NamedAgg in **kwargs. NamedAgg's whole reason to exist is naming a source column per result, which is meaningless once a single column is already selected — Lesson 4's plain total="sum" string form is still the right tool there, unchanged. Reach for NamedAgg/tuples specifically on the whole-groupby, multi-source-column case.

4 · SQL bridge

This is exactly SELECT customer, SUM(amount) AS total, COUNT(order_id) AS orders, MIN(order_date) AS first_order FROM orders GROUP BY customer — one SELECT, several aggregate expressions over different source columns, each given its own alias. pd.NamedAgg's column=/aggfunc= pair is the pandas spelling of "which column, which aggregate, what alias" all in one place, the same three facts a SELECT ... AS line states.

Q: "You need total spend, order count, and first order date per customer, in one call, with clean column names — how?" A strong answer, out loud: "Call .agg() on the whole groupby object, not a pre-selected column, and pass one pd.NamedAgg per output name: column= for the source, aggfunc= for the function. Each named result can read a totally different column, and the output comes back with plain flat column names already — no MultiIndex to flatten by hand, which is what you'd get from a plain dict with list-valued functions. The tuple shorthand, (column, func), does the exact same thing with less typing; NamedAgg is worth naming because it also takes a custom callable, not just a built-in function name, and it only works once you're grouping the whole frame rather than a single already-selected column." The signal: naming the exact keyword (aggfunc=, not func=), contrasting with Lesson 61's manual flatten, and knowing the whole-groupby precondition.
