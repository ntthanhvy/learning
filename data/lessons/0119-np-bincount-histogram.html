np.bincount() / np.histogram(): the counting siblings of digitize()

Yesterday's lesson closed with three standing candidates from a fresh curriculum/glossary scan: np.lexsort(), np.partition()/argpartition(), and np.histogram()/np.bincount() — the latter named explicitly as "the bin-counting sibling of today's bin-assigning function" and as Lesson 68's own passing, never-taught mention. Today picks that one: it continues the same "name the NumPy function underneath an already-taught pandas idiom" lineage as Lessons 93, 100, 102, 109-112, 114, and 117-118, and ties directly back to yesterday's np.digitize() lesson with a confirmed exact-equivalence chain.

1 · bincount(): the fast tally underneath factorize() + count

Lesson 68's factorize() turns repeated labels into small dense integer codes. np.bincount() is the raw-array primitive doing that tally: given an array of non-negative integer codes, it returns one count per distinct code value, indexed by the code itself. Confirmed directly (numpy 2.5.4, pandas 3.1.1), reusing Lesson 68's own factorize() shape on a small name column:

import numpy as np
import pandas as pd

s = pd.Series(["An", "Binh", "Binh", "Chi", "An", "An"])
codes, uniques = pd.factorize(s)
# codes   = array([0, 1, 1, 2, 0, 0])
# uniques = Index(['An', 'Binh', 'Chi'])

np.bincount(codes)
# array([3, 2, 1])  -- 3 "An"(code 0), 2 "Binh"(code 1), 1 "Chi"(code 2)

s.value_counts().reindex(uniques)
# An      3
# Binh    2
# Chi     1
# dtype: int64  -- SAME counts, reindexed to match factorize()'s code order

Confirmed directly: np.bincount(codes) matches value_counts() exactly once both are lined up to the same order — but bincount() works on raw integer codes only, with none of value_counts()'s label bookkeeping. minlength= pads the output with trailing zeros when the highest code might not appear in every batch (useful when counts get accumulated across chunks):

np.bincount(np.array([0, 2]), minlength=5)
# array([1, 0, 1, 0, 0])  -- codes 3 and 4 never occurred, padded with 0 instead of omitted

2 · weights=: bincount() doubles as a hand-rolled groupby sum

Confirmed directly: passing weights= (an array the same length as the codes) switches bincount() from counting occurrences to summing weights per code — the exact shape of a groupby().sum(), done without pandas:

weights = np.array([10.0, 20.0, 5.0, 1.0, 2.0, 3.0])

np.bincount(codes, weights=weights)
# array([15., 25.,  1.])  -- sum of weights where code==0, code==1, code==2

pd.DataFrame({"code": codes, "w": weights}).groupby("code")["w"].sum()
# code
# 0    15.0
# 1    25.0
# 2     1.0
# Name: w, dtype: float64  -- SAME totals, via pandas groupby instead

This is the sharpest interview-relevant fact about bincount(): it only ever accepts non-negative integers for its main array — a float input raises TypeError: Cannot cast array data from dtype('float64') to dtype('int64'), and a negative integer raises ValueError immediately. There is no silent coercion either way; both error cases are confirmed loud, not silent.

3 · histogram(): the same bin-edge idea as digitize(), but counting instead of assigning

Yesterday's np.digitize(x, bins) returned one bin index per value. np.histogram() instead returns the count of values landing in each bin directly, plus the edges — skipping the per-value index step entirely. Confirmed directly: chaining yesterday's two functions reproduces histogram()'s counts exactly, on the same amount values and bin edges as Lessons 12/118:

amounts = np.array([120.0, 35.5, 180.0, 42.0, 40.0])
bins = [0, 40, 100, 200]

counts, edges = np.histogram(amounts, bins=bins)
# counts = array([1, 2, 2]), edges = array([  0,  40, 100, 200])

np.bincount(np.digitize(amounts, bins) - 1, minlength=len(bins) - 1)
# array([1, 2, 2])  -- IDENTICAL: histogram() == bincount() chained onto digitize() - 1

Confirmed directly against the official docs: every bin except the last is half-open ([edge, next), right excluded) — the same convention as yesterday's digitize() default — but the last bin is closed on both sides ([edge, last], right included), the one asymmetry digitize() itself does not have.

4 · The trap: out-of-range values, and NaN most of all, vanish with no warning

Confirmed directly, and confirmed absent from the official docs page (no mention of NaN handling at all): any value outside every bin edge — and a NaN value always counts as outside, since every comparison against it is False — is silently dropped from every bin's count, with the total across all bins coming up short of the input length and no exception, no warning: 
vals = np.array([np.nan, 50.0, 120.0])

counts, edges = np.histogram(vals, bins=bins)
# counts = array([0, 1, 1])  -- sums to 2, but len(vals) is 3: the NaN is just gone

pd.cut(pd.Series(vals), bins=bins).value_counts(dropna=False)
# (0.0, 40.0]       0
# (40.0, 100.0]     1
# (100.0, 200.0]    1
# NaN               1
# Name: count, dtype: int64  -- pd.cut() keeps the NaN as its OWN visible row

This is the sharp, genuinely interview-relevant gotcha, and it is the same root cause as yesterday's np.digitize() trap wearing a different costume: np.digitize() at least gives NaN a (wrong-looking) valid index to investigate; np.histogram() gives it nothing at all — the count total simply comes up short, which is easy to miss if nobody is comparing it against the array's own length. Anyone hand-rolling a histogram pass on real data (which always has some missing values) must check counts.sum() == len(x) explicitly, or drop/flag NaN before calling it — pd.cut(...).value_counts(dropna=False) is the pandas-native alternative that already surfaces the missing count as its own row.

5 · bins as an integer: histogram()'s other common call shape

Confirmed directly: calling np.histogram(x) with no bins= (or bins= as a plain integer) auto-computes that many equal-width bins spanning x's own min/max — a quick distribution shape check with zero manual edge-picking, the same auto-binning role pd.cut(x, bins=10) (an integer, not a list) plays back in Lesson 12:

np.histogram(amounts)  # default bins=10, auto edges from amounts.min() to amounts.max()
# counts = array([2, 0, 0, 0, 0, 1, 0, 0, 0, 1])
# edges  = array([ 35.5 ,  49.95,  64.4 ,  78.85,  93.3 , 107.75, 122.2 ,
#                  136.65, 151.1 , 165.55, 180.  ])
