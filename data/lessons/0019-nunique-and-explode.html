nunique() and explode(): counting distinct, and un-nesting lists

Lesson 18's closing teaser named this pair directly — "nunique() or explode(), both still genuinely uncovered." Today ships both together: one collapses multiplicity down to a count, the other expands it out into rows — a deliberate contrast, not a coincidence of pairing.

1 · nunique(): how many DISTINCT values, not how many rows

Three pandas methods sound similar and answer three genuinely different questions. Lesson 10's value_counts() answers "how many rows have EACH value" — one count per distinct value. Plain .count() answers "how many non-null rows are there" — one number, ignoring whether values repeat. nunique() answers a third question: "how many DISTINCT values are there, total" — one single count, collapsing all the repeats away.

Run it on the raw 6-row orders_raw.csv fixture Lessons 6-18 have loaded from — three customers placed those 6 orders (An x3, Binh x2, Chi x1):

df = pd.read_csv("practice/data/orders_raw.csv")

df["customer"].count()      # 6  -- six non-null rows in the column
df["customer"].nunique()   # 3  -- only three DISTINCT names among those 6 rows
df["customer"].value_counts()
# An      3
# Binh    2
# Chi     1

value_counts() breaks the 6 rows down per name; count() just counts the 6 non-null rows and throws away which name each one belongs to; nunique() throws away both the row count AND the per-name breakdown, keeping only "how many different names appeared." The SQL bridge is exact and immediate: nunique() is COUNT(DISTINCT col), full stop — the one pandas method whose SQL translation needs no hedging.

2 · nunique() per group

Chained after groupby(), nunique() answers "how many distinct X does each group have" — a per-group cardinality check, same split-apply-combine shape Lesson 4 introduced. On the clean 4-row slice (dropping the unparseable amount and the missing date, same slice every lesson since Lesson 6 has used), how many distinct order dates does each customer have:

clean.groupby("customer")["order_date"].nunique()
# An      2   (2026-01-05, 2026-01-10)
# Binh    2   (2026-01-06, 2026-01-09)

Both customers show 2 — each of their two clean orders happened on a different day, so "distinct dates" equals "row count" here. That's not always true: if An had placed two orders on the same date, nunique() would say 1 while a plain row count would still say 2 — exactly the gap this method exists to catch (e.g. "did this customer order on multiple distinct days, or just submit the same day's order twice?"). SQL bridge:

SELECT customer, COUNT(DISTINCT order_date)
FROM orders
GROUP BY customer;

3 · explode(): one row per list element

Sometimes a column doesn't hold a scalar — it holds a Python list (or, loaded from JSON, an array) of several values packed into one cell. explode() un-nests that: one row goes in, one row comes out per list element, with every other column's value copied alongside each one. A small inline table — orders that each carry a list of tags (not touching the shared CSV fixtures, same as Lesson 11's inline "double-submitted export" table):

tagged = pd.DataFrame({
    "order_id": [1, 2],
    "tags": [["urgent", "gift"], ["bulk"]],
})
tagged.explode("tags")
#    order_id    tags
# 0         1  urgent
# 0         2    gift
# 1         2    bulk

Order 1 had two tags, so it becomes two rows — order_id 1 duplicated on both, one tag per row. Order 2 had one tag, so it stays one row. Notice the row INDEX duplicates too (0 appears twice) — explode() doesn't renumber, so a follow-up .reset_index(drop=True) is standard practice once the shape is what you want. SQL's cousin is array-unnesting: Postgres' UNNEST(tags), typically written as CROSS JOIN LATERAL unnest(tags) to pair each unnested element back with its row, or the equivalent for exploding a JSON array column (jsonb_array_elements). Same job, different spelling: "one row per list element, other columns copied alongside."

4 · Round trip: nunique() collapses, explode() expands

nunique() and explode() point in opposite directions, and both are fundamentally about handling multiplicity — many values mapping to (or packed into) one thing:

  • nunique() — many rows in, one number out. Collapsing, same direction as Lesson 4's groupby() (which collapses by aggregating values, not just counting distinct ones).
  • explode() — one row (with a list) in, many rows out. Expanding, but a different kind of expansion than Lesson 6's melt(): melt reshapes COLUMNS into rows (wide → long, no lists involved); explode reshapes LIST ELEMENTS WITHIN a single cell into rows (no columns disappear, one column's values multiply out).

In a real cleaning pipeline they can even chain: explode a tags column out to one-tag-per-row, then nunique() that exploded tags column to answer "how many distinct tags exist across all orders" — expand first to make each value analyzable on its own row, then collapse to count what's distinct.

Q: "How would you count distinct values in a column, and how would you handle a column that holds a list per cell?" A strong answer, out loud: "For distinct counts I'd reach for nunique() — it's exactly COUNT(DISTINCT col) from SQL, and I'd use it as a quick cardinality or sanity check: how many unique customers, how many unique SKUs, does this ID column actually behave like a key. For a list-valued cell — tags, categories, a JSON array column — I'd explode() it: one row per list element, every other column copied alongside, the same job as UNNEST() or CROSS JOIN LATERAL unnest() in Postgres. I'd reach for explode() specifically when I need to denormalize a packed array/JSON column into rows I can groupby or filter on individually — you can't groupby a list value, so exploding first is usually the unblocking step." The signal: naming COUNT(DISTINCT) and UNNEST unprompted, and being able to say WHEN each pandas method actually gets reached for, not just what it does.
