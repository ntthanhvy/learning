DataFrame.insert() and .pop(): the two column-management methods that mutate in place

Lesson 95's teaser carried forward two open candidates — np.broadcast_to() and DataFrame.insert()/.pop() — without naming either as THE next pick. A fresh grep across every lesson body and the glossary confirmed both are still genuine zero-coverage gaps. Picking the pandas pair today: it closes the column-management picture left open since Lesson 78's .assign() (always non-mutating, always appends at the end) and Lesson 54/57's family of frame-shape checks — the two methods here are the only common column tools that mutate the DataFrame directly, a real interview trap if assumed to behave like everything else.

1 · insert(): adding a column at a CHOSEN position, in place

Plain assignment (df["new"] = values, Lesson 78's .assign()) always appends a new column at the end. insert() is the one tool that puts a column anywhere else. Confirmed directly (pandas 3.0.6):

import pandas as pd
df = pd.DataFrame({"a": [1, 2], "b": [3, 4], "c": [5, 6]})
ret = df.insert(1, "new_col", [100, 200])
# ret is None -- insert() mutates df directly, nothing to reassign
df
#    a  new_col  b  c
#0  1      100  3  5
#1  2      200  4  6      -- new_col landed exactly at loc=1, between a and b

The trap: insert() raises ValueError on a duplicate column name by default — confirmed directly — unless allow_duplicates=True is passed explicitly, and raises IndexError if loc is outside 0 <= loc <= len(df.columns):

df.insert(0, "a", [0, 0])
# ValueError: cannot insert a, already exists
df.insert(99, "z", [0, 0])
# IndexError: loc must be an integer between -1 and 4

A second, sharper trap, confirmed directly against the official pandas docs: if value is a Series with its own index, insert() aligns by that index label, not by row position — a mismatched index silently produces NaN, exactly like Lesson 5's merge/join alignment rules, not a positional drop-in:

df2 = pd.DataFrame({"col1": [1, 2], "col2": [3, 4]})
df2.insert(0, "col0", pd.Series([5, 6], index=[1, 2]))
#    col0  col1  col2
#0    NaN     1     3   -- row 0 has no label "0" in the Series -> NaN
#1    5.0     2     4   -- row 1 matched label 1 -> 5

2 · pop(): removing a column AND handing it back

pop() is the mirror case: it removes a column from the DataFrame and returns it, in one call. Confirmed directly:

df3 = pd.DataFrame({"a": [1, 2, 3], "b": [4, 5, 6], "c": [7, 8, 9]})
popped = df3.pop("b")
# popped is a Series: [4, 5, 6], name="b"
df3
#    a  c
#0  1  7
#1  2  8
#2  3  9      -- "b" is gone from df3, not just from a copy

Compare that to Lesson 57's row-count-safety cousin, drop(columns=): drop() always returns a new frame and leaves the original untouched (inplace=True aside) — pop() never gives that choice, it always mutates. Confirmed directly, a missing column name raises KeyError on both:

df3.pop("zzz")
# KeyError: 'zzz'

3 · Why this pair is the odd one out

Every other common column-shaping tool in this course returns something new and leaves the input alone: .assign() (Lesson 78), drop(columns=), rename(), plain df["x"] = ... assignment on a view-safe frame. insert() and pop() are the exception — both mutate the DataFrame object itself, in place, no reassignment needed or even possible (df = df.insert(...) would silently set df to None). That matters most in a method chain: a chain built around .assign()/.pipe()-style immutability (Lesson 8) breaks the moment insert() or pop() is dropped in — they have to run as a standalone statement, not inside a chain.

# WRONG -- insert() returns None, this sets df to None:
df = df.insert(0, "x", [1, 2])

# RIGHT -- call it as its own statement, df is already mutated:
df.insert(0, "x", [1, 2])

Q: "What's the difference between df.insert(), df.pop(), and df.drop(columns=)?" A strong answer, out loud: "insert() and pop() both mutate the DataFrame directly and return None or the removed column — not a new frame. insert() lets me put a column at an exact position instead of always appending at the end, but it raises if the name already exists unless I pass allow_duplicates=True. pop() removes a column and hands it back as a Series in one call, which is handy when I want to both pull a column out and drop it from the frame. drop(columns=), by contrast, never touches the original — it always returns a new frame, so it fits inside a method chain the way insert() and pop() never can, since they return None or a Series, not a DataFrame." The signal: naming the in-place/returns-None behavior correctly, and knowing why that breaks a chained pipeline.
