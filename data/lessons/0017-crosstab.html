crosstab(): frequency tables done right

Lesson 16's closing teaser named crosstab() directly — "a frequency-table shortcut related to but distinct from pivot_table, not yet covered." Lesson 6 built pivot_table for general reshape-and-aggregate work; today's tool is the one-call shortcut for the specific, very common case of "just count how two categorical columns co-occur."

1 · The one-call shortcut pivot_table doesn't have

pd.crosstab(index, columns) counts how often each combination of two categorical columns occurs together — a frequency cross-tab — with no values and no aggfunc needed for the plain-count case. That's the difference from Lesson 6's pivot_table, which always requires both: pivot_table is built around "aggregate a values column," so even a pure count needs aggfunc="size" spelled out explicitly. In fact the two calls are exactly equivalent for that case:

pd.crosstab(a, b)
-- is the same table as --
df.pivot_table(index=a, columns=b, aggfunc="size", fill_value=0)

crosstab() is just that one common shape given its own name and a shorter call — one tool for quick categorical counts, the other for everything else.

2 · Building one: reusing Lesson 12's bins

Lesson 12 sorted amount into tiers with pd.cut(amount, bins=[0, 40, 100, 200], labels=["Low", "Mid", "High"]). Run that on the same clean 4-row slice Lessons 6-16 have used (An/120.0, Binh/35.5, Binh/180.0, An/42.0) and cross-tab the result against customer:

tier = pd.cut(clean["amount"], bins=[0, 40, 100, 200], labels=["Low", "Mid", "High"])
pd.crosstab(clean["customer"], tier)
--           Low  Mid  High
-- An          0    1     1
-- Binh        1    0     1

An's two orders land one in Mid (42.0) and one in High (120.0); Binh's land one in Low (35.5) and one in High (180.0). Every cell not mentioned is a real, counted zero — same fill_value=0 behavior Lesson 6's pivot_table needed to ask for explicitly, except crosstab() does it by default since it's always counting, never risking a genuine missing aggregate.

3 · normalize=: percentages without a transform() detour

Pass normalize="index" to turn every row into proportions of that row's own total, summing to 1.0 across each customer:

pd.crosstab(clean["customer"], tier, normalize="index")
--           Low  Mid  High
-- An        0.0  0.5   0.5
-- Binh      0.5  0.0   0.5

normalize="all" divides by the grand total instead, so every cell is a share of every order across every customer, not just that customer's own orders — the four cells above become 0.0, 0.25, 0.25 for An and 0.25, 0.0, 0.25 for Binh, all six real cells summing to 1.0. This is crosstab()'s strongest advantage over building the same percentages by hand: Lesson 16's groupby().transform("sum") path (per-row divide by a broadcast group total) gets there for one row-normalization case, but takes a groupby, a transform, and a division — versus one keyword argument here.

normalize= options: "index" — each row sums to 1 (row-wise %). "columns" — each column sums to 1 (column-wise %). "all" — every cell is a share of the grand total. Pick the one matching the question actually being asked: "of An's orders, what % were High?" is "index"; "of all High orders, what % were An's?" is "columns".

4 · When crosstab grows into pivot_table

Add values= and aggfunc= and crosstab() stops being count-only and becomes functionally identical to pivot_table:

pd.crosstab(clean["customer"], tier, values=clean["amount"], aggfunc="sum")
--           Low   Mid   High
-- An        NaN  42.0  120.0
-- Binh     35.5   NaN  180.0

That's the exact same result Lesson 6's pivot_table(index="customer", columns=tier, values="amount", aggfunc="sum") would produce — no fill_value this time, so the genuinely-empty cells show NaN, same default as pivot_table. The rule of thumb: reach for crosstab() when the question is "how do these two categorical columns break down against each other" (counts or percentages, no values needed) — reach for pivot_table the moment there's a real values column and the full aggfunc/fill_value/multi-metric control Lesson 6 covered is wanted. Both call the same reshape machinery under the hood; crosstab() just defaults toward the counting case.

Q: "You need a quick frequency breakdown of two categorical columns with row-wise percentages — what's the one-liner?" A strong answer, out loud: "pd.crosstab(col_a, col_b, normalize='index') — crosstab defaults to counting how often each combination occurs, and normalize='index' turns each row into proportions of that row's own total in one call. The alternative — groupby(col_a)[col_b].value_counts() then transform to divide by the row total — gets the same numbers but takes several more steps. I'd reach for pivot_table instead only if I actually need to aggregate a real values column, not just count categories." The signal: naming normalize= specifically, not just "crosstab counts things" — the percentage shortcut is the part that actually saves work over a plain value_counts().
