Series.mode(): the most-frequent value, and why it can hand back more than one

Lesson 107 closed the .str.* text-cleanup family (strip → pad → title → join) with no pre-committed next topic. A fresh scan across every lesson body and the glossary turned up .mode() as a genuine zero-hit gap: Lesson 9 taught value_counts() to see every value's frequency, but never the single dedicated method for "just give me the most frequent one(s)" — and probing it directly surfaced a real shape trap: it always returns a Series, not a scalar, because there can genuinely be more than one correct answer.

1 · mode() always returns a Series — even when there's exactly one answer

value_counts() (Lesson 9) ranks every distinct value by frequency. Series.mode() skips the ranking and hands back only the value(s) sitting at the very top. On this course's own orders_raw.csv fixture, where customer has An×3, Binh×2, Chi×1, there is exactly one most-frequent value — but the result is still a one-row Series, not a plain string:

import pandas as pd

orders = pd.read_csv("practice/data/orders_raw.csv")
orders["customer"].mode()
# 0    An
# Name: customer, dtype: str   -- a Series with ONE row, not a bare "An" string

orders["customer"].mode().iloc[0]
# "An"   -- pull out the scalar explicitly once you know there's only one

Confirmed directly (pandas 3.1.0): orders["customer"].mode().iloc[0] equals orders["customer"].value_counts().index[0] exactly — same answer, reached two different ways — but mode() never shows the actual counts the way value_counts() does. SQL has no single built-in either: the usual shape is GROUP BY customer ORDER BY COUNT(*) DESC LIMIT 1, which also silently drops any tie past the first row unless written more carefully — exactly the trap the next section makes explicit instead of hiding.

2 · The real reason it's a Series: ties come back as multiple rows

The Series shape is not an accident of API design — it's the only correct shape, because more than one value can be tied for most frequent, and mode() returns every one of them, confirmed directly against the official docs:

s = pd.Series(["a", "b", "a", "b", "c"])
s.mode()
# 0    a
# 1    b
# Name: ..., dtype: str   -- "a" and "b" are BOTH tied at 2 occurrences each; "c" (1) is left out

Pushed to the extreme: a Series where every value is unique has every single value tied at a frequency of exactly 1 — so mode() returns the entire Series back, sorted, not an error and not an empty result:

pd.Series([3, 1, 2]).mode()
# 0    1
# 1    2
# 2    3   -- every value occurred exactly once, so every value is "the mode"
This is the sharp interview trap: code that blindly does df["col"].mode()[0] or .mode().iloc[0] assuming "the one most common value" will silently return an arbitrary member of a tie instead of raising anything — no exception, no warning, just the first row of whatever the tie-break order happens to produce. Always check len(s.mode()) before trusting index 0 alone when ties are even remotely plausible (categorical columns with few distinct values, especially).

3 · Missing values: dropped by default, but not always

Confirmed directly: mode() ignores NaN by default (dropna=True), the same default direction as value_counts() — but unlike value_counts(), flipping dropna=False doesn't just add NaN's count to the ranking, it lets NaN win outright if NaN is genuinely the single most frequent entry:

import numpy as np

s2 = pd.Series([1, 1, 2, np.nan, np.nan, np.nan])
s2.mode()
# 0    1.0   -- dropna=True (default): NaN excluded from the count entirely, 1.0 wins among real values

s2.mode(dropna=False)
# 0    NaN   -- NaN occurs 3 times, more than any real value -- it IS the mode here

Confirmed directly: an all-empty Series returns an empty mode Series (no error, no NaN row) — mode() never raises on empty or all-NaN input, unlike idxmax()'s documented ValueError on all-NaN data (Lessons 20/91/93). DataFrame.mode() (no column selected) runs this column-by-column and stacks the results side by side, each column padded with NaN down to the longest column's tie count — a shape worth knowing exists, out of scope to drill here.

Q: "How would you find the most common value in a column, and what would you watch out for?" A strong answer, out loud: "I'd reach for .mode() — it's purpose-built for exactly this, versus manually sorting value_counts(). But I wouldn't blindly take .iloc[0]: mode() always returns a Series, not a scalar, specifically because ties are possible — if two or more values are tied for most frequent, it returns all of them as separate rows, and grabbing index 0 silently picks an arbitrary one with no warning. I'd check the length first, and if NaN itself might be the most common entry, I'd explicitly decide whether dropna=True or False is the right call for that column." The signal: knowing mode()'s return shape is deliberate, not incidental — it exists to represent "there may be more than one right answer" honestly.
