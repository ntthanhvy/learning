reindex(): forcing a chosen label set

Lesson 32 flagged, in passing, that a real weekday revenue report "would reindex against an explicit Monday-through-Sunday list" before presenting it — and then moved on without ever showing how. Lesson 46's own teaser named no single dangling candidate, so today's fresh scan picked up that loose thread: reindex(), the tool for forcing a Series or DataFrame onto EXACTLY the labels you name, filling in whatever's missing and dropping whatever isn't asked for.

Recap, in one line

.loc[] (Lesson 1 onward) looks up labels you give it and raises KeyError the moment one isn't there. reindex() is built for exactly that missing-label case: instead of raising, it returns your object reshaped onto the label list you asked for, real data lined up where it already matches and everywhere else quietly NaN (or a value you choose).

1 · The problem reindex() solves: a result missing rows that should exist

Same weekday revenue from Lesson 32 — only 4 of the 7 weekdays actually had an order, so the plain groupby() result silently has only 4 rows, sorted alphabetically:

by_day = clean.groupby(clean["order_date"].dt.day_name())["amount"].sum()
-- order_date
-- Friday      180.0
-- Monday      120.0
-- Saturday     42.0
-- Tuesday      35.5
-- Name: amount, dtype: float64   -- only days that HAD an order show up at all

Wednesday, Thursday, and Sunday aren't wrong here — they're simply not present. A groupby() can only report on data that exists; a day with zero orders leaves no row for it to compute at all. That's a different failure shape from a wrong value: there is no row to be wrong, the row is just missing.

2 · reindex(): specify the full label set you actually want

reindex() takes the label list you actually want and forces the result onto it:

weekday_order = ["Monday", "Tuesday", "Wednesday", "Thursday",
                 "Friday", "Saturday", "Sunday"]
by_day.reindex(weekday_order)
-- order_date
-- Monday       120.0
-- Tuesday       35.5
-- Wednesday      NaN   -- no orders that day -- reindex() ADDS this row
-- Thursday       NaN
-- Friday       180.0
-- Saturday      42.0
-- Sunday         NaN
-- Name: amount, dtype: float64

Lesson 32's own dangling fix, finally done: the result is now in true calendar order, with the missing weekdays represented rather than silently absent.

3 · fill_value: choosing what "missing" becomes

A missing day of revenue is more honestly 0.0 than NaN — nobody bought anything, the true number is known, it's zero. fill_value= makes that explicit instead of leaving NaN to mean two different things ("unknown" and "genuinely zero") at once:

by_day.reindex(weekday_order, fill_value=0)
-- Monday       120.0
-- Tuesday       35.5
-- Wednesday      0.0   -- explicit real zero now, not NaN
-- Thursday       0.0
-- Friday       180.0
-- Saturday      42.0
-- Sunday         0.0

Whether to reach for fill_value=0 or leave it as NaN is a judgment call about what "missing" means in context (Section 4 shows a case where NaN is the honest answer instead).

Gotcha — reindex() requires the axis' labels to be UNIQUE, or it raises: The weekday example works because groupby() collapsed each weekday down to one row — "Monday" appears exactly once in the result's index. Try the same move on clean set_index'd directly on "customer" (two rows are literally labeled "An", two are labeled "Binh") and it refuses outright rather than guessing which row you meant: 
clean.set_index("customer").reindex(["An", "Binh", "Danh"])
-- ValueError: cannot reindex on an axis with duplicate labels
Group-and-aggregate FIRST (so each label appears exactly once), then reindex() the result — the same order this lesson's own weekday example already used.

4 · A genuinely-missing entity: NaN is the honest answer, not 0

Reindexing a per-customer total onto every known customer name (including one who placed zero orders in this fixture, "Danh") is a different situation from the weekday case — here, leaving it NaN is the correct call, not a compromise:

totals = clean.groupby("customer")["amount"].sum()
totals.reindex(["An", "Binh", "Danh"])
-- An      162.0
-- Binh    215.5
-- Danh      NaN   -- unknown whether Danh bought nothing or just hasn't ordered yet

Filling Danh in as 0.0 would be actively misleading here: it asserts "we know Danh spent nothing," when the truth is "we have no data on Danh in this table at all." The weekday case and the customer case look identical mechanically — both are reindex() onto a superset of labels — but the right fill_value choice depends entirely on what a missing label actually means for that specific column, a judgment call worth naming out loud in an interview rather than defaulting to one habit.

5 · reindex() on columns: adding one that doesn't exist

reindex() isn't limited to row labels — columns= does the identical job across the other axis, and a genuinely absent column doesn't raise either, joining this course's "no crash, quietly wrong" family (Lessons 19, 30, 43):

clean.reindex(columns=["order_id", "customer", "amount", "region"])
--   order_id customer  amount  region
-- 0        1       An   120.0     NaN   -- "region" isn't a real column -- added as all-NaN
-- 1        6       An    42.0     NaN
-- 2        2     Binh    35.5     NaN
-- 3        5     Binh   180.0     NaN

A typo'd column name here doesn't raise KeyError the way clean[["region"]] would — it silently manufactures a brand-new all-NaN column instead. Worth an .isna().all() gut-check on any column that arrived via reindex(columns=...) before trusting it.

Q: "How would you fill in the gaps in a groupby result — say, days with zero activity that don't show up at all?" A strong answer, out loud: "A plain groupby only produces rows for keys that actually exist in the data — a day with no orders leaves no row, not a zero row. reindex() fixes that: I'd reindex the result onto the full label set I actually want — every calendar day, every known customer, whatever the complete set should be — and pandas fills in real values where they exist and NaN everywhere else. Then I'd think about fill_value: is a missing label a genuine zero, like a day with no sales, or a genuine unknown, like a customer I have no data on at all? Those need different fill values, and defaulting to 0 everywhere can quietly assert something false. I'd also flag that reindex() needs unique labels on that axis — it raises ValueError on a duplicate-label index rather than guessing which row to use, so I'd aggregate down to one row per key first if the raw table doesn't already have that." The signal: naming the missing-vs-wrong distinction, the fill_value judgment call, and the duplicate-label gotcha unprompted.

6 · The SQL bridge

reindex()'s closest SQL relative is a LEFT JOIN against a fully-populated calendar/dimension table — SELECT cal.weekday, COALESCE(SUM(o.amount), 0) FROM calendar_weekdays cal LEFT JOIN orders o ON cal.weekday = day_name(o.order_date) GROUP BY cal.weekday guarantees every weekday appears, filling non-matches with COALESCE's default — the same two-step shape as reindex(fill_value=...), just spelled with a join instead of a standalone table method.
