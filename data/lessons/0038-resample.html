resample(): bucketing a datetime index into fixed periods

Lesson 37's teaser named no single dangling candidate, so this round is a fresh scan against the curriculum spine and glossary. Lesson 32 taught the .dt accessor for pulling date parts out row by row, and Lesson 4 taught groupby() for grouping by an existing column's values — but neither one fills in a period with zero rows, which is exactly the gap a real "daily revenue" or "weekly active customers" report needs closed. resample() is pandas' purpose-built tool for that: group by fixed time buckets (day, week, month) directly off a datetime index, buckets with no rows included.

1 · The problem: groupby by date silently skips empty periods

On this course's cleaned 4-row slice (An 120.0/01-05, An 42.0/01-10, Binh 35.5/01-06, Binh 180.0/01-09), grouping daily revenue with Lesson 32's own .dt-accessor pattern looks reasonable at first:

clean.groupby(clean["order_date"].dt.date)["amount"].sum()
# order_date
# 2026-01-05    120.0
# 2026-01-06     35.5
# 2026-01-09    180.0
# 2026-01-10     42.0

Four rows in, four dates out — but 2026-01-07 and 2026-01-08, the two days with zero orders, are not in the result at all. groupby() can only group values that exist; a day nobody ordered on has no row to begin with, so there's nothing to group. For a daily revenue chart or a "days since last order" calculation, a missing row and a genuine $0 day look identical from the output alone — which is wrong in exactly the way Lesson 3's missing-data lessons warned about.

2 · resample(): groupby for fixed time periods, gaps included

resample() requires a DatetimeIndex — Lesson 33's set_index() on the already-parsed order_date column, exactly the setup step both tools share:

indexed = clean.set_index("order_date")
indexed["amount"].resample("D").sum()
# order_date
# 2026-01-05    120.0
# 2026-01-06     35.5
# 2026-01-07      0.0   <- no orders that day -- resample still emits the row
# 2026-01-08      0.0   <- same
# 2026-01-09    180.0
# 2026-01-10     42.0
# Freq: D, Name: amount, dtype: float64

"D" is the offset alias naming the bucket width. Every calendar day between the Series' first and last timestamp gets its own row now — 2026-01-07 and 2026-01-08 included, summed to 0.0 because sum() of an empty group is zero. That's the entire difference from Section 1's groupby(): resample() builds the full calendar grid first, then aggregates into it, rather than only ever seeing rows that already exist.

3 · Same aggfunc menu as groupby — but "empty" isn't always 0

resample() is chained with the exact same aggregations as groupby()/Lesson 4 — sum(), mean(), count(), .agg({...}) — but what an empty bucket becomes depends entirely on which one is chosen:

indexed["amount"].resample("D").count()
# 2026-01-07    0    <- count of zero rows is genuinely 0, no ambiguity
indexed["amount"].resample("D").mean()
# 2026-01-07    NaN  <- the mean of NOTHING isn't 0, it's undefined
Gotcha: resample().sum() quietly fills empty buckets with 0.0 — a real, defensible number for a revenue total. resample().mean() quietly fills them with NaN instead, because "the average of zero orders" has no sensible numeric answer. Same method chain shape, two different fill behaviors depending on what the aggregate itself means for an empty group — always check which aggfunc is in play before assuming what an empty period looks like in the output.

4 · Bigger buckets: "W" for week, and the single-week trap in this fixture

Swapping the offset alias changes only the bucket width, nothing else about the call shape:

indexed["amount"].resample("W").sum()
# order_date
# 2026-01-11    377.5
# Freq: W-SUN, Name: amount, dtype: float64

Only one row comes back — not a bug, just this fixture's real shape: all four orders (Jan 5-10) fall inside a single Sunday-ending week, so there is only one bucket to report. W defaults to weeks ending Sunday (hence the label 2026-01-11, the Sunday that closes out that week); W-MON, W-TUE, etc. move the week boundary if a report needs to start weeks on a different day. The general lesson: resample's bucket count depends on the data's actual date span relative to the bucket width, not on how many rows exist — a wider bucket than the data's range collapses everything into one period, same as a GROUP BY key with only one distinct value.

5 · Mixed columns: resample().agg({...}) for more than one aggregate

Like Lesson 14's multi-aggfunc pivot_table, resample() also accepts a per-column aggregation dict — useful when a numeric column needs summing while a text column just needs "whichever value showed up":

indexed.resample("D").agg({"amount": "sum", "customer": "first"})
#             amount customer
# order_date
# 2026-01-05   120.0       An
# 2026-01-06    35.5     Binh
# 2026-01-07     0.0      NaN   <- no rows that day -- amount sums to 0, but there's no customer to report, so NaN
# 2026-01-08     0.0      NaN
# 2026-01-09   180.0     Binh
# 2026-01-10    42.0       An

Worth noticing directly: the same empty bucket produces 0.0 in the amount column (a real sum) and NaN in the customer column (no row at all to take a "first" value from) — Section 3's per-aggfunc empty-bucket rule applies per column too, not just per whole call.

6 · asfreq(): the same grid-building step, no aggregation

When there's already at most one row per timestamp and the only goal is to expose the gaps (not aggregate anything), asfreq() does resample's grid-building half without an aggfunc:

indexed["amount"].asfreq("D")
# 2026-01-07    NaN   <- no aggregation happened -- there was simply no row, so NaN, not 0
# 2026-01-08    NaN

asfreq("D") is close to resample("D").asfreq() or, on data with no duplicate timestamps, to a plain reindex() against a generated daily date range — it reindexes onto the regular grid but never sums or counts, so a missing day is unambiguously NaN, never 0. Reach for resample() the moment there's a real aggregation to run (including "first row wins" ties); reach for asfreq() only when the data is already one-row-per-timestamp and the gaps themselves are the whole point.

Q: "You have a table of timestamped orders and need daily revenue, including days with zero orders. How do you build it?" A strong answer, out loud: "First, order_date needs to be parsed to datetime64 and set as the index — resample() requires a DatetimeIndex, it won't work off a plain column. Then indexed['amount'].resample('D').sum() gives one row per calendar day between the first and last order, zero-filled automatically for any day with no orders — that's the key difference from groupby(df['order_date'].dt.date), which can only group rows that already exist, so it silently skips empty days entirely. One thing I'd flag: sum() zero-fills empty buckets, but mean() gives NaN for them instead, since the average of zero orders isn't a real number — so which aggfunc is running changes what 'empty' looks like in the output. If I needed weekly instead of daily, it's the same call with 'W' instead of 'D', just watch that a narrow date range can collapse into a single week bucket." The signal: naming resample's DatetimeIndex requirement, the groupby contrast (skips vs. fills gaps), and the sum-vs-mean empty-bucket distinction unprompted.
