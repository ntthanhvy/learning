np.piecewise(): the conditional-branching sibling of np.select() — and the Series footgun hiding inside it

Lesson 115's own closing note named np.piecewise() as the one remaining standing candidate, first surfaced in Lesson 113's note and carried forward through 114 and 115 without being picked. A fresh scan of every lesson, the full glossary, and this course's own notes confirms it is still a genuine zero-hit as taught content — today it closes that gap.

1 · np.select() picks a VALUE per branch; np.piecewise() runs a FUNCTION per branch

Lesson 24 already covers np.where() and np.select(): both pick, per element, a precomputed value from a parallel list of choices based on which condition matched. np.piecewise() is the sibling that instead runs a different function on each matching slice of the input — closer to its actual mathematical namesake, a piecewise-defined function:

import numpy as np

x = np.array([-5.0, -1.0, 0.0, 2.0, 10.0])

# Piecewise: square negatives, pass non-negatives through unchanged.
result = np.piecewise(x, [x < 0, x >= 0], [lambda v: v**2, lambda v: v])
# array([25.,  1.,  0.,  2., 10.])  -- lambda v: v**2 ran ONLY on [-5, -1], not the whole array

Confirmed directly (numpy 2.5.4): each function in funclist receives only the already-filtered subset of x matching its own condition — v inside the first lambda above is array([-5., -1.]), never the full five-element array. That is the core mechanical difference from np.select(), whose choice expressions are normally computed over the full array first and picked from afterward.

2 · Three small rules, confirmed directly, before the real trap

A scalar anywhere in funclist is accepted and quietly treated as a constant function (np.piecewise(x, [x<0, x>=0], [-1, 1]) works, no lambda required). Passing len(condlist) + 1 functions — one more function than conditions — makes that extra, final function the "otherwise" default, run wherever every condition was False. Elements covered by no condition and no default function are confirmed to come back as plain 0, not NaN:

np.piecewise(x, [x < -100], [lambda v: -1])
# array([0., 0., 0., 0., 0.])  -- no element matched; default is 0, not NaN

np.piecewise(x, [x < 0], [lambda v: -1, 99])  # 2 funcs, 1 cond -> 2nd is "else"
# array([-1., -1., 99., 99., 99.])

A function-count that is neither len(condlist) nor len(condlist) + 1 raises ValueError immediately, naming both counts — confirmed directly: "with 1 condition(s), either 1 or 2 functions are expected".

3 · The footgun: a list of pandas Series conditions crashes with a confusing IndexError

The trap: confirmed directly (pandas 3.1.0, numpy 2.5.4) by reading the NumPy source after reproducing the failure — passing condlist as a Python list of pandas Series (the natural result of writing [s < 0, s >= 0] on a Series s) raises IndexError: too many indices for array: array is 1-dimensional, but 2 were indexed. This is not a dtype problem and not about x itself — x can be a Series with no issue. The cause is a heuristic inside np.piecewise() that decides whether condlist is "one condition" or "a list of several conditions" by checking isinstance(condlist[0], (list, numpy.ndarray)). A pandas Series is neither a list nor an ndarray, so the check misfires: the whole two-item list of Series gets wrongly treated as a single condition and wrapped in an extra layer, turning a shape that should be (2, 5) into (1, 2, 5) — a 2-D condition array ends up indexing a 1-D x, which is exactly what the IndexError reports.
import pandas as pd

s = pd.Series([-5.0, -1.0, 0.0, 2.0, 10.0])
np.piecewise(s, [s < 0, s >= 0], [lambda v: v**2, lambda v: v])
# IndexError: too many indices for array: array is 1-dimensional, but 2 were indexed

# Fix: convert each CONDITION to a NumPy array (x itself may stay a Series).
np.piecewise(s, [(s < 0).to_numpy(), (s >= 0).to_numpy()], [lambda v: v**2, lambda v: v])
# array([25.,  1.,  0.,  2., 10.])  -- works; result is a plain ndarray, not a Series

Confirmed directly: the fix only needs each condition converted via .to_numpy() — x is free to stay a Series throughout, since np.piecewise() runs np.asanyarray(x) on it internally with no trouble. Also confirmed directly: the return value is always a plain ndarray, even when x was a Series going in — the result must be re-wrapped with pd.Series(result, index=s.index) to get the original labels back, the same "Index disappears" shape Lesson 111 found for np.percentile().

4 · When a single bare condition is passed, the same "wrap in a list" logic is intentional

That promotion rule is not purely a bug — it is documented (if "undocumented" per the NumPy source's own comment) behavior for the genuinely common case of passing exactly one raw condition, not wrapped in a list at all. Confirmed directly: np.piecewise(x, x < 0, [lambda v: -1, 1]) — one bare boolean array, no outer list — works correctly, treated as a single condition needing the "+1 default function" form. The trap in Section 3 is specifically a list of Series being misidentified as if it were one bare condition, because Series fails the same list/ndarray type check a bare array would have passed.
