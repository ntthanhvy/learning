1 · Three questions, in the original teaching order

Answer each out loud or on paper before reading the fold-out answer. If one is shaky, note it and go fix it in the practice file below rather than only rereading the old lesson.

Day 112 — threading.Lock. Why does an unprotected shared counter updated by several threads end up lower than the expected total, and what does with lock: guarantee that a manual lock.acquire()/lock.release() pair does not, by default?

Fold-out answer: without a lock, two threads can both read the same old counter value before either writes its update back, so one thread's write overwrites the other's instead of building on it — confirmed live, the widened-gap demo lost most of its increments (8000 expected, 2003 actual). with lock: calls lock.acquire() on entry and lock.release() on exit guaranteed, even if an exception escapes the block — confirmed live, a ValueError raised inside still left lock.locked() reporting False right after. The manual spelling works the same way when nothing goes wrong, but a forgotten release() on an exception path leaves the lock stuck forever.

Day 113 — glob & fnmatch. Why does root.glob("*.csv") miss a matching file sitting inside a subdirectory of root, while root.rglob("*.csv") finds it — and what happens when Path.glob() is called with a pattern that matches nothing at all?

Fold-out answer: a plain * in a glob pattern never crosses a / boundary, so glob("*.csv") only looks inside the one directory it's called on. rglob("*.csv") is glob("**/*.csv") written out — ** is the one piece of glob syntax allowed to cross a / boundary, so rglob() walks into every subdirectory at every depth applying the same pattern. A pattern matching nothing returns an empty result, confirmed live — list(root.glob("*.xyz")) is [], never an exception, unlike Day 13's Path.read_text() on a missing file.

Day 114 — shlex. What does shlex.split() give you that a plain .split() call on spaces would not, and what is the relationship between shlex.join() and shlex.split()?

Fold-out answer: shlex.split() parses a string the way a POSIX shell would, so a quoted substring containing spaces stays together as one list element with the quote marks stripped away — confirmed live, shlex.split('cp "my file.txt" /tmp/backup --verbose') returned ['cp', 'my file.txt', '/tmp/backup', '--verbose'], not a naive 4-way split on every space. shlex.join(argv) is the exact inverse: it builds one shell-safe string from a list, quoting each element only where needed, such that shlex.split() on that string reproduces the original list exactly — confirmed live on the same cp/my file.txt//tmp/backup example.
