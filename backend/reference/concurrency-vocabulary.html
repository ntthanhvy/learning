Concurrency vocabulary & decision rules

The compressed version of Lesson 25. Four words, two questions, one decision rule. Designed to be printed and re-read, not read once.

The two questions the four words answer

QuestionThe two answersWhat it's a property of
How is the work arranged?concurrency — structured as independent interleaving pieces
parallelism — pieces literally executing at the same instant		your program's design (concurrency) / the hardware & runtime (parallelism)
Who switches between pieces?thread — the OS kernel does
coroutine — the language runtime does		the mechanism your concurrency is built on

Rob Pike's definitions (go.dev/blog/waza-talk): concurrency is "the composition of independently executing processes" — "dealing with lots of things at once." Parallelism is "the simultaneous execution of (possibly related) computations" — "doing lots of things at once."

The one-line test: a single-core machine can be concurrent but never parallel.

You write concurrency. The runtime and hardware grant parallelism. No concurrent structure → extra cores have nothing to pick up.

The same idea, per language

LanguageIts coroutineWhat to know
Gogoroutine — go f()Deliberately not called a coroutine or thread: it's preemptible and can block anywhere, with no async/await. Runtime spreads them across cores automatically; GOMAXPROCS defaults to available CPUs. One primitive covers I/O and CPU cases.
Pythonasync def coroutine, run by asyncioDefault CPython has the GIL: threads give concurrency but not parallelism for pure-Python computation. So asyncio for I/O, multiprocessing for CPU. Python 3.14's free-threaded build (python3.14t, PEP 779) removes the GIL but is opt-in.
Rustasync fn → a Future, run as a task by a runtime (tokio)Futures are inert until polled — nothing runs without a runtime driving it. Stackless: suspends only at .await points.
JavaScript / Nodeasync function, driven by the event loopOne thread runs your JS. CPU-bound work must leave it entirely — worker threads or a separate process.
Kotlin / JVMsuspend fun, launched in a coroutine scopeWhere the word "coroutine" is most used as the official name; JVM threads underneath.

The decision rule: what is the work waiting on?

I/O-boundCPU-bound
Spends its timewaiting — network, database, diskcomputing — burning cycles
Backend examplesquerying Postgres, calling a service, reading a file, idle connectionshashing a password, resizing an image, parsing huge JSON, compression
What you needconcurrencyparallelism
Reach forcoroutines / goroutines — thousands, on a handful of threadsthreads or processes — roughly one per core, no more
Ceilingmemory and file descriptorsphysical core count. Full stop.

The trap: concurrency does not speed up CPU-bound work. 100 coroutines on 4 cores = the same 4 cores, the same total work, plus scheduling overhead.

The incident: one long CPU-bound coroutine that never yields starves every other coroutine on its thread → all request latencies spike at once.

Glossary quick list

concurrencyStructuring a program as independent pieces that interleave. A design property.
parallelismPieces literally executing at the same instant. Needs >1 core.
OS threadKernel-scheduled execution stream with its own stack. The unit of real parallelism.
coroutineFunction that suspends and resumes, scheduled by a language runtime. Cheap.
preemptive schedulingThe scheduler interrupts a task at a time of its own choosing.
cooperative schedulingThe task yields control voluntarily, at defined points.
M:N schedulingM runtime tasks multiplexed onto N OS threads, M ≫ N.
context switchSaving one task's state and restoring another's. Cheap in user space, costlier in the kernel.
blocking callA call that doesn't return until its work finishes, holding whatever runs it.
I/O-boundTime dominated by waiting. Fixed by concurrency.
CPU-boundTime dominated by computing. Fixed only by parallelism, capped by cores.
GILCPython's lock allowing one thread to run Python bytecode at a time.
