idxmax(axis=1) / idxmin(axis=1): which COLUMN, not which row

Lesson 20's own "Primary source" footer named this directly as deferred — "covers axis=1 (finding which COLUMN holds the max per row, instead of which row), and how ties and all-NaN rows/columns are handled in that direction, neither covered in today's lesson." A fresh curriculum/glossary scan today re-confirmed it's still a genuine zero-hit gap 71 lessons later, and it is a real, distinct interview question: "for each student, which subject was their best?" needs the exact opposite axis from Lesson 20's "for each customer, which order was biggest?"

1 · Same method, flipped axis: now it answers "which column"

Lesson 20 covered idxmax()/idxmin() with the default axis=0: called on a single column, it returns the row label holding that column's max/min. Pass axis=1 (or the string "columns") and the whole question flips: now it's called on a DataFrame with several numeric columns, and for every row it returns the column name holding that row's max/min — the same method, pointed the other way:

scores = pd.DataFrame({
    "math": [90, 70, 60],
    "sci":  [80, 95, 60],
    "art":  [70, 60, 60],
}, index=["An", "Binh", "Chi"])

scores.idxmax(axis=1)
-- An      math
-- Binh     sci
-- Chi     math
-- dtype: str

Confirmed directly (pandas 3.0.6): the result's index is still the original row labels (An, Binh, Chi) — but the values are now column names ("math", "sci"), not row labels. An's best subject was math (90); Binh's was science (95). "For each student, which subject was their best?" is exactly the row-wise twin of Lesson 20's "for each customer, which order was biggest?" — same tool, transposed intent.

2 · Ties: first column wins, by position — same rule as Lesson 20's row ties

Chi's row is math=60, sci=60, art=60 — a flat three-way tie. Confirmed directly, scores.idxmax(axis=1)["Chi"] returns "math", the first column in column order, not the first alphabetically and not an arbitrary pick. This is the documented rule, matching Lesson 20's own row-wise tie behavior exactly: the official pandas docs for idxmax() state it returns the "index of first occurrence of maximum" — on axis=1 that means first by column position, left to right. Reordering the columns (without changing any values) would change which name wins the tie, which is easy to miss if the DataFrame's column order came from a dict literal or a prior .reindex() rather than something deliberately sorted.

3 · The real trap: an all-NaN row raises, but a partial-NaN row doesn't

Confirmed directly (pandas 3.0.6): with the default skipna=True, a row with some NaN values quietly skips them and returns the best name among what's left:

scores2 = scores.astype(float)
scores2.loc["Chi", "math"] = np.nan   # Chi: math=NaN, sci=60, art=60
scores2.idxmax(axis=1)
-- An      math
-- Binh     sci
-- Chi      sci    (NaN silently skipped; tie between sci/art broken by position again)
-- dtype: str

But a row that's entirely NaN has nothing left to skip to, and that's where the behavior sharpens into a real guard, not a silent gap: idxmax(axis=1) raises ValueError: Encountered all NA values rather than returning NaN or some placeholder. Passing skipna=False goes further still — confirmed directly, it raises that same ValueError the instant any NA is encountered in a row, even just one among otherwise-real values, rather than only on a fully-empty row. The three behaviors are easy to conflate: partial-NaN-with-default-skipna silently succeeds, partial-NaN-with-skipna=False raises, and all-NaN raises regardless of skipna. An interview-shaped version of this: running idxmax(axis=1) across a batch of rows where most are clean but one row came in fully empty from an upstream join — that one row crashes the whole call unless it's filtered or imputed first, rather than quietly producing a NaN that could be checked for later.

4 · Don't confuse this with NumPy's np.argmax(axis=1) — it returns a position, not a label

A genuinely common mix-up: NumPy's own np.argmax(arr, axis=1) looks like it should be the array-level version of the same idea, but it returns an integer position within each row, not a column label — and those two can silently disagree the moment a DataFrame's columns aren't already sitting at position 0, 1, 2... in label order:

np.argmax(scores.to_numpy(), axis=1)
-- array([0, 1, 0])   -- plain positions: 0, 1, 2 ... no column names at all
scores.idxmax(axis=1)
-- An      math
-- Binh     sci
-- Chi     math        -- same winners here, but only because columns are still in original order

On this particular DataFrame the two happen to agree once translated back (position 0 is "math"), but np.argmax() has no concept of column names at all — it works on the raw NumPy array underneath, after .to_numpy() has already thrown the labels away. Reorder or drop a column and the position-to-name mapping silently shifts while idxmax(axis=1) keeps tracking the real label through any reordering. The safe rule: reach for np.argmax/np.argmin only when a plain array position is genuinely what's wanted (e.g. inside a NumPy-only numeric routine); reach for pandas' idxmax(axis=1)/idxmin(axis=1) any time the answer needs to be a real column name that survives column reordering.

Q: "How would you find, for each row, which column holds the highest value — and what should I watch out for?" A strong answer, out loud: "idxmax(axis=1) — same method as the row-wise case, just with the axis flipped, so instead of returning which row has the max per column, it returns which column has the max per row, as a Series keyed by the original row labels. Two things to watch for: ties resolve to the first column by position, left to right, not alphabetically — so column order matters even when no value changed. And NaN handling has three distinct outcomes, not one: a row with some NaNs just skips them under the default skipna=True; the same partial-NaN row raises a ValueError if I pass skipna=False; and a row that's entirely NaN raises that same ValueError no matter what skipna is set to, since there's nothing left to compare. I'd also never reach for np.argmax(axis=1) here instead — that returns a raw position in the underlying array, not a column name, and it'll silently point at the wrong column the moment the DataFrame's columns get reordered." The signal: naming all three NaN outcomes distinctly, not just "it handles missing values," and flagging the np.argmax position-vs-label trap unprompted.
