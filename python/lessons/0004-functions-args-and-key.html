Functions that pull their weight

Day 3 ended with Counter(row["city"] for row in sales) giving you counts per city — but a raw dict of counts doesn't come out in an order that's useful to read. Today's job is the missing piece: how to tell sorted(), min(), and max() what to sort by when "by the value itself" isn't the right rule — using a small anonymous function called a lambda, plus enough of how Python functions accept arguments to understand why that works.

Bridge from SQL: ORDER BY count DESC tells the database to sort rows by a column, not by whatever the row itself looks like. Python's sorted(..., key=...) is the same idea in code: key names a function that computes the sort column from each item, on the fly.

1 · A function is a value, not just a name to call

You've called functions since Day 1 — len(x), list(x), row.setdefault(...). A function is defined with def, a name, parentheses for its inputs, and a body that optionally returns a value:

def discount(price, rate):
    return price * (1 - rate)

discount(100, 0.2)     # 80.0

The part that matters today: discount itself is an object, exactly like the ints and lists from Day 1 — it has a name bound to it, and that name can be passed around, stored in a variable, or handed to another function as an argument, without the parentheses that would call it:

my_func = discount        # binds a second name to the SAME function object — no call, no ()
my_func(100, 0.2)      # 80.0 — calling through either name works identically

That single fact — a function is a value you can pass to another function — is the whole mechanism behind today's lesson. sorted() doesn't just sort things; it accepts a function as an argument and calls it for you, once per item, to decide the order.

2 · Arguments: positional, keyword, and default

discount(100, 0.2) matched 100 to price and 0.2 to rate purely by position — a positional argument. You can instead name which parameter each value goes to, in any order, with a keyword argument:

discount(price=100, rate=0.2)   # 80.0 — same call, named, order doesn't matter
discount(rate=0.2, price=100)   # 80.0 — still correct, arguments matched by name

A parameter can also declare a default argument — a value used automatically when the caller doesn't supply one:

def discount(price, rate=0.1):    # rate defaults to 0.1 if the caller omits it
    return price * (1 - rate)

discount(100)          # 90.0 — uses the default rate
discount(100, 0.5)     # 50.0 — caller's rate overrides the default

One trap worth flagging now, since Day 1 already built the vocabulary for it: Python evaluates a default value once, when def runs — so def add_item(item, bucket=[]) would hand every call the same list object, accumulating across unrelated calls instead of starting fresh. That's why a mutable default like [] or {} is a trap; the fix, when you need one, is a default of None and building the fresh mutable object inside the body.

Two signatures you'll recognize in other people's code from here on, at a recognition level only — mastering them isn't today's job: def f(*args) collects any number of extra positional arguments into a tuple named args, and def f(**kwargs) collects extra keyword arguments into a dict named kwargs. You'll see both spellings constantly in library code (including sorted's own documentation); knowing the names is enough for now.

3 · lambda: a function small enough to write inline

Writing a whole def block just to say "square this number" is a lot of ceremony for a one-line idea. A lambda is exactly that: an anonymous, throwaway function limited to one expression, whose result is returned automatically:

square = lambda n: n * n
square(5)              # 25 — same call syntax as any function

# equivalent def, spelled the long way:
def square(n):
    return n * n

Read lambda n: n * n as "a function of one parameter, n, whose value is n * n" — no def, no name required, no return. A lambda can take several parameters the same way a def can (lambda a, b: a + b), but it can never hold a loop, an if statement, or more than one expression — anything bigger belongs in a real def. In practice a lambda is almost never assigned a name like square above; its whole point is showing up inline, unnamed, exactly where a function is expected as an argument — which is precisely what section 4 needs it for.

4 · key=: telling sorted(), min(), and max() what to compare

Plain sorted() compares items directly — fine for numbers, and fine for strings (alphabetically). It breaks down the moment you need to sort by something about each item rather than the item itself: sorting the Day 3 sales rows by amount doesn't work by comparing whole dicts. This is what the key= argument is for — a function, called once per item, whose return value is what actually gets compared:

sales = [
    {"city": "Hanoi", "amount": 120},
    {"city": "HCMC",  "amount": 80},
    {"city": "Danang", "amount": 200},
]

sorted(sales, key=lambda row: row["amount"])
# [{'city': 'HCMC', 'amount': 80}, {'city': 'Hanoi', 'amount': 120}, {'city': 'Danang', 'amount': 200}]

sorted(sales, key=lambda row: row["amount"], reverse=True)
# biggest amount first — reverse is a keyword argument with default False

max(sales, key=lambda row: row["amount"])   # {'city': 'Danang', 'amount': 200}
min(sales, key=lambda row: row["amount"])   # {'city': 'HCMC', 'amount': 80}

Read key=lambda row: row["amount"] as "for each row, use row["amount"] as its sort value" — sorted calls that function on every item once, then orders items by the results, without you ever writing the comparison logic by hand. reverse=True is a keyword argument in the exact sense section 2 defined: named, with a default (False) used when you leave it out.

This is where Day 3's grouping and today's sorting meet. A Counter (or any dict) doesn't come out of the box in count order — its .items() gives (key, value) pairs in insertion order, not sorted:

from collections import Counter

city_counts = Counter(["Hanoi", "HCMC", "Hanoi", "Hanoi", "HCMC"])
# Counter({'Hanoi': 3, 'HCMC': 2})  — already looks sorted here, but that's not guaranteed

sorted(city_counts.items(), key=lambda pair: pair[1], reverse=True)
# [('Hanoi', 3), ('HCMC', 2)] — a list of (city, count) tuples, most-counted first

Each pair here is a (city, count) tuple from .items(); pair[1] reaches the count, the second slot. sorted() always returns a fresh list, even when sorting a dict's items or a set — worth knowing so the result's type isn't a surprise. This exact shape — sort a grouped or counted result by size — is the single most common reason a data script reaches for key= at all.

Where pandas goes from here: Counter(...).most_common() and today's sorted(..., key=...) both do by hand what df.sort_values("amount", ascending=False) does in one call once data/ introduces DataFrames. Same idea — order by a computed value, not the row itself — different spelling for a different container. Not covered here; that's data/'s job, and this is the only sentence in this lesson that mentions it.
