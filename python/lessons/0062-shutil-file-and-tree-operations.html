1 · The problem: open() only handles one file's bytes, not the file itself

Days 6 and 13 can read a file's contents, write new contents, and check whether a path exists — but none of that touches the file as a filesystem entry. Copying a file the "manual" way means opening the source for reading, opening the destination for writing, and copying every byte across by hand:

from pathlib import Path

src = Path("report.csv")
dst = Path("backup/report.csv")
with open(src, "rb") as fsrc, open(dst, "wb") as fdst:
    fdst.write(fsrc.read())   # works for one file, but copies no metadata (permissions, timestamps)

This works for a single small file, but it copies only bytes — no file permissions, no modified-time metadata — and it has no answer at all for "copy this entire directory, with everything inside it, to a new location." shutil ("shell utilities") is the standard library's answer: one function call per whole-file or whole-tree operation.

2 · Copying a file: shutil.copy() vs shutil.copy2()

import shutil

shutil.copy("report.csv", "backup/report.csv")    # copies content + permission bits
shutil.copy2("report.csv", "backup/report.csv")   # copy() plus modified-time and other metadata

Both accept either plain strings or Path objects (Day 13) interchangeably, and both also accept a destination directory instead of a full filename — shutil.copy("report.csv", "backup/") figures out the filename from the source automatically. copy2() is the one to reach for when preserving "when was this last touched" matters, such as a cache or a de-duplication check like Day 59's content hashing; plain copy() is enough when only the content matters.

3 · Whole directory trees: copytree(), move(), rmtree()

The bigger gap open() and pathlib alone never close is operating on an entire directory at once — every file and subdirectory inside it, recursively:

import shutil

shutil.copytree("data/raw", "data/raw_backup")   # recursively copies everything inside; destination must NOT already exist
shutil.move("data/processed", "archive/processed")  # moves a file OR a whole directory; works across filesystems too
shutil.rmtree("data/scratch")                    # deletes a directory and everything inside it -- no confirmation, no undo

copytree()'s destination-must-not-exist rule is deliberate, not a limitation to work around by pre-deleting the target — it exists so a typo in the destination path can never silently merge into and corrupt an existing directory. Pass dirs_exist_ok=True only when merging into an existing directory is genuinely the intent. move() is the general-purpose one: unlike os.rename(), it also handles moving across different disks/filesystems by copying then deleting the source when a plain rename isn't possible at the OS level, and it works identically whether the source is a single file or a whole tree.

rmtree() has no undo: it deletes immediately and permanently — no recycle bin, no confirmation prompt. The same discipline Day 8's exceptions lesson applied to except clauses applies here even harder: never call rmtree() on a path built from unvalidated input (a config value, a CLI argument, string concatenation gone wrong) without first confirming, ideally with Path.resolve() and an explicit check, that the resolved path is actually inside the directory intended to be cleaned.

4 · One more use: shutil.disk_usage()

Before writing a large output file or unpacking a big archive, checking that there's actually room avoids a pipeline failing halfway through:

import shutil

usage = shutil.disk_usage(".")
usage.total, usage.used, usage.free   # all in bytes -- a namedtuple (Day 53), so also usable as usage[0], usage[1], usage[2]

disk_usage() returns a namedtuple — exactly the lightweight-record shape Day 53 taught — so usage.free reads clearly instead of an unlabeled index into a plain tuple.

Where pandas goes from here: nothing pandas-specific today — DataFrame.to_csv()/read_csv() read and write file contents, but neither pandas nor any DataFrame method copies, moves, or deletes a file or directory as a filesystem entry; that stays shutil's job (or pathlib's, for a single file) in any pandas pipeline too.
