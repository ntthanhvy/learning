string.Template: substitution without evaluation

Day 46 taught the f-string format spec — but an f-string's {...} part is a real Python expression, evaluated by the interpreter. That's fine when the programmer writes the template string in the source file. It stops being fine the moment the template itself comes from somewhere else — a config file, a database row, a user-editable email template — because an f-string-shaped string built from untrusted text and fed back through eval() or .format_map() on attacker-controlled data can run arbitrary expressions. The standard-library string.Template class is the tool for exactly that case: placeholders only, never code.

1 · $name placeholders, filled by plain lookup

Template(text) wraps a string containing $identifier or ${identifier} placeholders. .substitute(**values) (or a single mapping) fills them in by looking each name up — nothing after the $ is ever evaluated as code, it is only ever matched against the keys given:

from string import Template

t = Template("Hello $name, your balance is $$${amount}.")
print(t.substitute(name="Alice", amount="42.00"))
# 'Hello Alice, your balance is $42.00.' -- confirmed live
# note the doubled $$ above: that's how a literal dollar sign is escaped

The braces form, ${name}, exists only to mark where the identifier ends when it would otherwise run into the next character — ${name}suffix substitutes correctly and reads back as "xsuffix" for name="x", whereas $namesuffix would be parsed as one long (and missing) identifier namesuffix.

2 · Missing a key is loud by default — unless you ask it not to be

.substitute() raises KeyError the moment a placeholder has no matching value, the same fail-loud behavior Day 8 taught for exceptions in general. .safe_substitute() is the deliberate escape hatch: any placeholder it can't fill is left in the output untouched instead of raising:

t = Template("Hello $name, your balance is $$${amount}.")
try:
    t.substitute(name="Bob")  # no 'amount' given
except KeyError as e:
    print("KeyError:", e)          # KeyError: 'amount' -- confirmed live

print(t.safe_substitute(name="Carol"))
# 'Hello Carol, your balance is $${amount}.' -- confirmed live, nothing raised

Reach for safe_substitute() only when a half-filled result is genuinely useful (a preview, a draft) — reaching for it just to silence an error hides a real bug the same way a bare except: pass would.

3 · Why this exists when f-strings already do substitution

An f-string's {...} is a Python expression slot, evaluated by the interpreter at the point the f-string appears in source code — that's exactly what makes it powerful (any expression, any name in scope) and exactly why it must never be built dynamically from text that didn't come from a trusted developer. Template solves a narrower problem on purpose: its $name syntax has no expression grammar at all, so substituting into attacker- or user-supplied template text is safe in a way an f-string built the same way never is:

from string import Template

# this text could have come from a config file or a database row
untrusted_template_text = "User said: $msg"
t3 = Template(untrusted_template_text)
print(t3.substitute(msg="just a string value, no code runs here"))
# 'User said: just a string value, no code runs here' -- confirmed live,
# there is no way to smuggle a function call or attribute lookup through $msg

t.get_identifiers() (confirmed live, Python 3.11+) lists every placeholder name a template expects — ['name', 'amount'] for the balance template above — and t.is_valid() reports whether the template's $ syntax parses at all, without needing any values yet. Both are useful for validating a template that was itself loaded from outside the program before ever trying to fill it in.

Where pandas/NumPy go from here: nowhere directly — this is plain string substitution, a layer below either library. A realistic shape is a Template-based email or report body filled in per row of a pandas DataFrame during a data/-course pipeline, but that row-iteration half is data/'s job and isn't shown here.
