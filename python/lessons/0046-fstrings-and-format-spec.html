f-strings and the format spec mini-language

f-strings have appeared in nearly every lesson since Day 1 — Day 15's logging lesson, Day 21's SQL-injection demo, Day 30's __repr__ — always as plain f"{name}" interpolation, never stopping to teach the part after the colon. Today closes that thread: the format spec that turns a bare value into an aligned, rounded, or padded one, plus the debug-only !r/= conversions.

Bridge from SQL: this is the Python-side equivalent of ROUND(price, 2), LPAD(), or TO_CHAR(n, '999,999.99') — formatting a value for display without changing the underlying number. SQL leaves formatting to the client or a dialect-specific function; Python puts it directly in the string literal, right where the value is interpolated.

1 · The placeholder has two independent parts

Every {...} inside an f-string is {expression}, optionally followed by {expression:spec}. The part before the colon is any Python expression — a name, a call, an attribute lookup. The part after the colon is the format spec, a small separate mini-language that never runs Python code; it only describes how to render whatever the expression already produced.

price = 1234.5
print(f"{price}")        # 1234.5 -- no spec, just str()
print(f"{price:.2f}")    # 1234.50 -- .2f = fixed-point, 2 digits after the dot
print(f"{price:,.2f}")   # 1,234.50 -- comma groups thousands, still 2 decimals

Verified live: price itself is untouched by any of these — it's still the float 1234.5 after all three lines. The spec only changes what gets rendered into the string, exactly the way ROUND() in a SELECT doesn't change the stored row.

2 · Width, alignment, and fill — building a table without pandas

A number or a minimum field width before the type letter pads the rendered value; <, >, and ^ force left/right/center alignment, and any single character placed right before them becomes the fill character instead of a space:

rows = [("Hanoi", 1200), ("HCMC", 980)]
for city, total in rows:
    print(f"{city:<10}{total:>6,}")
# Hanoi      1,200
# HCMC         980

{city:<10} left-aligns the string in a 10-character field; {total:>6,} right-aligns the number in a 6-character field with a thousands separator. Strings default to left-aligned, numbers default to right-aligned — writing </> explicitly is only needed to override that default or to pick a non-space fill, e.g. {city:-<10} pads with dashes instead of spaces.

3 · !r and = — the two debug-only conversions

A ! right before the colon (or with no colon at all) picks which built-in function converts the value to a string, before any spec is applied. !r is the one worth knowing cold: it calls repr() instead of the default str(), which is exactly the distinction Day 30's __repr__ lesson relied on without spelling out the !r syntax itself:

name = "Hà Nội"
print(f"{name}")     # Hà Nội       -- str(): human-facing
print(f"{name!r}")   # 'Hà Nội'     -- repr(): quotes shown, unambiguous for logs/debugging
print(f"{name=}")    # name='Hà Nội' -- the = specifier: prints "expr=" then repr() of its value

The trailing = (no space before it) is a debug-only shortcut added in Python 3.8: it expands to the literal source text of the expression, an =, and then that expression's value — by default formatted with repr(), same as !r. It exists specifically so a quick print(f"{name=}") during debugging shows both the variable's name and its value without typing either twice.

Gotcha, confirmed live: !r and a numeric spec don't mix. f"{price!r:.2f}" raises TypeError: unsupported format string passed to str.__format__ — once a value has been converted with !r (or !s/!a), what's left is already a plain string, and a numeric spec like .2f only applies to __format__ on the original object, not to a string. Use one or the other on a given value, not both.
Where pandas goes from here: nothing pandas-specific — df.style.format() and pd.options.display.float_format solve the same "how should this render" problem for a whole DataFrame at once, using this exact same format-spec syntax underneath for individual cells. Not demonstrated; this is the only sentence in this lesson that names pandas.

Q: "How would you print a number with two decimal places and a thousands separator?" A strong answer, out loud: "An f-string with a format spec after the colon — f'{value:,.2f}'. The comma adds thousands separators, the .2f means fixed-point with two digits after the decimal. It only affects how the string renders; the original number is untouched. If I also needed to left- or right-align it in a fixed-width column, I'd add an alignment character and a width before that, like f'{value:>10,.2f}'." The signal: knowing the spec is a small, composable mini-language — fill/align, then sign, then width, then grouping, then precision, then type — not a set of one-off tricks.
