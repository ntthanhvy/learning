np.vstack() / np.hstack() / np.column_stack(): the array layer under pd.concat()

Lesson 99 closed with two standing candidates and no promotion: itertuples() and the NumPy stacking family. A fresh scan confirmed both still had zero hits, plus a dozen other zero-hit names already tried in prior rounds. The stacking family won: Lesson 21 taught pd.concat() as the row/column stacker for DataFrames and mapped it to SQL's UNION ALL — but the raw-array layer underneath it, the one that actually decides what "stack" means when there's no DataFrame or Index to align by, was never itself covered. A clean, well-scoped gap, and a good one for round 100: it closes the loop back to Lesson 21's own tool.

1 · Two functions, two different answers to "stack these 1-D arrays"

Confirmed directly (numpy 2.5.4): np.vstack() / np.hstack() / np.column_stack() look like a matched trio, but vstack and hstack behave very differently on the exact same 1-D inputs:

import numpy as np
a = np.array([1, 2, 3])
b = np.array([4, 5, 6])

np.vstack([a, b])
# array([[1, 2, 3],
#        [4, 5, 6]])    -- 2-D now! each 1-D array became one ROW

np.hstack([a, b])
# array([1, 2, 3, 4, 5, 6])    -- still 1-D! just concatenated end to end

np.column_stack([a, b])
# array([[1, 4],
#        [2, 5],
#        [3, 6]])    -- 2-D, but each array became a COLUMN, not a row

Confirmed directly: on two plain 1-D arrays, vstack always produces a 2-D result (one row per input), hstack stays 1-D (a longer flat array), and column_stack produces a 2-D result shaped the opposite way from vstack — columns, not rows. This is the single most common mistake with this trio: reaching for hstack expecting a matrix and getting a flat array back instead.

2 · On 2-D arrays, both reduce to a named axis of concatenate()

The confusion mostly disappears once the inputs are already 2-D — confirmed directly, vstack and hstack become exact, literal spellings of np.concatenate() with a fixed axis:

A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])

np.vstack([A, B])                    # same result as:
np.concatenate([A, B], axis=0)   # -- stack downward, more rows

np.hstack([A, B])                    # same result as:
np.concatenate([A, B], axis=1)   # -- stack sideways, more columns

Confirmed directly with np.array_equal(): both equivalences hold exactly. vstack/hstack are not separate machinery — they are concatenate() with the axis pre-chosen and, for 1-D inputs only, an implicit reshape to 2-D first (that implicit reshape is exactly why vstack on 1-D arrays surprised Section 1 by returning a matrix). This mirrors Lesson 21's pd.concat(axis=0) vs axis=1 almost exactly — same two directions, same idea, one level lower, no Index to align by.

3 · Where concatenate() actually errors — and where pd.concat() wouldn't

Confirmed directly: every function in this family demands matching shape on every axis except the one being stacked along, and raises ValueError naming the exact dimension and the two conflicting sizes — no silent fix-up:

np.vstack([a, np.array([1, 2])])
# ValueError: all the input array dimensions except for the concatenation
# axis must match exactly, but along dimension 1, the array at index 0
# has size 3 and the array at index 1 has size 2

This is the sharpest contrast with Lesson 21's pd.concat(), confirmed directly against that lesson's own example: stacking two DataFrames with mismatched columns silently NaN-fills the gap and returns a result — pd.concat() never raises over a shape mismatch. The raw NumPy layer has no column names to reconcile by, no NaN-filling machinery, and no opinion about what should happen when shapes don't line up — it just refuses. Reach for pd.concat() when inputs might legitimately have different columns; reach for this family only once shapes are already known to agree, typically deep inside a numeric pipeline with no DataFrame in sight.

One more confirmed trap, silent rather than loud: dtype promotion follows the same rule as any mixed-type array. Stacking an int array with a float array upcasts the whole result to float64; stacking an int array with a string array upcasts everything to a Unicode string dtype (<U21) — numbers included, now unusable for arithmetic without converting back. No warning either way.

Q: "You have a list of several same-length 1-D NumPy arrays, one per sensor reading, and need them as rows of one matrix for a model. What's the risk of just reaching for hstack?" A strong answer, out loud: "hstack on 1-D arrays concatenates them into one long flat array, not a matrix — it stays 1-D. vstack is the one that treats each array as a row and actually produces the 2-D shape I want, one row per sensor. If I'd wanted them as columns instead, that's column_stack, not hstack. I'd also check all the arrays are the same length first, since any mismatch raises ValueError immediately rather than silently padding or dropping anything, unlike pd.concat() on DataFrames with different columns." The signal: naming the 1-D surprise unprompted, not just knowing the three function names exist.
