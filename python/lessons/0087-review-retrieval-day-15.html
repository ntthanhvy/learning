1 · Three questions, in the original teaching order

Answer each out loud or on paper before reading the fold-out answer. If one is shaky, note it and go fix it in the practice file below rather than only rereading the old lesson.

Day 84 — traceback. What does traceback.format_exc() give you that a plain str(e) inside an except block does not, and what happens if format_exc() is called with no exception actually in flight?

Fold-out answer: str(e) only gives the exception's own message — it says nothing about where in the call chain the failure happened. traceback.format_exc() returns the full report (type, message, and the entire active call chain) as one ordinary string, the same text Python would print on an uncaught exception, just captured as data instead of lost once the except block moves on. Called with no exception active, it does not raise an error to flag the mistake — it quietly returns the misleading short text "NoneType: None" instead, confirmed live. It belongs inside an active except block, never outside one.

Day 85 — warnings. What is the key behavioral difference between warnings.warn() and raise, and why reach for warn() instead of logging.warning() when flagging a deprecated argument?

Fold-out answer: raise stops the function immediately and propagates up the call stack until something catches it. warnings.warn() prints a notice and then execution continues normally on the very next line — the function still runs to completion and still returns its value, confirmed live. warn() beats logging.warning() for a deprecation notice because it is built to be programmatically acted on: a caller can filter it, collect it in a test via catch_warnings(record=True), or escalate it into a real exception via filterwarnings("error", ...) — none of which a plain logged line supports.

Day 86 — inspect. What does inspect.signature(greet) actually do to greet, and why does a parameter with no declared default report inspect.Parameter.empty instead of None?

Fold-out answer: inspect.signature(greet) reads greet's own stored parameter metadata straight off the function object and returns it as a Signature object — it never calls greet, and the function's body never runs. That is exactly why a framework (FastAPI's Depends() included) can inspect a route function safely before any real request arrives. A no-default parameter reports Parameter.empty, not None, because None is itself already one valid, real default a parameter could have — a separate sentinel is required so "no default at all" can be told apart from "the default really is None."
