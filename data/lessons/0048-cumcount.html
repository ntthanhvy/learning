cumcount(): a running position within each group

Lesson 47's own closing teaser named this directly: cumcount(), used inline back in Lesson 28 to number each customer's visits ("clean.groupby("customer").cumcount() + 1") with no standalone explanation and no glossary entry of its own. Today it gets the proper treatment — what it actually counts, and the two methods it's most often confused with.

Recap, in one line

Lesson 7's rank() orders rows within a group by value — biggest amount first, or smallest, your choice. cumcount() ignores value entirely: it just counts off rows within each group in whatever order they currently are, 0, 1, 2, 3… — a running position, not a ranking.

1 · cumcount(): 0-indexed row position within each group

Same clean 4-row orders_raw.csv slice Lessons 6-47 have used, sorted by customer then order date:

clean
--   order_id customer  amount order_date
-- 0        1       An   120.0 2026-01-05  (Monday)
-- 1        6       An    42.0 2026-01-10  (Saturday)
-- 2        2     Binh    35.5 2026-01-06  (Tuesday)
-- 3        5     Binh   180.0 2026-01-09  (Friday)

cumcount() chained after groupby() (Lesson 4) gives each row its running position, starting at 0, within its own group:

clean.groupby("customer").cumcount()
-- 0    0   -- An's 1st row
-- 1    1   -- An's 2nd row
-- 2    0   -- Binh's 1st row
-- 3    1   -- Binh's 2nd row
-- dtype: int64

An restarts at 0, Binh restarts at 0 — the count is per-group, same split-apply-combine shape every groupby() chain in this course has used. In practice the human-friendly, 1-indexed version is more common, exactly Lesson 28's line:

clean["visit_num"] = clean.groupby("customer").cumcount() + 1
-- An's two rows: visit_num 1, 2
-- Binh's two rows: visit_num 1, 2

cumcount() takes no column argument at all — unlike cumsum() or rank(), which act on a named column's values, cumcount() only cares which group a row belongs to and where it sits in the current row order. It exists only on a GroupBy object: calling it on a plain Series or DataFrame (no groupby() first) raises AttributeError — confirmed directly, there is no ungrouped "running position" concept for it to count against.

2 · cumcount() vs rank(): position vs value

Lesson 7's rank() and today's cumcount() both produce one number per row, per group — easy to conflate, but they answer different questions. rank() orders by a column's value; cumcount() orders by row position, ignoring value completely:

clean["amount_rank"] = clean.groupby("customer")["amount"].rank(method="first")
clean["visit_num"]  = clean.groupby("customer").cumcount() + 1
--   customer  amount  amount_rank  visit_num
-- 0       An   120.0          2.0          1   -- An's 1st VISIT, but 2nd by AMOUNT (42 < 120)
-- 1       An    42.0          1.0          2   -- An's 2nd visit, but the CHEAPER order
-- 2     Binh    35.5          1.0          1
-- 3     Binh   180.0          2.0          2

An's row order (by date) and amount order disagree: the 120.0 order happened first chronologically (visit_num 1) but ranks 2nd by size (amount_rank 2.0, since 42.0 is smaller). cumcount() would give the identical 0, 1, 0, 1 no matter what the amount column contained, or even if there were no numeric column at all — it only ever looks at position. The SQL bridge: cumcount() is ROW_NUMBER() OVER (PARTITION BY customer ORDER BY <current row order>) - 1 — a ROW_NUMBER(), not a RANK(), and 0-indexed rather than SQL's 1-indexed default.

3 · cumcount() vs nunique(): per-row position vs per-group distinct count

Lesson 19's nunique() is the other easy mix-up — both are "count"-flavored and both chain after groupby(), but one returns a value per row and the other collapses to one value per group. A small inline table makes the gap concrete (An placed 3 orders, two of them for the identical amount — not present in the shared fixture, so built inline the same way Lesson 19's tagged-orders example was):

demo = pd.DataFrame({
    "customer": ["An", "An", "An", "Binh"],
    "amount":   [50.0, 50.0, 75.0, 30.0],
})
demo["visit_num"] = demo.groupby("customer").cumcount() + 1   # per-ROW
demo.groupby("customer")["amount"].nunique()                          # per-GROUP
--   customer  amount  visit_num
-- 0       An    50.0          1
-- 1       An    50.0          2
-- 2       An    75.0          3
-- 3     Binh    30.0          1
--
-- customer
-- An      2   -- only 2 DISTINCT amounts among An's 3 rows (the two 50.0s collapse)
-- Binh    1

An's cumcount() correctly climbs to 3 — three real rows, three real visits, duplicate amount or not. An's nunique() says 2 — it never asked "how many rows," it asked "how many different values," and the repeated 50.0 only counts once. One row exists for every visit regardless of duplication; nunique() actively throws duplication away. Confusing the two would misreport "how many times has this customer ordered" as "how many different amounts has this customer paid" — a real interview gotcha, not a pedantic distinction.

4 · ascending=False: counting down instead of up

cumcount(ascending=False) flips the direction — instead of "how many rows came before this one," it answers "how many rows come after this one," in the same group, same current order:

clean.groupby("customer").cumcount(ascending=False)
-- 0    1   -- An's 1st row: 1 more An row still to come
-- 1    0   -- An's 2nd row: 0 more An rows after it (last one)
-- 2    1   -- Binh's 1st row
-- 3    0   -- Binh's 2nd row (last one)

The last row of each group is always 0 under ascending=False — a quick way to flag "is this the final row in its group" (== 0) without a separate groupby().tail(1) lookup.

A named idiom: top N per group via sort + cumcount(). Lesson 7 solved "top N per group" with rank() <= N. sort_values() then cumcount() reaches the identical rows a second way — sort each group into the order you want first, then keep the rows whose running position is below the cutoff: 
by_amount_desc = clean.sort_values(["customer", "amount"], ascending=[True, False])
by_amount_desc["rank_by_amount"] = by_amount_desc.groupby("customer").cumcount()
top2 = by_amount_desc[by_amount_desc["rank_by_amount"] < 2]  # keep positions 0 and 1 -- the top 2
This is exactly Lesson 7's sort_values().groupby().head(N) alternative, just spelled with an explicit position column kept as data instead of discarded — reach for this variant when the position number itself is useful downstream (e.g. showing "your #1 and #2 orders"), and .groupby().head(N) when only the rows matter.

Q: "How would you number each customer's orders in the order they were placed, and how is that different from ranking them by amount?" A strong answer, out loud: "I'd groupby customer and use cumcount() — it gives each row a 0-indexed running position within its group, based purely on current row order, so I'd add 1 for a human-friendly 'visit number.' That's different from rank(): rank() orders by a column's VALUE, so the biggest or smallest amount gets rank 1 regardless of when it happened, where cumcount() only cares about row position and never looks at amount at all — a customer's first visit chronologically could easily be their most expensive or least expensive order, cumcount() and amount_rank can disagree completely. It's also not nunique(): cumcount() gives one number per ROW, growing with every row in the group even if values repeat; nunique() collapses to one number per GROUP, counting only distinct values. The SQL bridge for cumcount() itself is ROW_NUMBER() OVER (PARTITION BY customer ORDER BY ) - 1 — a ROW_NUMBER(), 0-indexed instead of SQL's default 1-indexed." The signal: distinguishing position-based from value-based numbering unprompted, and correctly placing cumcount() as a ROW_NUMBER() cousin, not a RANK() cousin.

5 · The SQL bridge

cumcount()'s direct SQL equivalent is ROW_NUMBER() OVER (PARTITION BY customer ORDER BY <current row order>) - 1 — the - 1 only because SQL's ROW_NUMBER() starts at 1 and pandas' cumcount() starts at 0 (the + 1 pattern from Section 1 exists purely to bridge that gap back). Note the parallel to Lesson 7's tie-breaking distinction: cumcount() is always the "first"/ROW_NUMBER() flavor — position-based, never ties, never repeats a number within a group — there is no RANK()/DENSE_RANK() equivalent of cumcount(), because it was never ordering by value to begin with.
