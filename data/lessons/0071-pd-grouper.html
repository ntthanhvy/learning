pd.Grouper(): grouping by a date frequency, not just a column's values

Chào bạn — Lesson 70's teaser named no single dangling candidate, so this round is a fresh curriculum/glossary scan. Lesson 4 taught groupby() by an existing column's own values, and Lesson 38 taught resample() for fixed time buckets off a DatetimeIndex — but neither one covers "monthly revenue, per customer," the single most common real-world report shape, because that needs a date-frequency bucket AND a category column grouped together in the SAME call. A fresh grep of all 70 lessons and the glossary confirms pd.Grouper is still genuinely zero-hit — it is exactly that missing piece.

1 · The gap: resample() has no room for a second grouping column

Lesson 38's resample() buckets a DatetimeIndex into fixed periods, gaps included — but it only groups by time. Asking "revenue per day, per customer" needs a second key, and resample() takes none:

indexed = clean.set_index("order_date")
indexed.groupby("customer").resample("D")["amount"].sum()
# works, but requires set_index() first, and chains two separate group
# operations together rather than expressing "group by these two keys
# at once" -- awkward, and the two-step chain has its own MultiIndex
# quirks resample() alone doesn't have

That chain technically works, but it is not what groupby()'s own multi-key syntax looks like everywhere else in this course (groupby(["customer", "region"]), Lesson 4) — and it still demands set_index() first, the same setup resample() always required.

2 · pd.Grouper(key=, freq=): a date frequency as an ordinary groupby key

pd.Grouper(key=..., freq=...) turns a date-frequency bucket into an ordinary groupby key — it can sit directly inside a normal groupby([...]) list, right alongside a plain column name, with no set_index() required first. Confirmed directly (pandas 3.0.5), on this course's cleaned orders_raw.csv fixture (An 120.0/01-05, An 42.0/01-10, Binh 35.5/01-06, Binh 180.0/01-09):

clean.groupby(["customer", pd.Grouper(key="order_date", freq="D")])["amount"].sum()
# customer  order_date
# An        2026-01-05    120.0
#           2026-01-10     42.0
# Binh      2026-01-06     35.5
#           2026-01-09    180.0

Confirmed directly: order_date is still a plain column, untouched by set_index() — pd.Grouper(key="order_date", freq="D") reads it directly off the DataFrame and buckets it by the given frequency, exactly one key among the list passed to groupby(). If the date column is already the index instead, use level= in place of key= — pd.Grouper(level="order_date", freq="D") — confirmed directly that passing key= to a Grouper when that same name is already the index raises KeyError: 'The grouper name order_date is not found', because key= looks for a column, not an index level.

SQL bridge: the closest SQL shape is GROUP BY customer, DATE_TRUNC('day', order_date) — bucketing one column by its own values, and a timestamp column by a truncated time unit, in the same GROUP BY clause. pd.Grouper(freq=...) is pandas' spelling of that DATE_TRUNC-style time bucket, sitting in the same key list as any other column, the same multi-key groupby([...]) syntax Lesson 4 already covered.

3 · The gap-filling nuance: it depends on whether Grouper is alone or combined

Confirmed directly, and the sharpest interview point in this lesson: a SOLO pd.Grouper — the only key in the call — fills empty calendar periods with 0/NaN, exactly like resample():

clean.groupby(pd.Grouper(key="order_date", freq="D"))["amount"].sum()
# order_date
# 2026-01-05    120.0
# 2026-01-06     35.5
# 2026-01-07      0.0   -- no orders that day, but the day still appears
# 2026-01-08      0.0   -- same
# 2026-01-09    180.0
# 2026-01-10     42.0

But COMBINED with another groupby key, that gap-filling disappears — confirmed directly, the ["customer", pd.Grouper(...)] result from Section 2 has exactly 4 rows, one per real (customer, day) combination that actually occurred, with no zero-filled row for a day a given customer didn't order. Grouping by customer first partitions the data into per-customer groups before the date frequency ever applies, so there is no whole-calendar range left to fill gaps against — each customer's own date range is sparse on its own. This is a real trap: code that reads "uses pd.Grouper(freq=...), so it must include every day" is only true when pd.Grouper is the SOLE key, not when it rides alongside another column.

4 · One frequency-string trap, and why key= beats resample()'s setup cost

Confirmed directly (pandas 3.0.5): the once-common month-end alias freq="M" is dead — it now raises outright, not merely a deprecation warning:

clean.groupby(pd.Grouper(key="order_date", freq="M"))["amount"].sum()
# ValueError: Invalid frequency: M. Failed to parse with error message:
# ValueError("'M' is no longer supported for offsets. Please use 'ME' instead.")

freq="ME" (month end) is the current spelling, alongside "D" (day), "W" (week), and "QE" (quarter end) — the same frequency-alias vocabulary resample() already uses (Lesson 38), since both are built on the same offset machinery underneath. The practical reason to reach for pd.Grouper over chaining groupby().resample(): no set_index() setup step, and the result reads as one ordinary multi-key groupby([...]) call instead of two stacked group operations with their own MultiIndex interaction quirks.

Q: "How would you get monthly revenue per customer out of a raw orders table?" A strong answer, out loud: "groupby(['customer', pd.Grouper(key='order_date', freq='ME')])['amount'].sum() — Grouper turns the date-frequency bucket into an ordinary groupby key, so it sits right alongside the customer column in one call, and the date column stays a plain column, no set_index() needed first. The one thing I'd flag: with two keys like this, a customer's month with zero orders just doesn't appear as a row at all — Grouper only backfills empty calendar periods when it's the SOLE key in the call, the same gap-filling resample() does alone. If a report genuinely needs every customer-month combination present, even the zero ones, that needs an explicit reindex onto the full cross-product afterward, not just trusting Grouper to have filled it in already." The signal: naming that Grouper composes with an ordinary column in one groupby([...]) call (most candidates only know the resample()-alone shape), and specifically flagging that gap-filling is NOT guaranteed once a second key is added.
