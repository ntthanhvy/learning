Backend Foundations · Reference

Glossary

Every jargon term used in the lessons, in one place. Tiếng Việt column is dev-style — how Vietnamese devs actually say it, not textbook translation.

TermTiếng Việt (dev-style)In software
serverserver (giữ nguyên)A long-running program that listens on a port and answers requests. Not the physical machine — the process.
portport / cổng (thường giữ nguyên)A number (like 8080 or 5432) that lets one machine run many listening programs; the address within a machine.
endpointendpoint (giữ nguyên)One callable URL + method that an API exposes, e.g. GET /api/orders/{id}.
route / routingroute (giữ nguyên); routing = định tuyếnThe rule mapping a method + path pattern to the function that should handle it; routing is the act of matching.
handlerhandler (giữ nguyên) — hàm xử lý requestThe function that receives one request and produces one response. The backend equivalent of an event handler.
middlewaremiddleware (giữ nguyên) — lớp chạy trước/sau handlerCode wrapped around handlers to do cross-cutting work — logging, auth checks, timeouts — so every handler doesn't repeat it.
business logiclogic nghiệp vụ / business logicThe rules of your product ("an order over $100 ships free"), kept separate from HTTP parsing and database code.
statelessstateless (giữ nguyên) — không giữ trạng thái giữa các requestThe server keeps nothing in memory between requests; each request starts from zero. State that must survive goes to the database.
persistencepersist / lưu xuống DBStoring data so it survives after the process stops — usually meaning "write it to the database".
connection poolconnection pool (giữ nguyên) — pool kết nối DBA kept-warm set of database connections that handlers borrow and return, because opening a fresh connection per request is too slow.
serializationserialize (giữ nguyên) — chuyển object thành JSON/bytesTurning an in-memory value into bytes to send over the wire (e.g. struct → JSON); deserialization is the reverse.
schemaschema (giữ nguyên) — cấu trúc bảng của DBThe set of tables, columns, and rules defining what data can exist — the database's shape, shared by every feature.
entityentity (giữ nguyên) — thực thể, có id riêngA thing in the product with its own identity and lifecycle — it gets an id, usually its own table, and other things refer to it.
primary keyprimary key / khóa chính (hay nói tắt PK)The column that uniquely identifies one row — usually an id — which other tables point at.
foreign keyforeign key / khóa ngoại (hay nói tắt FK)A column holding another table's primary key, expressing "this row belongs to that row".
join tablejoin table / bảng trung gianA table whose rows each connect two other tables' rows — how a many-to-many relationship is stored (e.g. order_items between orders and products).
normalizationnormalization / chuẩn hóa dữ liệuStructuring tables so each fact is stored exactly once and everything else references it by key. Instinct version: one fact, one place.
denormalizationdenormalization (giữ nguyên) — cố ý lưu trùng dữ liệuDeliberately storing a fact in more than one place — a trade-off you must justify (e.g. snapshotting a price onto an order line).
API contractAPI contract (giữ nguyên) — hợp đồng giữa backend và clientThe agreed shape of an API — URLs, verbs, bodies, error format. The promise frontends build against; breaking it breaks them.
resourceresource (giữ nguyên) — "danh từ" mà API exposeA thing clients address by URL — usually an entity or collection (/orders, /orders/42). Verbs act on it; you don't make /getX endpoints.
idempotentidempotent (giữ nguyên) — gọi N lần như gọi 1 lầnSame end state whether performed once or many times, so blind retries are safe. GET/PUT/DELETE promise it; POST does not.
status codestatus code (giữ nguyên) — chữ số đầu nói ai có lỗiThe response's three-digit result. 2xx worked; 4xx the client's request was wrong (fixable by caller); 5xx the server broke (alarm).
error contracterror contract — MỘT format lỗi thống nhấtThe single JSON error shape every failing response uses, with a stable machine-readable code clients branch on — the API's sentinel errors.
authenticationauthentication (giữ nguyên) — xác minh "bạn là ai"Proving who is making a request — distinct from authorization, which decides what they're allowed to do once known.
cookiecookie (giữ nguyên)A small piece of data the browser stores and automatically re-sends to the same domain on every request.
session tokensession token / session ID (giữ nguyên)An opaque random identifier naming one row in a server-side sessions table — meaningless by itself until looked up.
session storesession store (giữ nguyên) — bảng lưu session ở serverThe server-side table (or Redis) mapping session tokens to user ids and metadata — where session state actually lives, keeping handlers stateless.
JWTgiữ nguyên "JWT" — token tự chứa thông tin, ký bằng chữ ký sốJSON Web Token: a signed, self-contained blob of claims (user id, role, expiry) any server can verify by signature alone, no database lookup.
XSSgiữ nguyên "XSS" — chèn JS độc hại chạy trên trang của bạnCross-Site Scripting: an attacker's JavaScript runs on your page, able to read anything JS can read — including a token in localStorage.
CSRFgiữ nguyên "CSRF" — trang độc hại giả mạo request bằng cookie có sẵnCross-Site Request Forgery: a malicious page makes the victim's browser fire an authenticated request, since cookies attach automatically.
indexindex (giữ nguyên) — cấu trúc phụ giúp tìm nhanh, ghi chậm hơn chútAn extra on-disk structure letting the database jump to matching rows instead of scanning the whole table — at the cost of extra work on every write to that table.
selectivityselectivity (giữ nguyên) — cột lọc được bao nhiêu dữ liệuHow much a WHERE condition on a column narrows the result set. A near-unique column (email) is highly selective; a near-constant column (a 95%-true boolean) is not, and rarely benefits from an index.
N+1 query problemgiữ nguyên "N+1 query problem" — 1 query lấy danh sách rồi lặp N lần query thêmFetching a list (1 query) then looping over it firing one more query per item (N queries), instead of one JOIN or batched IN (...) lookup. No index fixes this — the access pattern itself is the bug.
transactiontransaction (giữ nguyên) — nhóm câu lệnh, hoặc tất cả cùng thành công hoặc tất cả cùng bị hủyA group of one or more database statements that either all take effect together, or none do — BEGIN, then COMMIT (keep everything) or ROLLBACK (discard everything).
isolationisolation (giữ nguyên) — mức độ transaction này bị ảnh hưởng bởi transaction khác chạy song songHow much a transaction is protected from the effects of OTHER transactions running at the same time. A separate guarantee from atomicity — "commits together" says nothing about what happens when two transactions interleave.
lost updategiữ nguyên "lost update" — 2 transaction cùng đọc rồi cùng ghi đè, một bên bị mất tác dụngA race condition where two concurrent transactions each read the same stale value, both decide to update based on it, and one write silently overwrites the other's effect instead of combining correctly.
row lockrow lock (giữ nguyên) — SELECT ... FOR UPDATE khóa dòng đó, transaction khác phải chờA SELECT ... FOR UPDATE clause that locks the returned row(s) until the transaction ends — another transaction trying to lock or update the same row waits its turn instead of racing ahead on stale data.
information disclosuregiữ nguyên "information disclosure" — lộ thông tin nội bộ qua response, giúp attacker vẽ bản đồ hệ thốngLeaking internal implementation details — stack traces, file paths, library versions, raw database errors — through an application's normal responses, giving an attacker a map of the system without needing to break in.
correlation ID / request IDgiữ nguyên "correlation ID" / "request ID" — mã nối một request với các dòng log server tương ứngA unique identifier generated for one incoming request, attached to every log line produced while handling it and safely returned to the client — the bridge that lets a support ticket be matched back to the exact server-side log entries, without exposing their contents.
structured logginggiữ nguyên "structured logging" — log dạng key-value/JSON, lọc/tìm chính xác theo fieldLogging as structured key-value data (often JSON) instead of free-text sentences, so fields like request_id, user_id, or error can be filtered and searched precisely across millions of log lines.
load balancergiữ nguyên "load balancer" — bộ phân phối request tới nhiều instanceA component that sits in front of multiple server instances and distributes incoming requests across them, usually round-robin or by least-connections.
horizontal scalinggiữ nguyên "horizontal scaling" — chạy thêm instance thay vì máy mạnh hơnScaling by adding more instances of a process running the same code, as opposed to vertical scaling which gives one instance more CPU/RAM.
Redisgiữ nguyên "Redis" — cache/key-value store dùng chung qua networkAn in-memory data store used as a shared cache or fast key-value store that every instance connects to over the network, instead of each instance keeping its own local copy.
shared-nothinggiữ nguyên "shared-nothing" — instance không giữ gì độc quyền, mọi state đều ở chỗ dùng chungAn architecture where no server instance holds any data that isn't also recoverable from a shared store, so any instance can be killed or replaced without losing anything.
sticky sessions / session affinitygiữ nguyên "sticky sessions" / "session affinity" — LB luôn route 1 client về đúng 1 instanceA load balancer configuration that routes a given client's requests to the same backend instance every time, instead of distributing freely.
cachecache (giữ nguyên) — nơi lưu tạm kết quả để tránh đọc/tính lạiA fast, temporary copy of data kept somewhere cheaper to read than its original source, so repeat reads skip the expensive origin — a DB query, a slow computation.
cache-asidecache-aside (giữ nguyên) — check cache trước, miss thì đọc DB rồi ghi lại vào cacheThe most common caching pattern: on read, check the cache first; on a miss, read the real source, then write that value into the cache before returning it — the next read for the same key is a hit.
cache hit / cache misscache hit/miss (giữ nguyên) — có sẵn trong cache hay khôngWhether a lookup found the value already in the cache (hit) or had to go to the original source and store it for next time (miss).
TTLTTL (giữ nguyên) — thời gian sống, hết hạn tự bị bỏTime-to-live: a cache entry's expiry duration; once it passes, the entry is dropped or ignored automatically, forcing the next read to refetch a fresh copy.
invalidate cacheinvalidate cache (giữ nguyên) — chủ động xóa cache khi data gốc đổiDeliberately removing or refreshing a cached entry the moment its underlying data changes, instead of only waiting for its TTL — needed for data that must never be stale right after a write.
stale readstale read (giữ nguyên) — đọc trúng cache cũ, gốc đã đổiA read that returns a cached value that no longer matches the current source of truth — the risk every cache introduces, traded for speed.
Cache-ControlCache-Control (giữ nguyên) — header HTTP nói được cache bao lâuAn HTTP response header telling browsers and intermediate proxies whether and how long they may cache a response themselves, with no application code involved.
background jobbackground job (giữ nguyên) — việc chạy tách khỏi vòng request/responseAny unit of work triggered by a request but deliberately run outside that request's response cycle, so the client doesn't wait for it to finish.
job queuejob queue (giữ nguyên) — nơi lưu tạm các việc đang chờ xử lýA durable, ordered store of pending units of work — a database table or a dedicated system like Redis/SQS/RabbitMQ — that a handler writes to and a worker reads from.
enqueueenqueue (giữ nguyên) — đưa việc vào hàng đợiThe act of adding a new unit of work to a job queue, without waiting for it to be processed.
workerworker (giữ nguyên) — process riêng chuyên xử lý job trong hàng đợiA separate, independent process (or pool of goroutines) whose only job is to pull pending work off a queue and execute it, entirely outside any request's lifecycle.
at-least-once deliveryat-least-once delivery (giữ nguyên) — job có thể chạy lại hơn 1 lần, không được phép mất jobA delivery guarantee where a queued job is retried until a worker confirms it finished, meaning the same job may occasionally execute more than once — the opposite risk of at-most-once, which can silently drop work instead.
rate limitingrate limiting (giữ nguyên) — giới hạn số request được phép trong một khoảng thời gianDeliberately capping how many requests a client (or the service as a whole) may make in a given time window, rejecting the excess instead of queueing it indefinitely.
token buckettoken bucket (giữ nguyên) — thuật toán giới hạn tốc độ bằng token nạp dầnA rate-limiting algorithm: a bucket holds up to N tokens, refills at a fixed rate, and each request must take one token to proceed — an empty bucket means the request is rejected until it refills.
backpressurebackpressure (giữ nguyên) — báo ngược cho phía gửi biết phải chậm lạiA system under load signaling upstream — a client, or an earlier stage in a pipeline — to slow down or stop sending more work, rather than silently accepting everything and failing later.
debouncedebounce (giữ nguyên) — trì hoãn, chỉ chạy lần gọi cuối sau khi ngừng gọi dồn dậpDelaying a function's execution until a burst of calls stops, so only the last one in a rapid sequence actually runs — the frontend cousin of server-side rate limiting.
authorizationauthorization (giữ nguyên) — quyết định user được làm gìDeciding what an already-identified user is allowed to do — a separate question from authentication, which only established who they are.
RBACRBAC (giữ nguyên) — gán quyền theo vai tròRole-based access control: permissions are attached to named roles (admin, editor, viewer) rather than to individual users, and each user is assigned one or more roles.
IDORIDOR (giữ nguyên) — sửa ID trên URL để đọc/sửa dữ liệu người khácInsecure Direct Object Reference: an endpoint checks that a user is authenticated but never checks that the specific record requested actually belongs to them, letting any logged-in user read or modify another user's data by changing an id in the URL.
403 Forbidden vs 401 Unauthorizedgiữ nguyên "403"/"401" — 403 là biết bạn là ai nhưng không cho làm, 401 là chưa biết bạn là ai401 means authentication itself failed or is missing (the server doesn't know who you are). 403 means authentication succeeded but that identity isn't allowed to do this — a different failure with a different fix.
log levellog level (giữ nguyên) — nhãn độ khẩn cấp trên mỗi dòng logA label on each log line (debug, info, warn, error) ranking how urgent or noteworthy it is, so tooling and humans can filter millions of lines down to the ones that matter right now.
monitoringmonitoring (giữ nguyên) — theo dõi liên tục các chỉ số hệ thốngContinuously watching a small set of numeric measurements about a running system — request rate, error rate, latency, queue depth — so trouble is visible from a trend or threshold before anyone reads a single log line.
metricmetric (giữ nguyên) — một con số được đo liên tục theo thời gianA single numeric time series a system emits continuously — request count, error rate, p99 latency, queue depth — designed to be graphed and alerted on, unlike a log line which describes one discrete event.
liveness checkliveness check — process còn sống không, không check dependencyAn endpoint answering only whether the process itself is alive and should keep running — no dependency checks, since a dependency being down is not a reason to kill and restart the process.
readiness checkreadiness check — instance này serve request được chưaAn endpoint answering whether this specific instance can currently serve real traffic, by checking the dependencies a real request would need — used by a load balancer to temporarily stop routing to an unready instance without restarting it.
nitnit (giữ nguyên) — góp ý về hình thức, không bắt buộc sửaA review comment about formatting, naming, or personal style preference — non-blocking, the author can take it or leave it, and it says nothing about whether the code is correct.
blocking (comment)blocking (giữ nguyên) — comment bắt buộc phải sửa trước khi mergeA review comment prefix marking an issue the author must resolve before the PR can merge, as opposed to a nit the author may take or leave.
paginationpagination (giữ nguyên) — chia kết quả thành từng trang nhỏSplitting a large result set into smaller pages the client requests one at a time, instead of returning every row in a single response.
offset paginationoffset pagination (giữ nguyên) — phân trang kiểu bỏ qua N dòng đầuPagination by row count: the client asks for page N, and the query skips (OFFSET) N pages worth of rows before returning the next LIMIT rows.
cursor pagination / keyset paginationcursor pagination / keyset pagination (giữ nguyên) — phân trang theo vị trí dòng cuối đã thấyPagination by position: the client sends back the sort key of the last row it saw, and the query asks the database for rows strictly after that key, instead of skipping a row count.
API versioningAPI versioning (giữ nguyên) — quy tắc đổi API mà không làm hỏng client cũA rule for evolving an API's contract over time without silently breaking clients who already depend on the current shape.
backward-compatible changebackward-compatible change (giữ nguyên) — thêm mới, client cũ vẫn chạy đượcA change to an API contract that every existing client keeps working through unmodified, because it only adds — never removes or repurposes — something.
breaking changebreaking change (giữ nguyên) — client cũ sẽ hỏng nếu áp dụng thẳngA change to an API contract that at least one existing, correctly-written client would break against — the trigger for a new version rather than an in-place edit.
deprecated versiondeprecated version (giữ nguyên) — vẫn chạy nhưng có ngày dừng hỗ trợA version the service still serves but no longer recommends, usually announced with a fixed retirement date so clients have a deadline to migrate by.
SQL injectiongiữ nguyên "SQL injection" — input độc hại được ghép thẳng vào câu SQL, đổi cả ý nghĩa câu lệnhA vulnerability where untrusted input is inserted directly into a SQL query's text, letting an attacker change what the query does instead of only what data it fetches.
parameterized query / prepared statementgiữ nguyên "parameterized query" / "prepared statement" — SQL và giá trị gửi tách riêng, giá trị không thể bị hiểu thành cú phápA query where placeholders ($1, $2, ...) stand in for values, and the driver sends the SQL text and the values as two separate messages — a value can never be interpreted as syntax.
input validationinput validation (giữ nguyên) — kiểm tra dữ liệu đầu vào đúng dạng/kiểu/giới hạn trước khi xử lýChecking that input matches the shape, type, and bounds a handler actually expects before acting on it — a different layer from injection defense.
allowlist validationallowlist validation — chỉ chấp nhận giá trị nằm trong danh sách biết trước là hợp lệRejecting everything except a known-good, explicitly enumerated set of values — as opposed to a blocklist, which tries to enumerate known-bad values and always misses one.
pool exhaustionpool exhaustion (giữ nguyên) — hết connection rảnh trong pool, request phải chờThe state where every connection in a pool is currently in use (or leaked) and a new caller must wait for one to free up — indistinguishable from a slow network or downed database from the outside, since requests simply stop completing.
migrationmigration (giữ nguyên) — script SQL có thứ tự, đi kèm code trong git, chạy qua tool để đổi schema từng bướcA versioned, ordered SQL script (or paired up/down script) checked into version control alongside the code that depends on it, applied by a migration tool that tracks which ones have already run — the schema's equivalent of a git commit history.
expand/contract patternexpand/contract pattern (giữ nguyên) — tách 1 thay đổi breaking thành nhiều bước nhỏ, bước nào cũng backward-compatibleThe pattern of splitting one breaking schema change into several individually backward-compatible steps: first expand the schema to tolerate both old and new code, then contract it once every instance has moved to the new code.
backfillbackfill (giữ nguyên) — chạy job điền dữ liệu cho các dòng cũ sau khi thêm cột mớiA script or job that fills in a value for rows that existed before a new column was added, so old rows end up with the same data new rows get going forward.
CREATE INDEX CONCURRENTLYconcurrent index build (giữ nguyên) — build index không khóa bảng, nhưng chậm hơn và fail giữa chừng phải tự retryAn index build that avoids locking the table against writes by scanning it more than once, at the cost of taking noticeably longer and needing a manual retry if it fails partway.
fix-forwardfix-forward (giữ nguyên) — không rollback migration lỗi, viết migration mới để sửa tiếpA policy of never reversing a bad migration; instead a new migration is written that fixes the problem going forward, leaving the migration history append-only.
Twelve-Factor AppTwelve-Factor App (giữ nguyên) — bộ quy ước phổ biến cho việc build service dễ deploy/scaleA widely cited set of conventions for building services that deploy and scale cleanly — config, statelessness, logs, and process management among its recurring themes.
configconfig (giữ nguyên) — giá trị thay đổi theo môi trường (dev/staging/prod), tách khỏi codeAnything that varies between deploys of the same code — credentials, hostnames, per-environment toggles — kept out of the codebase and supplied at runtime, usually via environment variables.
fail fastfail fast (giữ nguyên) — phát hiện lỗi sớm nhất có thể (vd lúc khởi động) rồi dừng ngay, thay vì để lỗi âm thầm lan xuống dướiDetecting a fatal problem at the earliest possible point (e.g. startup) and stopping immediately with a clear error, instead of letting it surface later as a confusing symptom far from the actual cause.
SameSiteSameSite (giữ nguyên) — thuộc tính cookie quyết định cookie có được gửi kèm request từ site khác hay khôngA cookie attribute controlling whether the browser sends that cookie on requests originating from a different site — Strict never sends it cross-site, Lax sends it on top-level cross-site navigations only, None sends it always (and requires the Secure flag).
double-submit cookiedouble-submit cookie (giữ nguyên) — cookie CSRF token phải khớp với token gửi kèm header/bodyA CSRF defense where the server sets a random token as a readable cookie, and the client must also send that same token back in a request header or body field on every state-changing request; a cross-site attacker can trigger the cookie to be sent but cannot read its value to copy it into the header.
synchronizer tokensynchronizer token (giữ nguyên) — token CSRF nhúng trong form, server so khớp với giá trị lưu ở sessionA CSRF defense where the server embeds a unique, unpredictable token in each rendered form (tied to the user's session server-side), and rejects the submission if that token is missing or doesn't match.
mass assignmentmass assignment (giữ nguyên) — bind thẳng JSON client gửi vào toàn bộ field của model, kể cả field không nên cho client sửaA vulnerability where decoding untrusted input directly onto a model binds every field the model happens to have, not just the ones the client was meant to set.
excessive data exposureexcessive data exposure (giữ nguyên) — trả nguyên model nội bộ ra response, lộ field không nên publicThe read-side mirror of mass assignment: encoding an internal model straight into an API response leaks fields — password hashes, internal flags, other users' data — that were never meant to leave the server.
SSRFgiữ nguyên "SSRF" (Server-Side Request Forgery) — dụ server tự gửi request tới địa chỉ attacker chọn, lợi dụng vị trí mạng và quyền của serverServer-Side Request Forgery: a vulnerability where an attacker gets a server to make an outbound HTTP request to a destination the attacker chose, instead of one the application intended — abusing the server's own network position and credentials rather than the client's.
concurrencyconcurrency (giữ nguyên) — chia chương trình thành nhiều phần chạy độc lập, xen kẽ nhau; là chuyện thiết kế code, không phải chuyện máy có mấy coreStructuring a program as independently executing pieces that can make progress in overlapping time periods — a property of your program's design, not of the hardware it runs on. Rob Pike: "the composition of independently executing processes."
parallelismparallelism (giữ nguyên) — nhiều việc chạy CÙNG một khoảnh khắc thật, bắt buộc phải có nhiều core; là chuyện hardware/runtimeTwo or more computations literally executing at the same instant, which requires more than one physical CPU core — a property of the hardware and runtime, not of your program's structure. Rob Pike: "the simultaneous execution of (possibly related) computations."
OS threadOS thread (giữ nguyên) — luồng thực thi do kernel của hệ điều hành quản lý và tự ý ngắt/đổi lúc nào cũng được; mỗi thread có stack riêng, khá tốnAn independently schedulable stream of execution managed by the operating system kernel, with its own stack; the kernel can interrupt and reschedule it at any moment. The only unit an OS will place on a separate core, so the unit of real parallelism — and comparatively expensive (megabyte stacks, a syscall to create).
coroutinecoroutine (giữ nguyên) — hàm có thể tự tạm dừng giữa chừng rồi chạy tiếp từ đúng chỗ đó; do runtime của ngôn ngữ điều phối, không phải kernel; rẻ nên tạo hàng trăm nghìn cái cũng đượcA function that can suspend itself mid-execution and later resume where it left off, scheduled by a language runtime or library rather than the OS kernel — cheap enough to create by the hundred thousand. Called goroutine in Go, task/Future in Rust, coroutine in Kotlin and Python async def.
goroutinegoroutine (giữ nguyên) — coroutine của Go; rẻ, chạy ghép lên vài OS thread, và khác coroutine thường ở chỗ block ở đâu cũng được, không cần async/awaitGo's unit of concurrency: a function executing concurrently with others in the same address space, multiplexed M:N onto OS threads by the runtime. Go avoided the words "thread" and "coroutine" deliberately — a goroutine is preemptible and can block anywhere, with no async/await ceremony.
preemptive schedulingpreemptive scheduling (giữ nguyên) — scheduler tự ý ngắt task đang chạy, task không cần (và không thể) xin phépScheduling where the scheduler forcibly interrupts a running task at a time of its own choosing, without the task's cooperation — how the OS kernel schedules threads.
cooperative schedulingcooperative scheduling (giữ nguyên) — task tự nhường quyền tại những điểm nhất định, chứ không bị ngắt từ bên ngoàiScheduling where a running task yields control voluntarily at defined points (an await, a channel operation, a network read), rather than being interrupted from outside — how most coroutine runtimes work.
M:N schedulingM:N scheduling (giữ nguyên) — M coroutine chạy ghép lên N thread thật, với M lớn hơn N rất nhiềuA scheduling model where M runtime-managed tasks are multiplexed onto N operating-system threads, with M vastly larger than N — usually N ≈ one thread per core. The reason coroutines don't compete with threads: they run on top of them.
context switchcontext switch (giữ nguyên) — lưu trạng thái task đang chạy rồi nạp trạng thái task khác vàoSaving one task's execution state and restoring another's so it can resume. Cheap when a runtime does it between coroutines in user space; costlier when the kernel does it between threads.
blocking callblocking call (giữ nguyên) — lời gọi không trả về cho đến khi xong việc, giữ luôn cái đang chạy nóA call that does not return until its work finishes, holding whatever executes it for the whole duration — the thing concurrency exists to stop from wasting a thread.
I/O-boundI/O-bound (giữ nguyên) — thời gian chủ yếu là NGỒI CHỜ network/disk/database, không phải chờ tính toánWork whose completion time is dominated by waiting for input/output — network, disk, or database — rather than by computation. The overwhelming majority of backend work, and the case where cheap concurrency is the right answer.
CPU-boundCPU-bound (giữ nguyên) — thời gian chủ yếu là TÍNH TOÁN thật; chỉ nhanh hơn khi có thêm core, thêm task không giúp gìWork whose completion time is dominated by computation, so it goes faster only when given more CPU cores, never by adding more concurrent tasks. Capped by physical core count.
GILGIL (giữ nguyên) — cái lock trong CPython mặc định khiến chỉ một thread chạy bytecode Python tại một thời điểm; thread vẫn concurrent nhưng KHÔNG parallel cho code Python thuầnGlobal Interpreter Lock: a lock in the default CPython interpreter that permits only one thread to execute Python bytecode at a time, so threads give concurrency but not parallelism for pure-Python computation. Python 3.14 ships an officially supported opt-in free-threaded build without it.
idempotency keyidempotency key (giữ nguyên) — key client tự tạo cho 1 lần thao tác, gửi kèm mỗi lần retry để server nhận ra đây là lần gửi lại, không phải thao tác mớiA unique value the client generates once per logical action and sends on every retry of the same POST request, so the server can recognize a retry and return the original result instead of repeating the side effect.
SIGTERMgiữ nguyên "SIGTERM" — tín hiệu xin dừng process, process có thể bắt được và tự dọn dẹp trước khi thoátA signal sent to a process asking it to terminate, which the process can intercept and react to (finish in-flight work, close connections) before exiting — as opposed to SIGKILL, which cannot be intercepted at all.
SIGKILLgiữ nguyên "SIGKILL" — tín hiệu buộc dừng ngay, process không kịp dọn gì cảA signal that terminates a process immediately, with no chance for it to run any cleanup code at all — the fallback a deployment platform sends if a process doesn't exit on its own within a fixed grace period after SIGTERM.
circuit breakercircuit breaker (giữ nguyên) — bộ canh trạng thái đặt quanh 1 lời gọi tới dependency hay lỗi/chậm, hỏng nhiều lần thì tự chặn gọi tiếpA stateful guard placed around a call to a flaky or slow dependency, which starts letting calls through, trips to blocking them after enough consecutive failures, and later allows a single test call through to check if the dependency has recovered.
cascading failurecascading failure (giữ nguyên) — lỗi lan từ chỗ hỏng sang chỗ đang gọi nó, vì cứ chờ/retry mãiA failure that spreads from one struggling component to the components calling it, because they keep waiting on or retrying the struggling one instead of giving up quickly — an otherwise-healthy caller goes down too.
half-open statehalf-open state (giữ nguyên) — trạng thái thứ 3, hết thời gian cooldown thì cho đúng 1 lời gọi thử qua để test dependency đã hồi chưaA circuit breaker's third state, entered after the open cooldown elapses, in which exactly one probe call is allowed through to test whether the dependency has recovered before deciding to close the circuit again or reopen it.
fallbackfallback (giữ nguyên) — phản hồi thay thế (kém hơn) khi breaker đang mở, thay vì báo lỗi tiếp lên trênA degraded but usable response returned when a circuit breaker is open and the real dependency can't be called — a cached value, a "check back shortly" message, or a fast honest error — instead of propagating the failure further after a full timeout.
dual-write problemdual-write problem (giữ nguyên) — phải ghi vào 2 hệ thống khác nhau (DB và message queue) như 1 bước, nhưng chúng không nằm trong cùng 1 transactionThe problem of a handler needing to update a database AND notify another system (a message queue, a webhook, a second service) as if it were one atomic step, when they are actually two independent systems with no shared transaction — a crash between the two writes either loses the event or, if retried, risks duplicating it.
outbox tableoutbox table (giữ nguyên) — bảng chứa event chờ publish, ghi cùng transaction với dòng nghiệp vụ để cùng commit hoặc cùng rollbackA database table that holds events waiting to be published, written in the same transaction as the business row that caused them, so the two writes commit or roll back together.
transactional outboxtransactional outbox (giữ nguyên) — ghi event vào outbox table cùng transaction với thay đổi nghiệp vụ, rồi để 1 tiến trình riêng lo publish thật sựThe overall pattern of writing an event to an outbox table in the same transaction as the business change that caused it, then relying on a separate relay process to actually deliver it — trading a two-system dual write for one transactional write plus an asynchronous, retriable delivery step.
relay / pollerrelay / poller (giữ nguyên) — tiến trình riêng, đọc outbox table và publish thật ra message queue, xong thì đánh dấu đã xử lýA standalone process that polls the outbox table for unprocessed rows, publishes each one to the real message queue or webhook, and marks it processed once the publish succeeds — the component that turns a written outbox row into a real delivered event.
webhookwebhook (giữ nguyên) — bên thứ 3 tự gọi POST tới URL của bạn để báo có sự kiện xảy raAn HTTP callback: a third-party service makes an outbound POST request to a URL you registered, to notify you an event happened on their side — no user session involved, so the caller's identity is only ever a claim until verified.
HMACHMAC (giữ nguyên) — hàm băm có khóa bí mật, tạo ra 1 chuỗi ký (tag) gắn liền với nội dung message; không có secret thì không tự tạo tag đúng được, đổi 1 byte trong message là tag khác hẳnHash-based Message Authentication Code: a cryptographic function combining a secret key with a message to produce a fixed-length tag. Anyone holding the same secret can recompute the same tag from the same message, but cannot forge a valid tag without it, and changing even one byte of the message changes the tag completely.
timing attacktiming attack (giữ nguyên) — đoán secret bằng cách đo thời gian so sánh, so sánh kiểu thường thoát sớm nên byte đúng nhiều thì lâu hơnAn attack that infers a secret value by measuring how long an operation takes — a naive equality check exits as soon as it finds the first mismatched byte, so response time leaks how many leading bytes were guessed correctly. Defended against with a constant-time comparison function (e.g. Go's hmac.Equal).
constant time (comparison)constant-time comparison (giữ nguyên) — so từng byte, luôn tốn thời gian như nhau bất kể sai ở đâu, không lộ thông tin qua tốc độA comparison that always takes the same amount of time regardless of where (or whether) the two values first differ, so an attacker measuring response time learns nothing about how close a guess was — the defense against a timing attack.
client credentials grantclient credentials grant (giữ nguyên) — service tự xác thực bằng client id/secret (không có user), đổi lấy access token ngắn hạn để gọi APIAn OAuth 2.0 grant type where a service authenticates directly with its own client id and secret — no user or browser redirect involved — and receives a short-lived access token to use on subsequent calls, trading a rarely-exposed long-lived secret for a token that expires soon if leaked.
mTLS (mutual TLS)mTLS (giữ nguyên) — cả 2 bên xác minh certificate của nhau khi bắt tay TLS, xác thực xảy ra trước khi có request HTTP nàoMutual TLS: both sides of a TLS connection present and verify a certificate, so the server confirms the client's identity as part of the handshake itself — no secret travels inside the HTTP request at all, since identity is proven a layer below it.
retry stormretry storm (giữ nguyên) — nhiều client cùng retry một lúc, tái tạo lại đúng cái spike gây lỗi ban đầuMany clients retrying at the same moment — often because they all used the same fixed delay — re-creating or amplifying the exact load spike that caused the original failure.
exponential backoffexponential backoff (giữ nguyên) — mỗi lần fail thì chờ lâu gấp đôi lần trước, có giới hạn trênA retry strategy where the wait between attempts roughly doubles after each failure, up to a capped maximum, so a client backs off harder the longer a dependency stays down.
jitterjitter (giữ nguyên) — random hóa thời gian chờ retry, tránh nhiều client retry cùng lúcRandomizing the retry delay instead of using the exact computed backoff value, so clients that failed at the same moment don't all retry at the same moment too.
full jitterfull jitter (giữ nguyên) — chọn thời gian chờ ngẫu nhiên đều trong khoảng [0, backoff], không chỉ dao động nhẹ quanh nóA jitter strategy that picks the actual wait uniformly at random between 0 and the full computed backoff value, spreading retries across the whole window rather than only wobbling near it — shown to break up synchronized retry waves better than smaller-randomness variants.
optimistic lockingoptimistic locking (giữ nguyên) — không khóa gì lúc đọc, chỉ check version lúc ghi, đổi rồi thì ghi fail chứ không phải chờA concurrency-control strategy that assumes conflicts are rare: reads take no lock at all, and a write only succeeds if the row hasn't changed since it was read (checked via a version number or timestamp) — a conflicting write fails fast instead of blocking, unlike pessimistic locking's SELECT ... FOR UPDATE.
soft deletesoft delete (giữ nguyên) — đánh dấu dòng là đã xóa (set timestamp/flag) thay vì DELETE thật, dòng vẫn còn trong DB nhưng query bình thường coi như không tồn tạiMarking a row as deleted by setting a flag or timestamp column (e.g. deleted_at) instead of removing it with DELETE — the row still physically exists and stays valid for foreign keys, but normal application queries filter it out.
partial indexpartial index (giữ nguyên) — index chỉ build trên các dòng thỏa WHERE, không phải cả bảngAn index (often UNIQUE) built over only the rows matching a WHERE clause, instead of the whole table — used to enforce a rule like uniqueness only among "live" rows, so a soft-deleted row's value can be reused by a new one.
unique violationunique violation (giữ nguyên) — lỗi Postgres trả về khi INSERT/UPDATE vi phạm UNIQUE hoặc PRIMARY KEY, tức là dòng bị trùngA Postgres error returned when an INSERT or UPDATE would violate a UNIQUE or PRIMARY KEY constraint — the row conflicts with one already present.
upsertupsert (giữ nguyên) — INSERT có ON CONFLICT, nếu trùng UNIQUE/PRIMARY KEY thì làm theo fallback đã khai (DO NOTHING hoặc DO UPDATE) thay vì báo lỗiAn INSERT statement with an ON CONFLICT clause naming what to do if the new row collides with an existing UNIQUE or PRIMARY KEY value — insert normally on no conflict, or apply the named fallback (DO NOTHING or DO UPDATE) instead of erroring.
batched querybatched query (giữ nguyên) — 1 câu query duy nhất lấy dữ liệu cho nhiều ID cha cùng lúc, thay vì query riêng cho từng cáiA single query that fetches the same kind of row for many parent IDs at once (typically via WHERE id = ANY($1) or WHERE id IN (...)), replacing one query per parent with one query for all of them.
lazy-loadinglazy-loading (giữ nguyên) — chỉ query dữ liệu liên quan khi code thực sự truy cập tới, tiện nhưng dễ gây N+1 nếu gọi trong vòng lặpFetching a related object or collection only when code first accesses it, rather than up front — convenient because it looks like a normal field access, but silently issues a new query every time it fires inside a loop, the most common way ORMs introduce the N+1 query problem.
dirty readdirty read (giữ nguyên) — đọc phải dữ liệu của transaction khác chưa commit, lỡ nó rollback thì coi như đọc phải dữ liệu không tồn tạiA transaction reads a row another transaction has written but not yet committed — if that other transaction rolls back, the first transaction acted on data that never actually existed. Postgres prevents this at every isolation level, including its READ UNCOMMITTED.
non-repeatable readnon-repeatable read (giữ nguyên) — đọc cùng 1 dòng 2 lần trong 1 transaction mà ra 2 giá trị khác nhau, vì transaction khác đã commit thay đổi ở giữaA transaction reads the same row twice and gets two different values, because another transaction committed a change to that row in between the two reads.
phantom readphantom read (giữ nguyên) — chạy lại đúng 1 câu query WHERE 2 lần mà ra khác số dòng, vì transaction khác đã INSERT/DELETE dòng khớp điều kiện ở giữaA transaction re-runs the same WHERE query twice and gets a different set of rows, because another transaction committed an INSERT or DELETE matching that condition in between — the hardest of the three anomalies to guard against, since there's no single row to lock.
READ COMMITTEDREAD COMMITTED (giữ nguyên) — mức mặc định của Postgres, mỗi câu lệnh thấy dữ liệu đã commit tại đúng thời điểm nó chạyPostgres's default isolation level — each individual statement sees whatever was committed at the moment that statement runs, so a later statement in the same transaction can see a different value than an earlier one did. Prevents dirty reads only.
REPEATABLE READREPEATABLE READ (giữ nguyên) — cả transaction nhìn dữ liệu theo đúng 1 snapshot chụp từ câu lệnh đầu tiên, đọc lại không đổiAn isolation level where a transaction's reads are pinned to a single consistent snapshot taken at its first statement, so re-reading the same row or the same query always returns the same result for the rest of that transaction. In Postgres this also blocks phantom reads, stricter than the SQL standard technically requires at this level.
SERIALIZABLESERIALIZABLE (giữ nguyên) — mức chặt nhất, đảm bảo kết quả y như chạy tuần tự từng transaction một; phát hiện xung đột thì abort, bắt caller tự retryThe strictest isolation level — guarantees the result is equivalent to some serial (one-at-a-time) ordering of all concurrent transactions, and aborts a transaction with a serialization failure (Postgres SQLSTATE 40001) if it cannot guarantee that, leaving the retry to the caller.
referential actionreferential action (giữ nguyên) — quy tắc trên foreign key, quyết định dòng con bị ảnh hưởng thế nào khi dòng cha bị xóa/đổi keyA rule attached to a foreign key naming what Postgres should do to a child row when the parent row it references is deleted or its key changes — RESTRICT, CASCADE, SET NULL, or SET DEFAULT.
RESTRICTRESTRICT (giữ nguyên) — mặc định, Postgres từ chối xóa/đổi dòng cha nếu còn dòng con tham chiếuThe default referential action — Postgres refuses to delete or update a parent row while any child row still references it, returning a foreign_key_violation error instead.
CASCADECASCADE (giữ nguyên) — xóa dòng cha thì tự động xóa luôn mọi dòng con tham chiếu tới nóA referential action where deleting the parent row automatically deletes every child row that references it, in the same transaction.
SET NULLSET NULL (giữ nguyên) — xóa dòng cha thì cột FK ở dòng con tự chuyển thành NULL, dòng con vẫn cònA referential action where deleting the parent row sets the child row's foreign key column to NULL instead of deleting the child.
SET DEFAULTSET DEFAULT (giữ nguyên) — xóa dòng cha thì cột FK ở dòng con quay về giá trị DEFAULT đã khaiA referential action where deleting the parent row resets the child row's foreign key column to its declared DEFAULT value instead of NULL or deletion.
