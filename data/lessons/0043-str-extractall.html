str.extractall(): every match, not just the first

Lesson 42's own "Go deeper" link name-dropped two cousins of str.extract() as out of scope: str.extractall() (every match per row, not just the first) and str.findall(). Today closes the first of those two gaps — the tool for when a single cell can hold a variable number of matches, like tags jammed into one free-text field.

1 · The problem: str.extract() only ever gives you the first match

Lesson 42's str.extract() was built for "one column, several facts glued together" — a fixed number of pieces per row. But some columns hold a variable number of matches per row, and str.extract() quietly keeps only the first one:

orders = pd.DataFrame({
    "order_id": [1, 2, 3, 4],
    "customer": ["An", "Binh", "An", "Chi"],
    "notes": [
        "tags: urgent, gift",
        "tags: bulk",
        "tags: urgent, fragile, gift",
        "no tags here",
    ],
})
orders["notes"].str.extract(r"(?P<tag>urgent|gift|bulk|fragile)")
--      tag
-- 0  urgent
-- 1    bulk
-- 2  urgent   <- row 2 actually has THREE tags; only the first survived
-- 3     NaN

Row 2's "fragile" and "gift" vanished with no warning — str.extract() is fundamentally a one-match-per-row tool, by design (that's what makes the DataFrame-of-columns shape work). str.extractall() is the tool for exactly this shape: every match, per row, as its own result row.

2 · The MultiIndex: (original row, match number)

orders["notes"].str.extractall(r"(?P<tag>urgent|gift|bulk|fragile)")
--              tag
--   match
-- 0 0       urgent
--   1         gift
-- 1 0         bulk
-- 2 0       urgent
--   1      fragile
--   2         gift
-- (row 3, "no tags here", is absent entirely -- zero matches, zero result rows)

The result is always a DataFrame (never a Series, even with one capture group), indexed by a two-level MultiIndex (Lesson 14): the outer level is the original row's position, the inner level (named "match") numbers each match within that row starting at 0. Six matches across three matching rows become six result rows — this reshapes long, the same direction as Lesson 6's melt(), just driven by regex matches inside a cell instead of by column names.

Gotcha: a row with zero matches doesn't appear in the result at all — not as a row of NaN, the way str.extract() handles a non-match. Row 3 ("no tags here") is simply missing from the output above. Counting matches per original row therefore needs an explicit group-and-count step (next section) — a naive len(result) / len(orders) silently under-counts rows with zero matches as if they didn't exist.

3 · Counting matches per row: groupby on index level 0

The outer MultiIndex level is exactly the original row position, so grouping by it with groupby(level=0) answers "how many matches did each row get" — and reindexing that count back onto the original DataFrame (Lesson 33's set_index/.loc alignment idea) correctly gives row 3 a real 0, not a missing group:

matches = orders["notes"].str.extractall(r"(?P<tag>urgent|gift|bulk|fragile)")
tag_count = matches.groupby(level=0).size()
orders["tag_count"] = orders.index.map(tag_count).fillna(0).astype(int)
orders[["order_id", "notes", "tag_count"]]
--    order_id                         notes  tag_count
-- 0         1            tags: urgent, gift          2
-- 1         2                    tags: bulk          1
-- 2         3   tags: urgent, fragile, gift          3
-- 3         4                  no tags here          0   <- correctly 0, not dropped

.index.map(tag_count) looks up each of orders' own row labels in the tag_count Series (indexed by that same row-label level); a row with no matches has no entry to find, so map() returns NaN there — .fillna(0) turns "no entry found" into the correct real zero before the final astype(int) (Lesson 41).

4 · str.findall(): the lighter-weight sibling

str.findall() answers a similar question with a different shape: one list per row (Python's built-in list, not a reshaped DataFrame), empty when there's no match — closer in spirit to Lesson 19's explode() starting shape than to extractall()'s long MultiIndex table:

orders["notes"].str.findall(r"urgent|gift|bulk|fragile")
-- 0             [urgent, gift]
-- 1                     [bulk]
-- 2    [urgent, fragile, gift]
-- 3                         []   <- empty list, not NaN and not dropped
-- Name: notes, dtype: object

Rule of thumb: reach for findall() when the matches are staying together as one Python list per row (e.g. about to explode() them); reach for extractall() when the shape you actually want is a proper reshaped table — a real row per match, ready for groupby()/merge()/counting without an extra explode() step first. findall() also never names its matches (no (?P<name>...) column labeling); extractall() keeps that str.extract() feature.

5 · The SQL bridge: unnesting a regex, not a value

Lesson 19 bridged plain explode() (unnesting an actual list column) to Postgres' UNNEST(). str.extractall() is the same unnesting idea, but the "list" is implicit — every regex match inside a text cell, rather than an already-materialized array column:

-- Postgres has no single built-in for this shape; the closest is
-- regexp_matches(col, pattern, 'g') used inside a LATERAL join,
-- which itself returns a set (one row per match) that needs unnesting:
-- SELECT o.order_id, m.tag
-- FROM orders o, LATERAL regexp_matches(o.notes, '...', 'g') AS m(tag);
orders["notes"].str.extractall(r"(?P<tag>urgent|gift|bulk|fragile)")
-- one call, same reshaped-long result

Q: "A free-text column can contain zero, one, or several tags per row. How do you pull them out as structured data?" A strong answer, out loud: "str.extract() is out immediately — it only ever keeps the first match per row, so any row with two or more tags silently loses the rest with no warning. str.extractall() is the right tool: it returns every match as its own row, indexed by a MultiIndex of the original row position and a match number starting at 0. The gotcha I'd flag unprompted: a row with zero matches isn't in the result at all, not even as a NaN row — so counting matches per original row needs groupby(level=0).size(), then mapping that back onto the original index and filling missing entries with 0, or rows with no matches silently disappear from the count instead of correctly reading as zero. If I just need the matches as a Python list per row rather than a reshaped table — say, right before an explode() — str.findall() is the lighter option, since it returns an empty list instead of dropping the row." The signal: naming the MultiIndex shape, the zero-match-row gotcha, and the explicit findall() alternative without being prompted for any of the three.
