str.replace(): rewriting text in place, and its flipped regex= default

Chào bạn — Lesson 76 closed the str.split() gap and named today's topic explicitly: the last uncovered core .str accessor method, str.replace(). It rewrites text rather than breaking it apart or filtering it, and it hides a real trap of its own — one that runs the OPPOSITE direction from Lesson 60's str.contains() gotcha.

1 · The basic swap: one substring for another, every occurrence

.str.replace(pat, repl) swaps every occurrence of pat for repl across a whole column in one vectorized call:

orders["sku_path"]
# 0      ELEC/PHONE/CASE-01
# 1     HOME/KITCHEN/MUG-02
# ...
orders["sku_path"].str.replace("/", "-")
# 0      ELEC-PHONE-CASE-01
# 1     HOME-KITCHEN-MUG-02
# ...  -- every "/" swapped, dtype stays str, original column untouched

Confirmed directly (pandas 3.0.6): the call returns a new Series — orders["sku_path"] itself is unchanged unless the result is assigned back, e.g. orders["sku_path"] = orders["sku_path"].str.replace(...). Same non-mutating habit as every other .str method taught so far (split(), contains(), extract()).

2 · The flipped default: regex=False here, the opposite of str.contains()

Lesson 60 confirmed str.contains() treats its pattern as a regex BY DEFAULT — a bare "." silently means "any character" unless regex=False is passed. str.replace() runs the opposite direction:

skus = pd.Series(["A.1", "A21", "B.5"])
skus.str.replace("A.", "X")                # 0  X1    1  A21   2  B.5   -- literal dot, "A21" untouched
skus.str.replace("A.", "X", regex=True)     # 0  X1    1  X1    2  B.5   -- "." now means ANY char, "A21" matches too

Confirmed directly by inspecting the method's own signature (regex: bool = False) and running both calls: str.replace() defaults to a LITERAL substring match, regex=False. Passing a genuine regex pattern (capture groups, character classes, anchors) without flipping regex=True either does nothing useful or raises, depending on the pattern — the pattern is only ever treated as regex on purpose here.

Remember this contrast, not just the two facts: str.contains() defaults to regex=True (Lesson 60) — a plain-looking pattern can silently over-match. str.replace() defaults to regex=False (today) — a pattern meant as regex silently under-matches or errors instead. Same library, same .str family, opposite defaults; naming which one applies to the method actually in front of you, unprompted, is the interview-grade move.

3 · regex=True unlocks capture groups and backreferences

With regex=True, repl can reference capture groups from pat using \1, \2, etc. — the same backreference syntax as re.sub():

orders["price_note"]
# 0    price: $19.99
# 1     price: $8.50
# ...
orders["price_note"].str.replace(r"\$(\d+\.\d+)", r"USD \1", regex=True)
# 0    price: USD 19.99
# 1     price: USD 8.50
# ...  -- the captured digits reinserted after "USD ", dollar sign dropped

Confirmed directly: the capture group (\d+\.\d+) grabs the numeric amount, and \1 in repl reinserts exactly that captured text — the same mental model as str.extract()'s capture groups (Lessons 42/43), but here the captured piece gets rewoven into a new string instead of pulled out into its own column.

4 · n= caps the replacement count; NaN passes through untouched

n= limits how many occurrences get replaced per string (default -1, meaning "all of them") — and exactly like every other .str method, a missing value in the source column stays missing rather than raising or becoming a literal "NaN" string:

s = pd.Series(["a-b-c-d", "x-y-z"])
s.str.replace("-", "_", n=1)   # 0  a_b-c-d   1  x_y-z   -- only the FIRST "-" per string swapped

orders["customer_full"].str.replace("-", " ")
# 0    An Nguyen North
# ...
# 4                NaN   -- the missing row stays NaN, never becomes the string "NaN"

Confirmed directly: n=1 stops after the first match per row, leaving the rest of that string's separators untouched — same capping idea as str.split()'s own n= (Lesson 76), just applied to replacement count instead of split count. The NaN passthrough was confirmed directly with pd.isna() on the one missing customer_full row from this course's running fixture.

SQL bridge: str.replace(pat, repl, regex=False) is Postgres's replace(column, pat, repl) — literal substring swap, no regex involved on either side. str.replace(pat, repl, regex=True) with backreferences is the pandas spelling of Postgres's regexp_replace(column, pat, repl) (add 'g' as the flag argument in Postgres for "replace all," matching pandas' default n=-1; Postgres without 'g' replaces only the first match, matching pandas' n=1).

Q: "You call `.str.replace('.', '_')` on a column expecting every literal dot to become an underscore, but it does something unexpected. What's going on?" A strong answer, out loud: "Actually str.replace() defaults to regex=False, so a plain dot IS treated literally here — this one wouldn't have the bug. The trap runs the other way: if I pass a pattern that's actually regex-special, like a plus sign or parentheses, meaning it as a literal character, regex=False still treats it literally and I'm fine. Where I'd get burned is the opposite case — reaching for str.replace() assuming it behaves like str.contains(), which defaults to regex=True. I'd double check which method I'm actually calling and what its own default is, rather than assuming the whole .str family shares one regex default." The signal: knowing the two defaults point opposite directions, and not assuming consistency across a method family without checking.
