np.repeat() and np.tile(): two different ways to multiply an array, and why broadcasting usually beats both

Lesson 94's teaser named two open runner-ups and picked neither as THE next pick, so today ran a fresh gap scan: np.repeat()/np.tile()/np.broadcast_to() and DataFrame.insert()/.pop() both came back as genuine zero-coverage gaps again. This lesson takes the NumPy pair — it closes a real loose end from Lesson 30's broadcasting lesson (that lesson explained the implicit, no-copy "stretching" NumPy does automatically; today covers the two functions you reach for when you need an actual materialized repeated array instead, e.g. building a cartesian test grid or fixture data).

1 · repeat(): each element repeated in place

np.repeat() repeats each element of the input in place, right where it sits. Confirmed directly (numpy 2.5.4): with no axis=, it flattens first (same flatten-then-index idea as Lesson 93's np.argmax()), then repeats each flattened scalar:

import numpy as np
arr = np.array([10, 20, 30])
np.repeat(arr, 3)
# [10 10 10 20 20 20 30 30 30]   -- each value repeated 3x in place

repeats can also be an array, one count per element, confirmed directly to raise ValueError if its length doesn't match the axis being repeated along:

np.repeat(arr, [1, 2, 3])
# [10 20 20 30 30 30]   -- 10 once, 20 twice, 30 three times
np.repeat(arr, [1, 2])
# ValueError: operands could not be broadcast together with shape (3,) (2,)

On a 2D array, axis=0 repeats whole rows; axis=1 repeats whole columns — confirmed directly, each row/column stays intact, unlike the no-axis default, which flattens everything first:

grid = np.array([[1, 2], [3, 4]])
np.repeat(grid, 2, axis=0)
# [[1 2]
#  [1 2]
#  [3 4]
#  [3 4]]        -- each ROW doubled

2 · tile(): the whole array repeated as a block

np.tile() repeats the entire array as one repeating block, confirmed directly to produce a visibly different result from repeat() on the exact same input:

np.repeat(arr, 3)
# [10 10 10 20 20 20 30 30 30]   -- repeat: each element's own 3 copies, grouped
np.tile(arr, 3)
# [10 20 30 10 20 30 10 20 30]   -- tile: the whole [10 20 30] block, 3 times

On a 2D array, reps is a tuple — one repetition count per axis — confirmed directly, (2, 1) stacks two full copies vertically, (1, 2) lays two full copies side by side:

np.tile(grid, (2, 1))
# [[1 2]
#  [3 4]
#  [1 2]           -- the WHOLE 2x2 block, repeated twice downward
#  [3 4]]

Confirmed directly (via the official NumPy docs, fetched this round): both functions always return a brand-new array — mutating the result never touches the original input, unlike a view.

3 · The real use: building a test grid, and why broadcasting usually wins instead

Pairing the two builds a cartesian grid without pd.merge(how="cross") (Lesson 92) — useful for constructing fixture/test data directly, e.g. every customer against every date:

import pandas as pd
customers = np.array(["An", "Binh"])
dates = pd.date_range("2026-01-01", periods=3, freq="D")
grid = pd.DataFrame({
    "customer": np.repeat(customers, len(dates)),  # each name, 3x in a row
    "date":     np.tile(dates, len(customers)),     # the whole 3-date block, 2x
})
#   customer       date
#0        An 2026-01-01
#1        An 2026-01-02
#2        An 2026-01-03
#3      Binh 2026-01-01
#4      Binh 2026-01-02
#5      Binh 2026-01-03

But for Lesson 30's actual day-to-day case — applying one smaller array across a bigger one in arithmetic — materializing a repeated copy with tile() is the wrong tool: broadcasting already does the same job without allocating the extra memory. The NumPy docs themselves say this outright (fetched this round, quoted verbatim): "it is strongly recommended to use NumPy's broadcasting operations and functions" instead of tile() for that case. Confirmed directly — the two approaches give the identical number, but tile() actually builds the repeated array in memory first:

# materialized (wasteful for plain arithmetic):
scale = np.tile([1.1], len(arr))
arr * scale
# [11. 22. 33.]

# broadcast (Lesson 30's mechanism -- no extra array ever built):
arr * 1.1
# [11. 22. 33.]   -- same numbers, no materialized copy

The takeaway to say out loud: reach for repeat()/tile() when you need an actual longer array to exist (building test fixtures, a cartesian grid, a lookup column) — reach for broadcasting when you're just doing arithmetic between mismatched shapes, which is almost always the pandas case.

Q: "What's the difference between np.repeat() and np.tile(), and when would you actually reach for either over plain broadcasting?" A strong answer, out loud: "repeat() repeats each element in place — [10, 20] with repeat 2 becomes [10, 10, 20, 20]. tile() repeats the whole array as one block — the same input becomes [10, 20, 10, 20]. I'd reach for either when I need a real, materialized longer array to exist — building a cartesian test grid, like every customer paired with every date, using repeat() on one side and tile() on the other. But for ordinary arithmetic between a smaller and a larger shape, I wouldn't use either — that's exactly what broadcasting already does for free, without allocating the extra copy, and the NumPy docs themselves say to prefer broadcasting over tile() for that case." The signal: naming the granularity difference correctly from memory, plus knowing broadcasting is usually the better tool for the arithmetic case specifically.
