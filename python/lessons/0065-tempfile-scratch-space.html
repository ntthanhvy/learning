1 · The problem: scratch space that has to be cleaned up by hand is scratch space that leaks

A pipeline that stages a downloaded file, extracts a zip (Day 64) to inspect it, or writes an intermediate CSV before the final aggregation all need somewhere to put files that should not outlive the run. The naive approach — pick a path under /tmp, write to it, delete it at the end — has two real problems: a hardcoded name collides if two runs happen at once, and the cleanup step gets skipped entirely if an exception fires before reaching it. tempfile solves both: every name it hands out is guaranteed unique even under concurrent runs, and its directory/file objects are context managers (Day 6) that delete themselves on the way out of a with block — success or exception, same as every other context manager this course has taught.

2 · A temporary directory: TemporaryDirectory()

import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as tmp_dir:
    tmp_path = Path(tmp_dir)
    (tmp_path / "staged.csv").write_text("id,amount\n1,10\n")
    # ... read it back, pass it to another function, whatever the step needs ...
# by here, tmp_dir and everything written inside it are already gone

TemporaryDirectory() creates a brand-new, uniquely named directory and returns its path as a string; wrapping it in with means the entire directory — and everything written inside it, no matter how deeply nested — is deleted the moment the block exits, exactly the way Day 62's rmtree() deletes a tree by hand, except nothing has to remember to call it. This is the exact pattern Day 64's path-traversal callout implies but never spells out: extracting an untrusted zip into a TemporaryDirectory() rather than a permanent location means a bad archive's mess disappears automatically when the with block ends, instead of littering a real directory.

3 · A temporary file: NamedTemporaryFile()

import tempfile

with tempfile.NamedTemporaryFile(mode="w", suffix=".csv", delete=False) as f:
    f.write("id,amount\n1,10\n")
    staged_path = f.name   # a real path on disk, usable by another process/library
# file is closed but NOT deleted yet, because delete=False was passed
# ... hand staged_path to something that reopens it by path ...

NamedTemporaryFile() behaves like open() (Day 6) — same mode, same file-object methods — but with a guaranteed-unique name and, by default, automatic deletion as soon as it closes. The delete=False flag is the one detail worth being deliberate about: some libraries insist on reopening a file by its path rather than accepting an already-open file object, and on some platforms an open file can't be reopened by another handle while still open. Passing delete=False defers cleanup to the caller — meaning that path must be deleted manually later, usually with Path(staged_path).unlink(), or the "cleans itself up" benefit is lost entirely.

Default to TemporaryDirectory() over NamedTemporaryFile(delete=False): a directory can hold one file or fifty, needs no per-file cleanup bookkeeping, and the automatic deletion is never opted out of. Reach for NamedTemporaryFile() only when something specifically needs one single named file path rather than a whole scratch directory.

4 · Why this isn't just "pick a path under /tmp"

tempfile never guesses a fixed name like /tmp/staging — it asks the operating system for the correct temp location (respecting TMPDIR if set) and generates a random, collision-proof name every time. Two pipeline runs started at once, or a retried run after a crash, never fight over the same path the way two hardcoded /tmp/staging runs would. This is the same "don't hand-roll what the standard library already gets right safely" lesson as Day 59's hashlib for content fingerprints or Day 1's garbage collection — uniqueness and cleanup are solved problems, not something to reinvent per script.

Where pandas goes from here: nothing pandas-specific today — pandas.read_csv()/to_csv() happily accept any path, including one inside a TemporaryDirectory(), but pandas has no opinion on where that scratch space comes from or how it gets cleaned up; that staging decision is this module's job in any pipeline, pandas-backed or not.
