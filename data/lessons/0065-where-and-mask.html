Series.where() and .mask(): conditional replace that keeps the shape

Lesson 64 closed out its own named candidate with no fresh teaser pointing anywhere specific, so today started from a from-scratch scan of every lesson and the full glossary against MISSION.md's goals. Lesson 24 taught np.where()/np.select() as NumPy's vectorized if/else — but pandas has its own condition-preserving pair, Series.where() and .mask(), and a grep of all 64 lessons and the glossary turned up zero hits for either as a DataFrame/Series method (only prose mentions of the unrelated np.where()). That's a real gap: .where()/.mask() read more naturally than np.where() once only ONE branch needs to change, and they're the tool that makes "replace values failing a check with NaN" a one-liner instead of a full np.where(cond, keep, other) call.

1 · The shape: keep-if-true, replace-if-false

where() keeps every value where a condition is True and replaces the rest with other (a NaN by default):

s = clean["amount"]
s.tolist()                    # [120.0, 42.0, 35.5, 180.0]

s.where(s >= 100)              # no `other` -- default fill is NaN
-- [120.0, NaN, NaN, 180.0]

s.where(s >= 100, other=0)     # explicit fill
-- [120.0, 0.0, 0.0, 180.0]

mask() is where()'s exact mirror image — same two arguments, opposite polarity:

s.mask(s >= 100, other=0)      # replace where TRUE this time
-- [0.0, 42.0, 35.5, 0.0]

# confirmed identical to negating the condition and swapping methods:
s.mask(s >= 100, 0).equals(s.where(~(s >= 100), 0))   # True

Confirmed directly (pandas 3.0.5) on the real orders_raw.csv clean 4-row slice above. Neither method filters rows out — the Series/DataFrame keeps its original length and index; only the failing cells change. That's the core difference from a boolean mask used to filter (s[s >= 100], Lesson 1's WHERE), which does drop rows.

2 · SQL bridge

where()/mask() are the pandas spelling of a single-branch CASE WHEN col >= 100 THEN col ELSE 0 END (that's where) or its flip, CASE WHEN col >= 100 THEN 0 ELSE col END (that's mask). Lesson 24's np.where(cond, a, b) covers the same ground but always needs both branches spelled out explicitly; where()/mask() read better the moment one branch is simply "keep what's already there" — no need to repeat the column as its own true-branch value.

3 · Chaining for more than one condition

Lesson 24's np.select() handles 3+ branches in one call with parallel condition/choice lists. where()/mask() have no multi-branch form of their own, but they chain cleanly, applying one condition at a time on top of the previous result:

tier = pd.Series("Mid", index=s.index)
tier = tier.mask(s >= 150, "High").mask(s < 50, "Low")
tier.tolist()                 # ['Mid', 'Low', 'Low', 'High']

# confirmed identical to np.select() on the same data:
np.select([s >= 150, s < 50], ["High", "Low"], default="Mid")
-- ['Mid', 'Low', 'Low', 'High']

Confirmed directly: both approaches land on the identical result. np.select() is the better read once there are three or more genuinely independent branches sharing one default; chained mask() calls read more like "start from a baseline, then override" — closer to how the logic is usually described out loud.

Gotcha, confirmed directly: a shorter/misaligned condition doesn't raise. where()/mask() align the condition to the caller's index first, exactly like every other pandas operation (Lesson 30's broadcasting note on label alignment). Passing a condition covering only the first two rows doesn't error — it silently treats every unmatched row as failing, filling it with other (or NaN):

s.where(s.iloc[:2] >= 100)
-- [120.0, NaN, NaN, NaN]   <- rows 2-3 have no aligned condition at all, NOT an error

Row 1 (42.0) correctly fails the condition and becomes NaN — but rows 2-3 become NaN too, for a completely different reason: there was no condition value for them to check at all. Same output, two different causes, no exception either way. Always confirm cond.index.equals(s.index) before trusting a where()/mask() result on anything but the exact same Series the condition was built from.

4 · DataFrame.where(): cell by cell, not row by row

Called on a whole DataFrame, where()/mask() check the condition cell by cell (or align a Series condition along axis=0/axis=1 first), not row by row:

clean.where(clean["amount"] >= 100, other="LOW")
-- order_id customer amount  order_date
--        1       An  120.0  2026-01-05   <- whole row passed its own check
--      LOW      LOW    LOW         LOW   <- every OTHER column got "LOW" too
--      LOW      LOW    LOW         LOW      even order_id and customer, untouched by amount
--        5     Binh  180.0  2026-01-09

Confirmed directly: the condition clean["amount"] >= 100 is a Series, so pandas broadcasts it across every column of that row (default axis=0) — meaning a row that fails on amount gets EVERY column replaced with "LOW", including order_id and customer, which had nothing to do with the check. This is rarely what's wanted; the fix that keeps other columns untouched is assigning back into just the target column with .loc[] or plain boolean-mask assignment (Lesson 1/26) instead of calling where() on the whole frame.

Q: "What's the difference between Series.where() and np.where(), and when would you reach for each?" A strong answer, out loud: "Both are vectorized if/else with no per-row Python loop, but the argument shape is different. np.where(cond, a, b) always needs both branches spelled out explicitly. Series.where(cond, other) assumes the branch that's already there is the true-case value and only asks for the replacement — so it reads better the moment one branch is just 'keep the original.' mask() is where()'s exact opposite polarity, same two arguments. Neither one filters rows out — they keep the original shape and index, only replacing the failing cells, which is the key difference from a boolean mask used to filter rows out entirely. One thing I'd watch for: the condition aligns to the caller's index first, so a condition that's missing some of the caller's rows doesn't error, it silently treats those rows as failing — I'd always check the two indexes match before trusting the result. For 3+ branches I'd reach for np.select() instead of chaining mask() calls, since it names every branch and its default in one call rather than a sequence of overrides." The signal: naming the argument-shape difference from np.where(), the shape-preserving behavior vs. a filtering mask, and the index-alignment gotcha unprompted.

5 · Where this fits

Lesson 24's np.where()/np.select(), Lesson 35's clip(), and today's where()/mask() are three different named shortcuts for the same underlying idea — a vectorized per-cell if/else — each best for a different shape of condition: clip() for "pull outliers back inside a range," np.select() for "3+ independent branches with one default," and where()/mask() for "keep what's there, replace only the failing cells" — the most common shape of all three once the check is a data-quality filter rather than a recode.
