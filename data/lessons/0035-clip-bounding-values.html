clip(): capping values into a min/max range, vectorized

Lesson 34's teaser named three genuinely-uncovered candidates (confirmed by grep before writing): clip(), between(), and combine_first(). Picked clip(): it's the highest interview-frequency of the three — capping outliers or enforcing a valid range is a routine cleaning step, and it's a clean vectorized answer to a per-row if/else people otherwise reach for apply() or nested np.where() for (Lessons 12 and 24).

1 · The problem: values outside a valid or sane range

Real data has outliers and typos that survive type conversion — a sensor misfire, a fat-fingered extra digit, a discount that should never exceed 100%. Sometimes the fix isn't to drop the row (Lesson 3) or flag it, but to cap it: keep the row, just pull its value back inside a known-valid range. clip() does exactly this in one vectorized call, no loop and no np.where() nesting required.

On this course's cleaned 4-row slice (An 120.0/01-05, An 42.0/01-10, Binh 35.5/01-06, Binh 180.0/01-09):

clean["amount"]
# 0    120.0
# 1     42.0
# 2     35.5
# 3    180.0

2 · clip(lower=, upper=): both bounds at once

clean["amount"].clip(lower=50, upper=150)
# 0    120.0   # already inside [50, 150] -- untouched
# 1     50.0   # 42.0 was below 50 -- pulled up to 50
# 2     50.0   # 35.5 was below 50 -- pulled up to 50
# 3    150.0   # 180.0 was above 150 -- pulled down to 150

Every value inside [lower, upper] passes through unchanged; anything below lower becomes exactly lower, anything above upper becomes exactly upper. Either bound is optional — pass only lower= to floor values with no ceiling, or only upper= to cap values with no floor:

clean["amount"].clip(lower=50)   # [120.0, 50.0, 50.0, 180.0] -- 180.0 untouched, no upper bound given
clean["amount"].clip(upper=100)  # [100.0, 42.0, 35.5, 100.0] -- 42.0/35.5 untouched, no lower bound given

3 · The vectorized answer to a per-row if/else you'd otherwise nest

Written by hand, the same logic is a nested np.where() (Lesson 24) or an apply() (Lesson 12) — clip() is the named, one-call shortcut for exactly this shape: np.where(x < lower, lower, np.where(x > upper, upper, x)), hand-verified on this slice to produce the identical result [120.0, 50.0, 50.0, 150.0] as Section 2's clip(lower=50, upper=150). SQL cousin: GREATEST(lower, LEAST(upper, col)) — the same "clamp between two bounds" idea, just spelled as nested built-ins instead of one named function.

4 · Per-row bounds: lower/upper can be a Series too

lower=/upper= don't have to be a single scalar — passing a same-length Series clips each row against its OWN bound, aligned by position:

amounts = clean["amount"].reset_index(drop=True)   # [120.0, 42.0, 35.5, 180.0]
row_floor = pd.Series([100, 40, 50, 40])
amounts.clip(lower=row_floor)
# 0    120.0   # 120.0 >= 100 -- untouched
# 1     42.0   # 42.0 >= 40 -- untouched
# 2     50.0   # 35.5 < 50 -- pulled up to that row's own floor, 50
# 3    180.0   # 180.0 >= 40 -- untouched

This is the shape a "cap this column at each row's group-specific limit" task takes — pair it with Lesson 16's transform() to build a per-group bound Series first, then clip() against it in one more call.

5 · DataFrame-wide clip()

Called directly on a DataFrame (not just one Series), clip() applies the same bounds to every numeric column at once:

df2 = pd.DataFrame({"a": [1, 5, 10], "b": [100, 5, -3]})
df2.clip(lower=0, upper=8)
#    a  b
# 0  1  8
# 1  5  5
# 2  8  0

Column a's 10 is capped to 8; column b's 100 is also capped to 8 and its -3 floored to 0 — the same [0, 8] bounds applied independently, column by column.

6 · The gotcha: NaN passes straight through, untouched and unflagged

Continuing this course's "no crash, quietly wrong" family since Lesson 19: clip() does not raise and does not fill a NaN with a bound — a missing value simply stays NaN, invisible in the clipped output unless checked for separately:

s = pd.Series([10.0, np.nan, 200.0])
s.clip(lower=50, upper=150)
# 0     50.0
# 1      NaN   # still NaN -- clip() never touches missing values
# 2    150.0

If a pipeline's next step assumes "every value is now inside [lower, upper]," a leftover NaN silently breaks that assumption. Same reflex as every gotcha since Lesson 19: check .isna().sum() before and after, don't assume clip() also cleaned missing data — it's a bounding step, not a fillna().

Q: "How would you cap outlier values in a column without dropping the rows?" A strong answer, out loud: "clip(lower=, upper=) — every value below the lower bound gets pulled up to it, every value above the upper bound gets pulled down to it, everything already inside the range passes through untouched. It's the vectorized version of a nested np.where, or GREATEST/LEAST in SQL. Either bound is optional, and both lower and upper can be a Series instead of a scalar, so I can clip each row against its own per-row or per-group limit. One thing to watch: clip() doesn't touch NaN at all — a missing value stays missing, it's not a substitute for fillna()." The signal: naming the per-row-bound capability and the NaN-passthrough gotcha unprompted, not just describing the two-bound mechanic.
