Data Pipelines · Reference

Glossary

Every jargon term used in the lessons, in one place, grouped by the lesson that introduced it. The Tiếng Việt column is dev-style: how Vietnamese data engineers actually say it, not a textbook translation.

Day 1 — The pipeline map & the repo

TermTiếng Việt (dev-style)In software
pipelinegiữ nguyên "pipeline" — chuỗi bước tự động di chuyển/biến đổi dữ liệuA scheduled, repeatable sequence of steps that moves and transforms data from a source to somewhere it can be used — the umbrella term for the whole thing this course builds.
ETLgiữ nguyên "ETL" — biến đổi TRƯỚC khi load vào đíchExtract, Transform, Load — data is transformed in a separate processing engine before it ever reaches the destination, so the destination only ever sees clean, final-shaped data.
ELTgiữ nguyên "ELT" — load THÔ trước, biến đổi SAU ngay trong warehouseExtract, Load, Transform — raw data is loaded into the destination first, untransformed, and transformation happens afterward inside that same destination using its own compute. This course's approach; dbt is the T.
raw layergiữ nguyên "raw layer" — dữ liệu thô, y nguyên lúc mới vào, chưa xử lý gìThe schema holding data exactly as it arrived from its source, before any cleaning or reshaping — the permanent, replayable starting point every transformation can be re-run from.
dbtgiữ nguyên "dbt" — công cụ biến đổi dữ liệu bằng SQL, chạy ngay trong warehouseA SQL-based transformation tool: you write SELECT statements, it compiles and runs them inside the warehouse, tracks which model depends on which via ref(), and can test the results — the T in this course's ELT.
Kafkagiữ nguyên "Kafka" — hệ thống log phân tán, nhận sự kiện liên tục theo thời gian thựcA distributed append-only log system: producers write events to topics, consumers read them in order, and it's built for continuously arriving data rather than periodic batches.
Airflowgiữ nguyên "Airflow" — công cụ lập lịch và điều phối, tự nó không xử lý dữ liệuA scheduler and orchestrator: it runs a defined sequence of tasks (a DAG) on a schedule, retries failures, and tracks whether each run succeeded — it does not transform or move data itself, it triggers the tools that do.
idempotentgiữ nguyên "idempotent" — làm 1 lần hay N lần, kết quả như nhauAn operation that produces the same end state whether performed once or many times — safe to retry blindly, which matters wherever a step might run twice. Same idea as backend/'s idempotency keys, applied to a pipeline.

Day 2 — dbt: sources, staging & ref()

TermTiếng Việt (dev-style)In software
dbt modelgiữ nguyên "dbt model" — 1 file .sql chứa 1 câu SELECT, dbt biên dịch và chạy để tạo ra 1 view/tableA single dbt model — one .sql file containing one SELECT statement, compiled and run by dbt, that produces one view or table in the warehouse.
DAGgiữ nguyên "DAG" — sơ đồ phụ thuộc dbt tự dựng từ ref()/source(), quyết định thứ tự buildThe directed acyclic graph dbt builds from every ref() and source() call in a project — which model depends on which, and therefore the only valid build order.
staginggiữ nguyên "staging" — lớp model đầu tiên trên raw, mỗi model ứng với 1 bảng nguồn, chỉ dọn nhẹ, không joinThe dbt layer immediately above raw sources — one model per source table, doing only light cleanup (renaming, casting, light derivations), never joining across sources.
sourcegiữ nguyên "source" — khai báo trỏ tới bảng raw có sẵn, model gọi qua source() thay vì viết tên schema.table cứngA dbt-declared pointer at a raw table that already exists in the warehouse (not built by dbt) — lets models reference it via source() instead of a hardcoded schema.table name, and is what freshness checks attach to.
materializationgiữ nguyên "materialization" — cách SELECT của model biến thành đối tượng trong warehouse: view, table, hay incrementaldbt's setting for how a model's SELECT becomes warehouse objects — view (query re-runs every time it's read, always fresh, no storage), table (query runs once at build time, stored, stale until next run), or incremental (Day 4).
viewgiữ nguyên "view" — dbt bọc SELECT trong CREATE VIEW, không lưu dữ liệu, luôn mới nhấtA materialization where dbt wraps the SELECT in CREATE VIEW — no data is stored, the query re-runs on every read, always reflects current raw data, cheapest to build.

Day 3 — dbt: tests catch bad data

TermTiếng Việt (dev-style)In software
data testgiữ nguyên "data test" — phép kiểm tra dbt chạy trên dữ liệu thật, query trả về hàng nào là fail hàng đóA dbt-run assertion against real warehouse data, expressed as a query — it fails if the query returns any rows, and runs alongside models via dbt build.
generic testgiữ nguyên "generic test" — test dùng lại được, khai báo trong YAML, áp cho cột nào cũng đượcA reusable, parameterized dbt test defined once (built into dbt or a package) and applied to any column via YAML — not_null, unique, relationships and accepted_values are the four that ship with dbt itself.
relationships testgiữ nguyên "relationships test" — kiểm tra khóa ngoại, giá trị cột này phải tồn tại ở cột kiaA generic dbt test asserting that every value in a column exists as a value in another model or source's column — the relational-integrity check, e.g. every stg_orders.restaurant_id must exist in stg_restaurants.restaurant_id.
not_null testgiữ nguyên "not_null test" — kiểm tra cột không có giá trị NULLA generic dbt test asserting every value in a column is non-NULL.
unique testgiữ nguyên "unique test" — kiểm tra cột không có giá trị trùngA generic dbt test asserting every value in a column is distinct — no duplicates.
singular testgiữ nguyên "singular test" — test viết riêng bằng 1 file .sql trong tests/, không dùng lại được cho cột khácA one-off dbt test written as a single .sql SELECT file in tests/ — fails if the query returns any rows, for a business rule too specific to express as a generic test.
source freshnessgiữ nguyên "source freshness" — kiểm tra dữ liệu nguồn có bị cũ/trễ không, dựa vào cột thời gianA dbt check on a source's timestamp column comparing its most recent value to now — warns or errors if the data is older than a configured threshold, catching a stalled loader before anyone notices missing rows.
loaded_at_fieldgiữ nguyên "loaded_at_field" — tên cột thời gian dùng để tính độ mới của dữ liệuThe sources.yml field naming which timestamp column freshness should read from — required for any source with a freshness block configured.

Day 4 — dbt: marts, facts, dimensions & incremental

TermTiếng Việt (dev-style)In software
martgiữ nguyên "mart" — lớp model trên cùng, join nhiều staging model lại thành bảng người dùng cuối thực sự truy vấnThe dbt layer built on top of staging, joining across staging models into the shapes a dashboard, analyst or downstream consumer actually queries — the layer this course's headline tables (fct_orders, dim_restaurants, dim_couriers, mart_delivery_sla) live in.
fact tablegiữ nguyên "fact table" — 1 dòng/sự kiện, chứa khóa ngoại tới dimension và các số liệu để tính tổng/trung bìnhA mart table holding one row per business event, at a fixed grain, with foreign keys to its dimensions and the numeric measures analysts aggregate — fct_orders is one row per order, the event this whole pipeline exists to track.
dimension tablegiữ nguyên "dimension table" — 1 dòng/thực thể, chứa các thuộc tính để filter hoặc group byA mart table holding one row per real-world entity, with the descriptive attributes people filter or group by — dim_restaurants is one row per restaurant, the entity orders reference by foreign key.
graingiữ nguyên "grain" — mức chi tiết 1 dòng đại diện, phải nói rõ ràng (ví dụ "mỗi dòng = 1 order")The level of detail one row of a table represents — stating it explicitly (e.g. "one row per order") is what lets anyone check a model is right without reading its SQL.
table (materialization)giữ nguyên "table" — dbt lưu kết quả SELECT thành bảng thật, đọc nhanh hơn view nhưng phải build lại mới cập nhậtA materialization where dbt runs the SELECT once at build time and stores the result as a real table — faster to query than a view, but stale until the next dbt run rebuilds it from scratch.
incremental modelgiữ nguyên "incremental model" — sau lần build đầu, dbt chỉ xử lý dòng mới/thay đổi, không build lại toàn bộA materialization where, after the first build, dbt only processes new or changed rows instead of rebuilding the whole table from scratch — the right default for a large, append-heavy table where reprocessing everything every run wastes time.
