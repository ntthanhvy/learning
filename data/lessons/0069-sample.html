sample(): random rows, reproducibly

1 · The basics: how many rows, and can you get them again

sample() returns a random subset of rows — pass n= for an exact count, or frac= for a fraction of the whole. Confirmed directly (pandas 3.0.5) on the same cleaned orders_raw.csv fixture recent lessons use (An 120.0/01-05, An 42.0/01-10, Binh 35.5/01-06, Binh 180.0/01-09):

clean.sample(n=2, random_state=0)
#    order_id customer  amount order_date
#           2     Binh    35.5 2026-01-06
#           5     Binh   180.0 2026-01-09

clean.sample(n=2, random_state=0)  # same random_state -- IDENTICAL rows again
#    order_id customer  amount order_date
#           2     Binh    35.5 2026-01-06
#           5     Binh   180.0 2026-01-09

Confirmed directly: with no random_state= at all, two calls generally return different rows (each a genuine fresh draw); with the SAME integer random_state=, two separate calls return byte-identical output — .equals() confirmed True across separate calls with random_state=42. This is the single habit that turns "random" into "reproducible": always pin random_state= in a script, a notebook, or a test fixture, so a teammate re-running the same code gets the same sample, not a different one each time.

SQL bridge: the closest SQL equivalent is ORDER BY RANDOM() LIMIT n (Postgres) or TABLESAMPLE — but neither has a built-in, portable seed the way random_state= does; reproducing an exact SQL random sample usually means hand-rolling a seeded PRNG function. sample()'s random_state= makes "the same random sample twice" a one-argument guarantee.

2 · n= and frac= are mutually exclusive, and rows keep their original index

Passing both raises immediately rather than silently picking one — confirmed directly:

clean.sample(n=2, frac=0.5)
# ValueError: Please enter a value for `frac` OR `n`, not both

And sampled rows keep their ORIGINAL index labels, not a fresh 0..n-1 range — confirmed directly, clean.sample(n=2, random_state=0).index.tolist() comes back [2, 3], the same row labels those rows had in clean, not [0, 1]. Chain .reset_index(drop=True) afterward if a clean sequential index is needed downstream — the same habit as after any row-dropping operation (Lesson 3).

3 · replace=True: sampling with repeats, and oversampling past the row count

By default replace=False — each row can appear at most once, and asking for more rows than exist raises rather than silently capping:

clean.sample(n=10)  # clean only has 4 rows
# ValueError: Cannot take a larger sample than population when 'replace=False'

clean.sample(n=10, replace=True, random_state=0)  # works -- rows repeat
# same row (order_id 5, Binh/180.0) appears 5 separate times in the 10

Confirmed directly: with replace=True, the output can and does contain the same row label more than once — .index.duplicated().any() came back True on a 10-row draw from the 4-row fixture. This is the standard tool for bootstrap resampling (draw-with-replacement, a common statistics/ML-adjacent interview mention) — without replace=True, oversampling past the available row count is a hard error, not a silent shrink.

4 · Two sharper tools: weights=, and stratified sampling via groupby()

weights= accepts a column (or array) of relative likelihoods — a row with a bigger weight is proportionally more likely to be drawn, confirmed directly by passing the amount column itself as weights and observing the higher-amount rows come up more often across repeated seeded draws. More interview-relevant: .sample() composes with groupby() for STRATIFIED sampling — one (or n=) random row per group, instead of a purely global random draw that could accidentally skip a whole customer:

clean.groupby("customer", group_keys=False).sample(n=1, random_state=0)
#    order_id customer  amount order_date
#           6       An    42.0 2026-01-10
#           2     Binh    35.5 2026-01-06

Confirmed directly: exactly one row per customer group came back, chosen independently within each group — the random draw for An's two candidate rows and Binh's two candidate rows happen separately, so neither customer can be shut out the way a single global clean.sample(n=2) could (by chance) return two rows from the same customer and zero from the other. group_keys=False keeps the result's index as the original row labels rather than adding an extra grouping-key index level on top — the same flag groupby().apply() uses (Lesson 61) for the analogous reason.

Q: "How would you take a reproducible random sample of a DataFrame, and how would you make sure every category is represented?" A strong answer, out loud: "sample(n=...) or sample(frac=...) draws a random subset — never both together, that raises ValueError. The reproducibility part is random_state=: pin it to any integer and the exact same rows come back on every re-run, which matters for anything a teammate needs to reproduce, or a test fixture that can't be flaky. By default it's without replacement, so asking for more rows than exist raises rather than silently capping — replace=True allows repeats, which is the standard move for bootstrap resampling. For making sure every category shows up rather than trusting a single global draw to cover all of them by luck, I'd group first — groupby('category', group_keys=False).sample(n=1, random_state=...) draws independently within each group, which is stratified sampling, not a global draw that could skip a whole category." The signal: naming random_state= unprompted, the n=/frac= mutual exclusivity, and specifically the groupby().sample() stratified pattern — that last one is the part most candidates don't think to mention.
