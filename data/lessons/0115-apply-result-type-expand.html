apply(result_type="expand"): turning one row-function's tuple into real columns

Lesson 114's own closing note named two standing candidates — np.piecewise() and apply(result_type="expand") — without pre-committing either. A fresh scan of every lesson and the full glossary confirms both are still genuine zero-hits; result_type="expand" wins today because it closes a pandas-native gap in apply() (Lesson 61) rather than adding another standalone NumPy function.

1 · A row function that returns more than one value stays stuck in one column

A function passed to df.apply(fn, axis=1) can return anything — including a tuple or dict bundling several computed values per row. The problem: by default, that whole tuple or dict lands as a single object sitting inside one cell of a Series, not spread across real columns:

orders = pd.DataFrame({
    "customer": ["An", "Binh", "Chi"],
    "price":    [100.0, 50.0, 200.0],
    "qty":      [2, 3, 1],
})

def stats(row):
    return (row["price"] * row["qty"], row["price"] / row["qty"])

orders.apply(stats, axis=1)
# 0         (200.0, 50.0)
# 1    (150.0, 16.666667)
# 2        (200.0, 200.0)
# dtype: object  -- ONE column of tuples, not two columns of numbers

Confirmed directly (pandas 3.1.0): the result is a plain Series of Python tuple objects, dtype: object. It ran without error and looks superficially fine in a quick print — the trap is assuming it already split into columns when it hasn't.

2 · result_type="expand" spreads a list-like return across columns

result_type="expand" tells apply() to spread a list-like return value across the columns of the result DataFrame instead of leaving it bundled as one object:

orders.apply(stats, axis=1, result_type="expand")
#        0           1
# 0  200.0   50.000000   -- unnamed integer columns: 0, 1
# 1  150.0   16.666667
# 2  200.0  200.000000

Confirmed directly: a tuple or list return gets unnamed integer columns (0, 1, …) — but a dict return carries its own column names straight through, which is the far more readable choice in practice:

def stats_dict(row):
    return {"total": row["price"] * row["qty"], "unit": row["price"] / row["qty"]}

orders.apply(stats_dict, axis=1, result_type="expand")
#    total        unit
# 0  200.0   50.000000   -- real column names: "total", "unit"
# 1  150.0   16.666667
# 2  200.0  200.000000

Confirmed directly: assigning the expanded result straight back onto the original frame with df[["total", "unit"]] = df.apply(stats, axis=1, result_type="expand") works cleanly — this is the idiomatic way to add several computed columns from one row-function in a single pass, instead of calling apply() twice for two separate single-value functions.

3 · The footgun this closes: forgetting result_type raises, it doesn't silently misfire

Good news confirmed directly: trying to assign an un-expanded, tuple-returning apply() result onto two new columns does not corrupt data quietly — it raises ValueError: Columns must be same length as key immediately. The real trap is subtler: a quick, un-assigned df.apply(stats, axis=1) in a notebook cell prints what looks like it worked (a Series of tuples renders fine), so it's easy to walk away believing the row function already returns separate columns when it doesn't — until the very next line that tries to use one of those "columns" by name fails.

The trap: confirmed directly via the pandas docstring itself — result_type only has any effect at all when axis=1 (row-wise). Pass it with the default axis=0 (column-wise) and it is silently accepted but does nothing differently. It is also a no-op, falling back to a plain Series with no error, if the function's first computed return value isn't list-like in the first place (e.g., a bare scalar) — confirmed directly, result_type="expand" on a scalar-returning function just returns the same plain Series result_type=None would have.

4 · Uneven-length returns across rows raise loudly, not silently

Confirmed directly: if the row function returns tuples of different lengths depending on the row (a length-2 tuple for one row, length-3 for another), result_type="expand" raises ValueError: All arrays must be of the same length — every row's list-like return must expand to the same number of columns. There is no silent padding with NaN.

Scope line

This lesson covers result_type="expand" on axis=1 row-wise apply(): spreading tuple/list/dict returns into real columns, the dict-gives-named-columns behavior, the confirmed no-op cases (axis=0, non-list-like return), and the confirmed ValueError on uneven-length returns. It does not cover result_type="reduce" or result_type="broadcast" in depth (the opposite-direction and shape-preserving siblings, out of today's scope), nor raw=True or the engine="numba" performance options.
