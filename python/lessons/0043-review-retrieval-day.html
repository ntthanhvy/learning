1 · Six questions, in the original teaching order

Answer each out loud or on paper before reading the fold-out answer. If one is shaky, that is exactly the point of a review day — note it, then go fix it in the practice file below rather than only rereading the old lesson.

Day 1 — names, objects & mutability. a = [1, 2]; b = a; b.append(3) — what is a now, and why?

Fold-out answer: a is [1, 2, 3]. b = a does not copy the list — it binds a second name to the exact same list object. b.append(3) mutates that one shared object in place, and a sees the change because a and b were never two different lists to begin with.

Day 2 — comprehensions. Rewrite out = []; for x in nums: out.append(x * 2) as one comprehension.

Fold-out answer: out = [x * 2 for x in nums] — expression first, then the exact same for x in nums loop header, no if clause needed here.

Day 3 — dict/set grouping. Given a list of (category, amount) pairs, what's the one-line stdlib call that groups totals by category without writing if key not in d: d[key] = 0 by hand?

Fold-out answer: a collections.defaultdict(float) (or int), then for cat, amt in pairs: totals[cat] += amt — the defaultdict supplies the starting 0/0.0 automatically on first touch, so there's no manual existence check.

Day 5 — generators. What is the one keyword that turns an ordinary function into a generator function, and what does calling that function return (not what does iterating it produce)?

Fold-out answer: yield. Calling a generator function does not run its body at all — it immediately returns a generator object, an iterator that only starts executing the body on the first next(), then pauses at each yield and resumes right after it on the following next().

Day 7 — dataclasses. What does @dataclass generate for a class that hand-written classes don't get for free?

Fold-out answer: __init__ (from the annotated fields, in order), __repr__ (a readable ClassName(field=value, …) string), and __eq__ (field-by-field equality) — all three inferred purely from the type-annotated class body, no method bodies written by hand.

Day 12 — decorators. What two things does a decorator need to do to avoid silently breaking the function it wraps?

Fold-out answer: accept *args, **kwargs in its inner wrapper so it works with any wrapped function's signature, and apply @functools.wraps(func) to that inner wrapper so the wrapped function keeps its original __name__/__doc__ instead of reporting the wrapper's.

2 · Why spread the review out instead of grouping by topic

The six questions above are deliberately out of a single theme: object model, then syntax, then a data structure, then a control-flow idea, then a class feature, then a function feature — the opposite of a single-topic drill. Mixed, spaced retrieval (sometimes called "interleaving") is harder in the moment than re-reading one lesson start to finish, and that difficulty is the mechanism: producing an answer for Day 1's mutability rule right after producing one for Day 12's decorator rule forces the brain to actually retrieve each one from scratch, rather than riding the momentum of one topic already open in working memory.
