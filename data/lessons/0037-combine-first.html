combine_first(): filling gaps in one Series from another

Lesson 34's original scan named three candidates; Lesson 35 picked clip(), Lesson 36 picked between(), and both times deferred combine_first() as the weaker interview-frequency pick. It is the last remaining candidate — genuinely uncovered, so today it ships.

1 · The problem: two sources, prefer one, fall back to the other

A recurring wrangling shape: two Series describing the same rows, each with its own gaps — a "verified amount" column and an "estimated amount" column, say — and the rule is "use the verified value where it exists, otherwise fall back to the estimate." fillna() (Lesson 3) only fills from a single scalar or a single Series lined up positionally; it has no notion of "prefer my own non-null values, fall back to this OTHER Series' values only where mine are missing." combine_first() is the named tool for exactly this.

2 · combine_first(other): caller wins, other only fills gaps

Two same-length Series, aligned by the same index (0-3, same as the cleaned 4-row slice from Lessons 6-36):

primary   = pd.Series([120.0, np.nan, 35.5, np.nan])
fallback  = pd.Series([999.0, 42.0, 999.0, 180.0])

primary.combine_first(fallback)
# 0    120.0   # primary had 120.0 -- kept, fallback's 999.0 ignored
# 1     42.0   # primary was NaN -- fallback's 42.0 used
# 2     35.5   # primary had 35.5 -- kept, fallback's 999.0 ignored
# 3    180.0  # primary was NaN -- fallback's 180.0 used

Notice row 0 and row 2: even though fallback has a value there too, primary's own non-null value always wins. combine_first() never overwrites a value the caller already has — it only ever fills gaps.

3 · Aligned by index, not by position

Like every pandas alignment operation (Lesson 5's merge, Lesson 21's concat()), combine_first() matches rows by INDEX LABEL, not row position. If other is missing a label that primary has, that gap simply stays NaN — there is nothing to fall back to, and no error is raised.
fallback2 = pd.Series([999.0, 42.0], index=[0, 1])  # no labels 2, 3
primary.combine_first(fallback2)
# 0    120.0
# 1     42.0
# 2     35.5
# 3      NaN   # primary was NaN, fallback2 has no label 3 either -- still NaN

4 · DataFrames: cell by cell, aligned by index AND columns

The same rule extends to whole DataFrames — each cell is filled from other only where the caller's own cell at that (row, column) is null:

df1 = pd.DataFrame({"amount": [120.0, np.nan], "region": [np.nan, "South"]})
df2 = pd.DataFrame({"amount": [999.0, 35.5], "region": ["North", "South"]})

df1.combine_first(df2)
#   amount region
# 0  120.0  North   # amount kept from df1, region filled from df2
# 1   35.5  South  # amount filled from df2, region kept from df1 (already "South")

Row 0's amount keeps df1's 120.0 but its region (NaN in df1) is filled from df2's "North" — the fill decision is made independently per cell, not per row or per whole object.

5 · Related tools: combine(), fillna(), update()

combine_first(other) is shorthand for the more general combine(other, func), where func decides per pair of aligned values which one survives — combine_first is just combine(other, lambda a, b: a if pd.notna(a) else b) pre-written. Two easy mix-ups to keep straight for an interview:

  • fillna(value) (Lesson 3) fills from one scalar or a single aligned Series/dict — no "prefer mine" logic needed because there's no competing second object with its own gaps.
  • update(other) looks similar but has the OPPOSITE precedence and mutates in place: wherever other has a non-null value, it overwrites the caller's value — even if the caller already had one. It also returns None, not a new Series.
p2 = primary.copy()
p2.update(fallback)  # mutates p2 in place, returns None
# 0    999.0   # fallback's 999.0 OVERWRITES primary's 120.0 -- opposite of combine_first
# 1     42.0
# 2    999.0   # overwrites 35.5 too
# 3    180.0

SQL bridge: there's no single built-in equivalent, but the shape matches COALESCE(primary.amount, fallback.amount) after a LEFT JOIN on the same key — "take the first non-null value in this list," left to right.

Q: "How would you merge two overlapping data sources where each has its own gaps, preferring one over the other?" A strong answer, out loud: "series_a.combine_first(series_b) — it keeps series_a's own value wherever it's non-null, and only pulls from series_b where series_a is missing, aligned by index the same way merge or concat align. It never overwrites a value series_a already has, which is the opposite of update(), which mutates in place and lets the OTHER object's non-null values win. If the two sources don't share every index label, a gap with no match in either stays NaN, it doesn't raise. It's really COALESCE(a, b) from SQL, and combine(other, func) is the general form underneath it if I need custom tie-breaking logic instead of just 'prefer non-null'." The signal: naming the precedence rule explicitly (caller wins) and contrasting it with update()'s opposite behavior unprompted.
